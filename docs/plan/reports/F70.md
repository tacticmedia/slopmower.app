- **Decisions and deviations:**
  - Agent prompts step: "without a token" is "T1 lists no active token". While `code_browser` runs, a fetcher loads the loader-only root route `tour-tokens`, which reads T1. A failed T1 shows no link. The link reads "Create an API token in Settings first."
  - The `file` part runs only on the `files/*` route of an open review: a closed review and the blame view have no gutter "+" and no Symbols.
  - File step 1 targets the first line number below the stuck file header, not a row that the header covers, so a file opened at `#L40` points at a visible line.
  - File step 3 targets the "Go to declaration" input in a PHP file, and the code of the step 1 line in other files, as the scope's "the code view, or the PHP input" says.
  - A navigation to another path also completes the `file` part, with the same code as `code_browser`. A part that has not started yet, for example while the code view waits for its rows, is not completed by a navigation.
  - Escape is a `keydown` listener on the document while a part runs: Joyride's own Escape moves to the next step. A click on the dimmed page does nothing. Close and Done end the part through a context, not through Joyride's actions.
  - A step whose target does not exist when the part starts is left out, so "n of m" stays right: a collapsed tree, a narrow screen without the Requests item, a file without Symbols.
  - Quick open, Agent prompts, and Symbols have no unique attribute, so they get `data-tour`. The tree, the table, the Requests link, and the input use their existing `data-testid`, `aria-label`, and `href`.
  - Joyride renders into `[data-portal-root]`, the `BaseStyles` of the app inside the Primer theme root, not into its own element in `body`, where no Primer token applies. The overlay colour is `var(--overlay-backdrop-bgColor)`, the backdrop of Primer dialogs: a grey veil in light mode, a light veil over the dark page in dark mode, with the spotlight in the page colour. The arrow is hidden, because Joyride draws it outside the tooltip.
  - The code view replaces its rows when the highlighting arrives and when a comment box opens. Joyride anchors the tooltip to the element of its last render, so the tooltip jumped to the top left. A `MutationObserver` on the shadow root renders the tour again once per frame.
  - The submit passes `defaultShouldRevalidate: false`, and the root `shouldRevalidate` reloads `me` after `/preferences`, so the review page does not reload its other data.
  - `ReviewTour` keeps the parts that ended in this visit, so a failed A4 write does not start the part again until the next visit.
  - `PreferencesInput::$completedTours` is a `list<Tour>`: the Serializer refuses an unknown name with "The data must be one of the following values: code_browser, file", and `Assert\Unique` refuses a name twice. Both give 422 `invalid_input`.
  - The response class `Preferences` has no factory: A1 and A4 call `new Preferences($user->getCompletedTours())`.
  - `npm view react-joyride version` is 3.2.0, the latest release, so no newer version exists.
- **Follow-ups and new ideas:**
  - Joyride updates the spotlight 100 ms after a resize. qa-capture resizes and captures at once, so the journey captures at the other viewports show the spotlight at its earlier place. The tooltip is placed right.
  - The dimmed overlay blocks clicks outside the spotlight, so a comment box that the "+" opens during file step 1 takes keyboard input only until the part ends.
