## Report: F06 Back-end bugs

- **Status:** Done (awaiting merge). One commit `fix: F06 back-end bugs` on the worktree branch.
- **Summary:**
  - D2 and V12 answer 404 `not_found` when a V13 or R6 delete commits between the read of the review and the insert. The controllers map the foreign key violation of the insert. V12 also answers 404, not 422 on `path`, when R6 removed the repository row before the clone check.
  - Of two concurrent first sign-ins, GitHub or local, the unique index lets one insert. The other resets the closed entity manager, reads the winner's user, and signs in.
  - `FetchRepository::removeAccess()` dispatches the clone deletion, the recomputes, and the live update on every call, so a repeated removal reaches a clone that a failed dispatch left. The sign-in sync queues `DeleteCloneJob` alone for an unlisted repository that an earlier removal left with a clone.
  - `Application\GitHubRepositoriesLock::run()` is the tenant lock of the sign-in sync, both GitHub handlers, and the GitHub connect. It runs the work only for an active tenant and returns null otherwise. The `repository` job and the installation jobs of a tenant that is being deleted change and publish nothing.
  - The webhook parser refuses a body that is not a JSON object with 406. `review_event.request_ids` has a GIN index. `/login` shows the error of a failed GitHub callback, which it did not before.

- **Decisions and deviations:**
  - Item 1: the race test keeps the review in the identity map of the first request and commits the V13 delete before the request, so the insert runs after the delete as in the race. A second connection that holds the delete open would block the single test process at the foreign key check. The controllers catch `ForeignKeyConstraintViolationException` around the insert only, not in `ApiExceptionListener`, so another foreign key violation stays a logged 500.
  - Item 2: the unique index decides, not a `symfony/lock`, because the loser must read the winner's row and a lock test cannot run the race in one process. The test commits the winner's rows on a second connection from a `preFlush` listener, between the loser's lookup and its insert. A failed flush closes the entity manager, so the loser calls `ManagerRegistry::resetManager()`. The loser records its sign-in on the winner's row.
  - Item 3: every `removeAccess()` call dispatches all three follow-ups, not only `DeleteCloneJob`, because the recompute and the live update have the same failure mode. `RepositoryRepository::removeAccess()` returns nothing and sets the state unconditionally. The sign-in sync calls `FetchRepository::deleteLeftClone()` for an unlisted removed repository: it queues `DeleteCloneJob` only while the clone directory exists, with no recompute and no publish, so a sign-in does not repeat them.
  - Item 4: the shared shape is 5 lines smaller in total (68 added with the new class, 73 removed) and puts the purge check on all four places. The sign-in sync and the GitHub connect now also do nothing for a tenant that is being deleted; the connect answers 404 then. Null from `run()` means a skipped run, so the work of the installation handlers returns `true`, and the handlers return before `removeAccess()` and the publish. The connect work runs in the transaction of `run()`, so a refusal inside it closes the entity manager for the rest of that request, which ends with the error response.
  - Item 5: `docs/specs/webhooks-and-live-updates.md` section 1 says "Unparsable JSON gets 406". F09 owns the `docs/specs` text now, so this branch leaves it. Proposed wording for the Parsing row: "Unparsable JSON, and JSON that is not an object, get 406."
  - Item 6: DBAL cannot declare an index method, so the mapping declares a plain index on `request_ids` and the migration creates it `USING GIN (request_ids jsonb_path_ops)`. Schema validation compares names and columns only, so it passes. `jsonb_path_ops` because the reads use only `@>`.
  - Item 7: the `/login` rule did not hold. HWIOAuthBundle 2.5.0's `AuthenticationFailureHandler` redirects without storing the exception, and its factory ignores the `failure_handler` option. `SignInErrorListener` stores the error of every failed sign-in of the `main` firewall, so `LocalSignInAuthenticator` no longer stores it itself.
- **Follow-ups and new ideas:**
  - `docs/specs/webhooks-and-live-updates.md` section 1, Parsing row: the wording of item 5.
  - A failed GitHub callback shows "An authentication exception occurred.", because HWIOAuthBundle throws plain `AuthenticationException`s. A friendlier message for a state mismatch or a denied authorization needs a mapping by exception message.
