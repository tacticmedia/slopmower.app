- **Summary:** The review page shows a Primer `TreeView` of the pinned commit beside a file pane. The root listing comes from V6 in a layout loader, and each directory lists its entries through its own `useFetcher` on V6 when it expands. `/reviews/:reviewId/files/*` reads V7 for the metadata and, for a renderable file, V8 for the text. `assets/code/CodeFile.tsx` is the only module that imports `@pierre/diffs`: `CodeView` with `cleanLastNewline`, the Shiki GitHub light and dark themes, a worker pool of 2, and memoized props. React Router loads it as a lazy chunk, so the library is not in the shell bundle. Deep links `#L10` and `#L10-L20` select through `selectedLines` and scroll through `scrollTo`. A selection made in the view writes the hash back. Binary files, files above 1 MiB, and symlinks show a placeholder.

- **Deviations and decisions:**
  - Route tree: a pathless `CodeLayout` route under `review` holds the tree and the `<Outlet />`, with its own error boundary, so a V6 failure keeps the review header. Its children are the index route ("Select a file in the tree.") and `files/*`, which has its own error boundary, so a V7 or V8 failure keeps the tree. The fetchers target a loader-only child route `tree` (`/reviews/:reviewId/tree?dir=`). Every listing reads all pages through `apiGetAllPages()` with `limit=1000`.
  - Deep-link write-back: line numbers select lines (`enableLineSelection`). The selection after the pointer is released (`onLineSelected`) writes `#L10` or `#L10-L20` with `navigate(..., {replace: true, defaultShouldRevalidate: false})`: clearing the hash is not a hash-only change for React Router, which would otherwise run every loader again. The selection lives in the file route (`useState`); `onSelectedLinesChange` feeds every change, also during a drag, back into the controlled `selectedLines`. A selection that the view did not report (the first load, a hash edit, back and forward) also scrolls, through `scrollTo({type: 'range', align: 'center'})`. A hash whose end line is above `lineCount` is ignored.
  - `CodeFile` props: `path`, `blobSha` (with the path, the `cacheKey` of the worker pool: the language follows the name, so equal bytes at another path need their own highlighting), `contents`, `selection`, `onSelectionChange`, `onSelectionCommit`, `className`. Both components are `memo`, and the items, the selection, and the options are memoized. The `WorkerPoolContextProvider` sits inside `CodeFile` and the view below it is keyed by path, so the pool stays up while files change. The theme is set on the pool, which owns it, and on the view options, for the main-thread fallback. `disableFileHeader`, because the Primer `FileHeader` replaces it.
  - Worker pool with Vite 8.3.1: works, no fallback needed. The factory is the library's tested Vite pattern, `import url from '@pierre/diffs/worker/worker.js?worker&url'` with `new Worker(url, {type: 'module'})`. `vite.config.ts` sets `worker.format: 'es'`, as the library documentation advises for Vite: with the default `iife` the worker was 837 kB with the Shiki WASM engine inlined, with `es` it is 214 kB and the WASM engine is a lazy chunk.
  - The PHP grammar loads lazily without configuration: the pool gets no `langs`, and the library resolves Shiki's `bundledLanguages` loader, a dynamic import, from the file name.
  - Lazy import: `FileRoute` imports `CodeFile` through `React.lazy` with a `Spinner` fallback.
  - `apiGetText()` in `client.ts` reads V8 and maps failures to `ApiError` like the JSON calls.
  - `actionError()` returns `{error: string}`; it never returned null. The tree loader reuses it: an API error other than 401 becomes `{error}`, which the directory shows in a Primer `TreeView.ErrorDialog` with retry; dismiss collapses the directory.
  - Tree entries: submodules are not links, because V7 answers 422 for them. Symlinks open, and the placeholder names the target. Items carry `data-path` for the tests and the DOM ID `file-tree:<path>`.
  - Placeholder texts: "Binary file not shown.", "File not shown: <size> MiB is above the 1 MiB limit.", "Symbolic link to <target>".
  - Layout: the code view is 70vh high (minimum 20rem), because `CodeView` virtualizes inside its own scroll container. The tree column is 12 to 18rem wide and scrolls at 80vh; below 768px it stacks above the file.
  - Fixtures: `FixtureRepositories::codeView()` is a file map for `GitRepositoryBuilder::commit()`, which `BrowserFixtures::localSource()` now takes. Line N of the lines 4 to 3499 of the large file declares `LINE_N`.
  - `CodeViewTest` "on demand" checks the V6 requests through Resource Timing (`performance.getEntriesByType('resource')`): Primer's `SubTree` renders nothing while it is collapsed, so the absence of a child in the DOM proves nothing about the request. `LargeFileTest` also requires `data-selected-line` on line 3000, which proves the deep link through `selectedLines`. `ShadowDom::waitUntil()` queries the row again on each attempt and reads it only inside its check, because the library replaces rows when the worker highlighting arrives; a stale element counts as not ready.
  - Skills: `make-test` (Panther for the browser behaviour, Vitest for pure TypeScript) and `cli-conventions` (`make` targets, `docker compose exec php` for a filtered run) applied. `services`, `configuration`, `components`, and `discover`: no PHP service or configuration changed.
