## Report: F59 Request detail like a GitHub issue

- **Status:** Done (awaiting merge). One commit `feat: F59 request detail like a github issue` on top of `main` 1968423.
- **Summary:**
  - The Request Detail has the layout of a GitHub issue: a header with the back link, the title of F58, and one state line (status, author, age, comment count); a sticky action bar; one next-step sentence; the closed-review banner; then a grid with the tabs and the main column, and a 256 px sidebar from 1012 px. Below 1012 px the sidebar comes before the tabs.
  - The action bar is a direct child of the article and sticks to the window top for the whole page. It holds `RequestActions` without the plan toggle and `SuggestionActions`. While it sticks, it shows the status (`stuck-status`) and the summary on one line. Without a button, for example in a closed review, it is not rendered.
  - `requestStage()` gives the next-step sentence by the 12 rules of the scope table. It replaces `TurnLabel` and "Plan required" on this page. `planState()` gives the Plan value, which never says "required" after the work.
  - The sidebar has Assignee, Plan with the plan toggle, Location, Development, and Suggested by. `useStuck()` moved to `assets/layout/useStuck.ts`.

- **Decisions and deviations:**
  - The h1 is `RequestTitle.tsx` of F58, not the `summary` of the Facts. The header keeps the back link above the title, as before.
  - The header has no `SuggestionLabel`. The scope lists only the state line in the header; the next-step rule 1 and "Suggested by" show the suggestion. The Suggestion spec now checks the next-step line after Accept and Dismiss instead of the absent label.
  - `OutdatedLabel`, `AnchorLink`, the FQN, and `LocationInfo` moved into Location; the pull requests into Development. Selectors follow: `OutdatedLabel` reads the sidebar, `PullRequestLink` says "sidebar" in its titles.
  - The tabs are inside the grid, after the sidebar in the DOM, so the narrow order needs no `order`. `ClosedRequestReadOnly` therefore reads `${DETAIL} button:not(nav button)` instead of `${DETAIL} > :not(nav) button`: still no button outside the tab nav.
  - The acceptance test of the plan toggle is in `RequestDetailLayout.spec.ts`, as the scope lists it, and `PlanRequirement.spec.ts`, which tested the same Q18 flow in the bar, is deleted to avoid a duplicate.
  - `Reopen.spec.ts` checks `data-awaiting` of the next-step line where it checked the text of `TurnLabel`.
  - Rule 5 skips `pull_request.linked`, `pull_request.unlinked`, and `request.retitled` when it finds the last agent entry, as `awaiting` rule 3 of architecture section 6 does, so a link after a question keeps the question sentence.
  - The article has no `max-width` of 1012 px any more, so the main column and the 256 px sidebar use the width of the root layout (at most 1280 px).
  - The sentinel of `useStuck()` cancels the flex gap of the article through `--page-gap`, so the status shows when the bar starts to stick. The bar extends over the 16 px side padding of the root layout.
  - While the bar exists, `html` has `scroll-padding-top` of 64 px, so the scroll to a commit section of the Changes tab stops below the bar.
  - `REQUEST_BUTTON_LABELS` replaces `buttonLabel()`, which only looked up the record once the plan toggle left the bar.
  - The journey captures use the default viewports of qa-capture (390, 768, 1024, 1728, and 1920 px). 1280 px is not one of them; the wide captures show the same layout from 1012 px.
- **Follow-ups and new ideas:**
  - The stuck state never shows in a journey, because qa-capture takes full-page screenshots at the document height.
  - Location shows the path and lines twice for a located request: `AnchorLink` and the location of `LocationInfo`. One of them could go.
