- **Summary:**
  - The Symbols menu, exact-range symbol anchors, re-anchoring by FQN, quick open, and the sticky scope lines work for `.java`, `.cs`, `.rb`, `.sh`, `.bash`, `.scala`, `.zig`, and `.lua` files.

  - The engine gets one general rule: the doc comment search passes from a declaration to the previous sibling of a parent that starts with it. A Ruby body starts at its first statement, and the comments before it are children of the class or module.

- **Decisions and deviations:**
  - Engine: `previousNamed()` in `extract.ts` lets the doc comment search pass to the previous sibling of a parent that starts where the declaration starts. tree-sitter-ruby puts the comments before the first statement of a body into the `class` or `module` node, before `body_statement`. Every other parent of the existing languages starts with a token such as `{`, so their tables do not change.
  - V7: `FileLanguage` gives `scala`, `zig`, and `lua` instead of null, which changes the V7 representation of those files. README section 6 requires a new version for that, so the V7 ETag is `v2`, and the README row now names a new `language` value as a reason. The scope named only the V9 ETag.
  - No `symbols/.npmrc`: no install failed, see the spike.
  - The kind tables follow the scope. Record components (Java), positional record parameters (C#), and case class parameters (Scala) are no properties, as TypeScript parameter properties.
  - Java: an annotation type element is a method `A.e()`, and an interface or annotation constant is a property. A compact constructor is a constructor. An enum constant body and an anonymous class are opaque, as is `block`, so local classes are skipped.
  - C#: a record struct is a struct through a pattern on its `struct` token before the record pattern. A `const` field is a property. Finalizers, operators, conversion operators, and indexers are no symbols: they have no name, or the class name, which would repeat the constructor FQN. A local function is no symbol. The fixture is two files, because C# refuses a file-scoped and a block namespace in one file.
  - Ruby: a `def` that is a direct child of `program` is a function, every other `def` and `def self.m` a method of the enclosing container. A method in `class << self` belongs to the class. `class A::B` captures the scope `A` as `@parent`. `argument_list` and `call` are wrappers, so `private def m` starts at `private`. `block`, `do_block`, and `lambda` are opaque, so `included do ... end` and RSpec blocks give no symbols. `#!` is no doc comment.
  - Bash: a function in a top-level `if` is a function. `#!` is no doc comment.
  - Scala: a `case` line with one case is captured whole, as a Go declaration with one spec, so its doc comment precedes it. An abstract `def` is a method. `val a, b` gives two properties, and a pattern such as `val (a, b)` none. A `def` of an `extension` has no container and is skipped. `function_definition`, `val_definition`, `var_definition`, `given_definition`, `block`, `lambda_expression`, and `instance_expression` are opaque.
  - Zig: `opaque {}` is a struct as `struct` and `union`, because its functions are methods. A `const` inside a container is a constant `S.C`. `const std = @import("std")` is a constant, as `const fs = require('fs')` in JavaScript. A `var` is no symbol. Tests and `comptime` blocks are opaque through `block`.
  - Lua: the doc comment pattern `---` excludes a `----` separator line.
  - The overload rule of the engine applies to every language: a function or method without a body right before one with the same FQN joins its range. So consecutive Java, C#, or Scala overloads without a body, or an abstract overload before a concrete one, are one symbol. Architecture "Symbol languages" says so.
  - `SymbolsApiTest`: the F29 case is extended to the ten languages of the service instead of a second case with the same rule.
  - `docs/developer-guide.md` and `.env` link to the language table of the architecture instead of listing the languages.
  - No change to `BlobSymbols`, `IndexSql`, the schemas, or the front end was needed.
- **Follow-ups and new ideas:**
  - Zig: tree-sitter-zig 1.1.2 gives `parseError` for every file with an empty container, `struct {}`, `enum {}`, `union {}`, or `opaque {}`, which is common in Zig. A fix needs an upstream grammar release, or a grammar built from a fork.
  - Scala 3 indentation syntax: an indented body runs to the next line with less indentation, so the range of the last definition includes the blank lines and comments before that line, and the doc comment of the next definition belongs to the indented body.
  - Scala: a companion object has the FQN of its class, so neither is unique and neither becomes a symbol anchor. The menu groups the members of both under one heading.
  - Lua: an LDoc block of a `---` summary and `--` lines is no doc comment, because the walk starts at the `--` line. EmmyLua blocks of `---` lines work.
  - Ruby: `attr_reader` and `attr_accessor` give no properties, and `define_method` gives no method.
  - Scala extension methods and C# operators and indexers are no symbols.
  - The V7 ETag needs a new version for each new `FileLanguage` entry. A version that includes a hash of the language map would remove that step.
