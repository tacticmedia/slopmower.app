## Report: M10 Sign-in and security

- **Status:** Done (awaiting commit).
- **Summary:** The firewalls `dev`, `api` (`^/api/v1`, lazy, context `web`), and `main` (lazy, context `web`) use `TenantUserProvider`, which loads a user by ID inside `TenantFilter::suspend()` and sets `TenantContext`. `TenantContextListener` runs directly after the firewall and sets the tenant from the authenticated user. `access_control` requires `IS_AUTHENTICATED` on `^/api/v1`: the `api` entry point answers 401 with the Error body and `WWW-Authenticate: Bearer realm="holistic-review"`, and the `main` entry point redirects to `/login`. `LocalSignInAuthenticator` (D25) is in the base `main` firewall and supports only `POST /login/local` in `dev` with a non-empty `APP_LOCAL_SIGN_IN`. `LocalUserProvisioner` creates the tenant and the local user at the first sign-in, for the local and the `e2e` sign-in. Sessions are in the `sessions` table through `PdoSessionHandler`, with its own lazy connection and a PostgreSQL advisory lock. A1 `GET /api/v1/me` returns the session caller.

- **Deviations and decisions:**
  - `App\Entity\User` is the security user. Its identifier is the user ID. The session stores the serialized entity: ID, tenant ID, login, and profile, never review data.
  - `User::recordSignIn()` updates `lastSignInAt` at each local and `e2e` sign-in. M05 left the column without a writer.
  - `PdoSessionHandler` has its own connection from a `pgsql:` DSN that `config/services.yaml` builds from the `url:` parts of `DATABASE_URL`. The handler opens it at session start and closes it at session save, so a worker never keeps a dead connection. Its pgsql branch ignores the URL query (`serverVersion`, `charset`), but a URL cannot carry the test database name. The parameter `app.session_database_suffix` mirrors the `dbname_suffix` of `doctrine.yaml`: `_test%env(default::TEST_TOKEN)%` under `when@test`, `_test` under `when@e2e`. `doctrine:schema:validate --env=test` guards it: with the suffix empty, the schema listener does not see `app_test` and the validation fails.
  - `lock_mode` is `LOCK_ADVISORY`: a session-level `pg_advisory_lock` per session ID, from session read to session save, released with the connection. It serializes the requests of one session, so a request that read the session before logout cannot write it back after logout deleted it. It holds no transaction open for the request.
  - The `api` entry point removes the target path that the firewall exception listener stores before it calls the entry point. Without that, every anonymous `/api/v1` call writes a `sessions` row and sends a cookie.
  - The logout path is the POST-only route `app_logout`. The security route loader adds no route for a route name, so `GET /logout` answers 405. `enable_csrf` uses the stateless token ID `logout`.
  - `check_header: true` is a global option of `framework.csrf_protection` in Symfony 8.1. It applies to all four stateless token IDs: `submit`, `authenticate`, `logout`, `api`. It changes nothing for the forms, which send the token value `csrf-token`.
  - CSRF protocol of `SameOriginCsrfTokenManager` 8.1.0, for M11 and M17. A request passes when `Sec-Fetch-Site` is `same-origin` (when present, this header decides alone), or else when `Origin` or `Referer` starts with the request scheme and host, or with a double-submit: a token of at least 24 characters as the token value, plus the header `csrf-token: <token>` or the cookie `csrf-token_<token>=csrf-token` (`__Host-` prefix on HTTPS). With `check_header`, the header alone is enough. With `check_header`, a `csrf-token` header that differs from the token value fails. A session remembers the strategy and refuses a downgrade. M11's listener can check `new CsrfToken('api', $request->headers->get('csrf-token', 'csrf-token'))`. A same-origin `fetch` of a current browser sends `Sec-Fetch-Site: same-origin` without extra code.
  - `LocalSignInAuthenticator::localLogin()` is the one place that decides whether local sign-in is on. `supports()` and the `/login` page use it. The route condition `env('APP_LOCAL_SIGN_IN') !== ''` plus `env: 'dev'` repeats it for the router.
  - The warning about `APP_LOCAL_SIGN_IN` outside `dev` is logged when the authenticator is built: once per worker in worker mode, once per request on the `main` firewall in classic mode.
  - A successful local sign-in redirects to `/`, which has no route until M17. A failed one stores the error in the session and redirects to `/login`.
  - `E2eSignInController` signs in through `Security::login()` with `LocalSignInAuthenticator` named, so a second authenticator in M32 needs no change. It answers 200 `text/plain` "Signed in as <login>".
  - `MeController` builds the A1 array itself. The links use `Request::getUriForPath()`, because the routes `/_mcp` and `/docs` do not exist yet. `features.localRepositories` is true when `APP_LOCAL_REPOSITORIES_DIR` is not empty.
  - `MeEndpointTest` compares the exact expected structure. The schema assertion is M11 task 5, when `opis/json-schema` arrives.
  - `#[Autoconfigure(public: true)]` is removed from `TenantContext` and `TenantFilter`, the M05 follow-up. Both now have consumers, and the tests still find them.
  - Two tests beyond the acceptance list: the warning outside `dev`, and logout with CSRF. Both are rules of the milestone scope.

- **Risks discovered:**
  - Each request that uses the session opens one more database connection, for the length of the request.
  - When the database drops the Doctrine connection, the next request fails once with DBAL `ConnectionLost`. If that happens in `refreshUser()`, `ContextListener` removes the security token from the session, and the user must sign in again. Session reads themselves recover at once.
  - Two simultaneous first local sign-ins with one login hit the unique index `uniq_app_user_local_login`, and one request gets 500. Local development only.
