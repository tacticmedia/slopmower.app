# Report: M10 Sign-in and security

- **Status:** Done, on `main`, 2026-09-29.
- **Summary:** Firewalls `dev`, `api` (lazy, `context: web`), and `main`. `access_control` answers 401 for `^/api/v1` before any value resolver runs. `TenantUserProvider` and `TenantContextListener` set the tenant from the signed-in user. There are JSON and redirect entry points, the dev-only local sign-in (D25), the `e2e`-only sign-in, `POST /logout` with CSRF, database sessions, the stateless CSRF token ID `api`, and A1 `GET /api/v1/me`. A scoped review found two defects. Both are fixed, and eleven redundant tests are cut.
- **Verification:** `make check` exit 0: 971 unit and functional tests, 2 E2E tests, PHPStan 0 errors, schema in sync.
- **Versions:** `opis/json-schema` 2.6.0 (table), with `opis/string` 2.1.0 and `opis/uri` 1.1.0.
- **Decisions:**
  - `ApiEntryPoint` removes the target path that the stateful `api` firewall stores. Otherwise every anonymous API call wrote a session row and sent a session cookie with its 401.
  - `ReconnectingSessionHandler` wraps `PdoSessionHandler` (advisory lock mode). It builds the handler per request from the Doctrine connection and closes that connection on a `PDOException`. The container kept one PDO per FrankenPHP worker, so after a lost database connection every session request gave 500 until the worker restarted. The handler also feeds DoctrineBundle's schema listener, so the `sessions` table stays in the schema.
  - `JsonApiAssertions` and `SchemaValidator` in `tests/Support/Contract` validate responses against `docs/specs/schemas`.
- **Follow-ups:** M11 enforces CSRF on session writes. M14 adds `api_bearer`.
- **Risks:** none known.
