## Report: M24 Live updates via Mercure

- **Status:** Done, committed as 12290f1 on 2026-10-03.
- **Summary:** `symfony/mercure-bundle` 0.5.0 publishes private updates with IDs only to the hub that FrankenPHP has built in. `PublishCommittedEvents` sends one `events` update per committed transaction, with the ID `urn:holistic-review:{tenantId}:{seq}`. `FetchRepository` dispatches `RepositoryChanged` after each sync state change, and `PublishRepositoryChanges` sends `repository`. `LivePublisher` logs a failed publish and does not retry it. A3 `POST /api/v1/mercure/authorize` sets the subscriber cookie with the tenant's two selectors for one hour. `useLiveRevalidation` in `RootLayout` holds the one EventSource, tracks `lastSeq`, revalidates the loaders one at a time, and catches up through V10 after a reconnect and when the tab becomes visible. The UI does not poll.

- **Deviations:**
  - No `SubscriberAuthorization` class: A3 is its only consumer, so the cookie code lives in `MercureAuthorizeController` (Jan's rule: no service class with one consumer). It uses the bundle's `Authorization::createCookie()` and replaces `Secure` with `$request->isSecure()`, because the bundle derives `Secure` from the scheme of the public hub URL, and the specs derive it from the request.
  - `LivePublisher` is a class the plan does not name: both publishers, and the later `index`, `outdated`, `repository_deleted`, and `candidates_changed` publishers, share its private-update and failure rule.
  - The GitHub mock of the `test` environment moved from `framework.http_client.mock_response_factory` to the `mock_response_factory` of the `github.client` scoped client. The global mock also caught the Mercure publishes, which must reach the real hub on port 8081 for `HubIsolationTest` and for the traceable hub, which records only successful publishes. The two GitHub tests that count requests read the mock transport through the `test` alias `github.client.mock_transport`, because a test cannot get a service whose ID starts with a dot.
  - `RootLayout` renders `data-live="connected"` while the EventSource of the current topics is open. `LiveUpdateTest` waits for it, because the e2e hub uses the `local` transport without history, so an update before the subscription is lost.
- **Decisions:**
  - `RepositoryChanged` is dispatched in `FetchRepository`, where the M09 and M11 use cases change the row: in `queueClone()` (R3 connect and the clone restart of R5, also when the dispatch fails and sets `failed`), after `request()` queues a fetch (R5, `link_commits`), when a synchronous fetch starts from `idle`, and after every clone or fetch attempt, success or failure. After a success, `RepositoryFetched` runs first, so the `events` updates of `commit.found` precede `repository` (section 2.2 step 4).
  - The publish failure is logged at `error` level.
  - The JWT secret stays the single `MERCURE_JWT_SECRET`; the recipe's duplicate line in `.env` was removed and the compose comment moved into the recipe block.
  - The open review comes from the `review` route data (`Review.id`) or the `request` route data (`Request.reviewId`). The review topic is the selector from A3 with `{reviewId}` replaced.
  - The sign-in sync (M33) dispatches `RepositoryChanged` for each repository whose name it changes, after the transaction and the lock (orchestrator decision on the open question).
  - `EventPositions` (`assets/live/eventPositions.ts`) is one module-level instance, because route actions record the `events[].seq` of command results outside React. Request commands and file comments record it with `rememberEvents()`, which also raises the seq that the router's revalidation after the action covers. `Review.lastEventSeq` comes from the review loader data.
  - The hook waits with its revalidation until the router itself is idle: `router.state.navigation` and every fetcher in `router.state.fetchers`, read through `UNSAFE_DataRouterContext`, with waiters resolved from `router.subscribe()`. The rendered state lags, because RouterProvider updates it in a transition. React Router drops the redirect of a fetcher action when a navigation, also `revalidate()`, starts during the action (`pendingNavigationLoadId > originatingLoadId` in `router.js`). V1 publishes `repository` during its synchronous fetch, so without the wait "Start review" stayed on the repository page, and `ReviewLifecycleTest` and `VerticalSliceTest` failed. The hook calls `router.revalidate()` directly.
  - After the router is idle, the queued revalidation is skipped when every pending update is an `events` update at or below the seq that `rememberEvents()` recorded, so the update of an own write that arrives before the command result causes no second revalidation.
  - Without a known `lastSeq`, the catch-up only revalidates. A3 runs again 60 seconds before `expiresAt`, at least 10 seconds apart. A 401 of A3 stops the subscription. Other A3 failures, and a connection that the browser gave up (`readyState` closed), retry after 10 seconds, doubling up to 5 minutes; an open EventSource resets the wait.
  - Skills: `make-listener` shaped both publishers as `#[AsEventListener]` classes. `make-voter` did not apply: A3 checks the actor kind with the existing `#[IsGranted(User::ROLE)]`, and no decision depends on an object. `configuration`: the hub URLs and the secret stay environment variables, the token lifetime is a class constant. `make-controller`: an invokable controller with `#[Route]` and `#[IsGranted]`.

- **Risks discovered:**
  - The first FrankenPHP release with Mercure 1.x needs `protocol_version: '1.0'` on the hub, `iss`, `sub`, and `client_id` claims in `mercure.hubs.default.jwt.claims`, and new Caddyfile `issuer` blocks; the cookie name then defaults to `__Secure-mercure_access_token`, which plain-HTTP development cannot set. Set `cookie_name: mercureAuthorization` then.
  - The M11 worker risk happened again during the manual check: the worker crashed on a container file that the `php` container rebuilt, and kept the clone message. Setting `delivered_at` to null in the worktree's `dev` database released it.
  - Every functional test that commits events now publishes to the e2e hub on port 8081. The suite took about the same time as before.
