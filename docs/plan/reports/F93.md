## Report: F93 Warning before leaving an unsaved comment

- **Status:** Done 2026-11-03.
- **Summary:**
  - `UnsavedCommentGuard` wraps `ReviewLayout`. It holds the set of comment boxes with unsaved text, and it has the only `useBlocker` of the router. A navigation to another path opens the `ConfirmationDialog` "Discard your unsaved comment?" with "Discard" and "Keep editing". A change of the hash or the query passes.
  - While the set is not empty, a `beforeunload` listener makes the browser ask before a reload or a closed tab.
  - `CommentBox` registers itself with `useUnsavedComment`. A box with `initialTextSaved` (the draft edit of `DraftBox`) is unsaved while its text differs from the saved text. Any other box is unsaved while its title or body is not blank, so a box that opens again after a failed write still counts. A box that sends is not unsaved.
- **Files:** `assets/comments/UnsavedCommentGuard.tsx` (new), `assets/comments/CommentBox.tsx`, `assets/comments/DraftBox.tsx`, `assets/routes/reviews/ReviewLayout.tsx`, `tests/ui/UnsavedComment.spec.ts` (new), `docs/user/comment.md`.
- **Tests:** UI `UnsavedComment`:
  - "Typed text and a click on another file ask first: Keep editing keeps the file and the text, and Discard opens the other file"
  - "An empty comment box does not ask, and a line click with typed text does not ask"
  - "A pending comment with changed text in its edit box asks first"
  - "A comment that was added does not ask"
  - "Closing the tab with typed text raises the beforeunload prompt"
- **Verification:**
  - `make front`: 108 Vitest tests. `make ui`: 204 passed. `make e2e`: 14 tests, 326 assertions.
  - Mutation check: with the guard off, the 3 tests that expect a prompt fail and the 2 others pass.
  - `bin/patch-react-router.mjs` changes only the fetcher redirect; the specs above pass with it.
- **Deviations:** the scope named "a small context module". It is one component with its hook, `UnsavedCommentGuard.tsx`, in `assets/comments/`.
