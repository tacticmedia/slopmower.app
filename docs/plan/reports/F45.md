## Report: F45 Database error details

- **Status:** Done (awaiting merge). One commit `feat: F45 database error details` on the worktree branch `f45-database-error-details`, from `2b86438`.
- **Summary:**
  - `App\Doctrine\StripDatabaseErrorDetail` is a DBAL driver middleware that replaces the exception converter of the driver. Before the PostgreSQL converter runs, it replaces the driver exception with one that has only the first line of the message, the same SQLSTATE and code, and no previous exception.
  - So each DBAL exception keeps its class, and code that catches `UniqueConstraintViolationException` or `ForeignKeyConstraintViolationException` works as before. No message in the exception chain holds the `DETAIL`, `HINT`, or `CONTEXT` lines of PostgreSQL, which carry row values, and the `PDOException` with the same text is no longer in the chain.
  - It applies to every connection. The RDS auth driver stays the outermost driver.
- **Files:**
  - Created: `src/Doctrine/StripDatabaseErrorDetail.php`, `tests/Functional/Doctrine/DatabaseErrorDetailTest.php`, `docs/plan/reports/F45.md`.
  - Changed: `docs/developer-guide.md` (namespace row `App\Doctrine`, functional class count), `docs/plan/README.md` (gotcha "Database error messages").
- **Tests added:**
  - Functional `DatabaseErrorDetailTest`: "A constraint violation keeps its class, SQLSTATE, and first line, and no message holds the row", with the data sets `NOT NULL` (`NotNullConstraintViolationException`, 23502), `check` (`DriverException`, 23514), and `unique` (`UniqueConstraintViolationException`, 23505). The table is temporary, because no table of the schema has a check constraint: `body text NOT NULL UNIQUE CHECK (body <> '')` and `note text`. Without the middleware, all three cases fail on the row text, after the class and SQLSTATE assertions pass. So the classes and SQLSTATEs are those from before F45.
- **Verification:**

    - without the middleware, for comparison: the same first line, then `DETAIL:  Failing row contains (..., acme/widgets, ..., row text of an error, ...)` in each of the three exceptions of the chain.

- **Decisions and deviations:**
  - No `#[AsMiddleware]`, which the scope file names. DoctrineBundle 3.3.2 autoconfigures every `Doctrine\DBAL\Driver\Middleware` with the tag `doctrine.middleware` (`DoctrineExtension`). The attribute only adds a priority or a list of connections, and this middleware needs neither.
  - The order of the middlewares does not matter. Every middleware driver in `vendor/` extends `AbstractDriverMiddleware`, which passes `getExceptionConverter()` to the driver that it wraps, and no other class overrides it. The RDS driver reads the raw driver exception of `connect()` before the conversion, so its password-failure check still sees the whole message.
  - One file: the middleware returns an anonymous driver class that is also the converter, and the replacement exception is an anonymous subclass of `Driver\AbstractException`. Monolog logs its class as `Doctrine\DBAL\Driver\AbstractException@anonymous`.
  - Every driver error is replaced, also a one-line error, so no chain holds a `PDOException`.
  - The checks of `PostgreSQL\ExceptionConverter` that read the message, `truncate` for 0A000 and `terminating connection` or `server closed the connection` for `ConnectionLost`, match words of the first line.
  - Also lost for an operator, besides the row values: the `DETAIL` of a deadlock, with the process IDs, and the hint lines of libpq after a failed connection, for example "Is the server running on that host". The first line names the error.
  - The `App\Doctrine` row counted 8 files, but `src/Doctrine` had 9: the row did not list `LogOutdatedDatabasePassword` of F28. It counts 10 now and names both.
  - At the merge, the orchestrator changed the risk row of architecture section 12 to name F45, and added the PostgreSQL server log settings `log_error_verbosity = terse` and `log_min_error_statement = panic` to `docs/deployment.md` section "Database connection". The PostgreSQL 18 documentation says that `TERSE` excludes `DETAIL`, `HINT`, `QUERY`, and `CONTEXT`, and that `PANIC` turns off the logging of failing statements.
- **Follow-ups and new ideas:** none open. The risk row, the candidate, the server log settings, and the file count of the developer guide are done at the merge.
