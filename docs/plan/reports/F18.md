- **Decisions and deviations:**
  - Item 1: the library rendered no expand button for a patch, because `DiffHunksRenderer` passes `expandIndex` only when the diff is not partial or `loadDiffFiles` is set. The defect was the "N unmodified lines" row of `line-info`, which looks like the GitHub expansion row and offers nothing. `metadata` replaces it with the `@@` hunk header, which states what the patch holds. `simple` would show no separator before the first hunk and a 4 px bar between hunks. The test asserts no `[data-expand-button]` and no `[data-unmodified-lines]`.
  - Item 2: D51 is the decision row and the specs README entry. The schema has a `description` on `files`, no other change, so `BundledSchemas` is not affected (Q9 has no MCP tool).
  - Item 3: the plan README rule reads "The response class of an endpoint is in `Application\Query`, also for a read that stays in its controller and for a write". It names endpoint responses, because `Anchoring\CodeExcerpt`, a nested part of `request.schema.json`, stays in `Anchoring`. The reports of M14, S02, S08, and S10 keep the old namespace, because they record history.
  - Item 4: `finalizeRender()` of `VirtualizedFile` is the same in 1.5.1 and 1.5.2: `if (this.getRenderedFile() !== this.pendingRender?.file) throw ...`, a comparison by identity, while `updatePendingRender()` compares with `areFileTargetsEqual()`, by `cacheKey`. `VirtualizedFileDiff.finalizeRender()` uses `areDiffTargetsEqual()` in both versions. The rule in `CodeFile.tsx` stays. The 1.5.2 changes are elsewhere: collapsed-file header heights, handled worker pool errors, the Firefox scroll rebase, and editor line updates. `npm install` also dropped `"peer": true` from `@shikijs/themes` in `package-lock.json`. Architecture section 2 and `spike-results.md` keep 1.5.1, because they record the spike.
  - Item 5: `composer update --lock` removed the package from `composer.lock` and `vendor/`, and changed nothing else. At the rebase on F17, `composer.json` kept both sides, `composer.lock` came from `main`, and `composer update --lock` removed the package again.
  - Item 6: `buffer_size: 50`, the value of `when@prod`. `GitHubFetchSecretTest` reads the warning of `ServerClone` and the debug record of `GitRunner`, both on the `app` channel; with `channels: ["doctrine"]` it fails as expected. Its leak check now covers the `app` channel, which holds the only records with git argv and exception messages.
  - Item 7: the translation file, not the template, because one key in the `security` domain is enough: on `/login` only the GitHub sign-in throws a plain `AuthenticationException`: HWIOAuthBundle for the `state` check, a callback without a code (a denied authorization), and an error of the code exchange, its `HttpTransportException` for an unreachable GitHub, which has no key of its own, and `GitHubUserProvider` for "GitHub returned no user.". Local sign-in throws `InvalidCsrfTokenException` or `TenantBeingDeleted`, which have their own keys and stay. XLIFF, as the Symfony best practices say.
