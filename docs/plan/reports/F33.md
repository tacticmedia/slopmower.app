- **Decisions and deviations:**
  - Lines are the token lines of the Twig lexer, which counts `\r\n` and `\r` as one line break. `docStartLine` is the line of the `{%` minus the line breaks between the first `{##` of the run and the `{%`.
  - The run of comments before a tag is found with a regular expression on the text before the `{%`: comments and whitespace up to the tag. Its first comment that starts with `{##`, but is not the empty comment `{##}`, starts the range. The gate is `Token::getDocumentation()`, so an empty `{## #}` alone and text between the comment and the tag give no doc line, as in Twig.
  - A `block` or `macro` tag without a name, and an `endembed` without its `embed`, also give `parseError`: Twig refuses both, and the pairing of the end tags needs them. The scope names only the end tags of `block` and `macro`.
  - A tag that the end of the file cuts off, such as `{% endblock` without a line break, gives no lexer error. The extractor then reaches the end of the token stream inside the tag, which gives `parseError` as an unclosed `{%`.
  - A macro inside `embed` stays a symbol, because the scope skips only blocks there.
  - Two blocks with the same name, which Twig refuses, give two rows. The front end keeps a selection of either as a range, as for other duplicate FQNs.
  - `Token::getType()` is deprecated since Twig 3.19, so the extractor uses `Token::test()`.
  - The V9 rule "A failure of the symbol service answers 500 for a file that is not PHP" now says "neither PHP nor Twig".
- **Follow-ups and new ideas:**
  - The Symbols menu shows Twig blocks and macros under the group heading "Functions and constants" (`SymbolsMenu.tsx`), because a block heads no group. A neutral heading such as "Top level" would fit every language.
  - Symfony UX TwigComponent: blocks inside `{% component %} ... {% endcomponent %}` override the blocks of the component template, as inside `embed`, but they count as blocks of the outer template. The `<twig:Component>` syntax is plain text to the lexer, so its `<twig:block>` elements give no symbols.
  - A `{% line N %}` tag moves the lines of the lexer, so the symbols after it have the lines of the original source, not of the file.
  - An unbalanced `{#` inside `{% verbatim %}` right before a documented tag hides the doc line of that tag.
  - Reviews that were indexed before F33 have no Twig rows for quick open (V16) until `app:index:rebuild` runs for them, which parses the blobs without an `indexed_blob` row. V9 parses a Twig file on demand.
