## Report: F48 Agent suggestions

- **Status:** Done 2026-10-14.
- **Summary:**
  - An agent starts a review with V1 or `start_review`, or uses a named one, and opens one suggestion per finding with Q20 or `suggest_request`. A suggestion is a request in the event log: `request.opened` with an agent actor and the sub-state `suggestion` `pending`.
  - The user accepts a suggestion with Q21, with "Ask for a plan first" checked by default, or dismisses it with Q22 and an optional note. An accepted suggestion is an ordinary request for "Work on Slopmower review <id>"; a dismissed one is `wont_do` set by the user, and a reopen accepts it.
  - The UI marks a pending suggestion "Suggestion" in the request list, the file header, and the thread, has Accept and Dismiss in the code view and on the request detail, the "Suggestions" filter, and a second copyable prompt "Review the code of Slopmower review <id> and suggest changes".
  - D72 holds the decision. Specs section 8 item 10 lists it as an amendment of v1 before the first release.

- **Decisions and deviations:**
  - "Spec details" and "Usage limits (D32)" in the [scope file](../F48-agent-suggestions.md#decisions).
  - The pending count is the last parameter `$pendingSuggestions` of `RequestDecider::decide()`, as `$availability` is. `RequestCommands` reads it with `countPendingSuggestions()` in the executor closure, the transaction of the write.
  - `ChangeRequest::project()` sets `suggestionState`, and `opened()` does not, because the value changes after the open and `project()` runs after every `opened()`.
  - While a suggestion is pending, the refused `claim`, `mark_wont_do`, and `set_plan_requirement` end their `invalid_transition` message with "the suggestion waits for the user to accept or dismiss it".
  - Q20 is in `AgentRequestController`, which has the full path on each route, so it holds a `/reviews/{reviewId}` route. The route names do not change.
  - V1 needs no new scope code: the `repository_scope` filter gives 404 for a repository outside the token scope.
  - The Q22 note is kept as written, as the optional release and verify notes are. The UI sends an empty note as null.
  - The Q1 `suggestion` value is a typed `?SuggestionState`, so an unknown value gets 400 `invalid_input`. It is part of the cursor filters, so a cursor issued before F48 gets 422 once; v1 has no release yet.
  - `suggest_request` with `anchorKind` null gives `invalid_input` for each other anchor parameter that is not null, under that parameter's name.
  - Accept and Dismiss in the code view run in the action of the request detail route: `useRequestCommand()` takes the route of its action.
  - On the request detail, Accept and Dismiss are in the header next to the request actions, and the "Suggestion" label is next to the turn label, because the thread there has no header.
  - The "Suggestions" filter of the request list is a checkbox that sets `suggestion=pending`.
  - `SuggestionFlowTest` unchecks "Ask for a plan first" before Accept, so the agent links and marks ready without a proposal.
  - The developer guide had `Application\Query` at 42 files; it has 43.
