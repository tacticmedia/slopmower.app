## Report: M12 Reviews API

- **Status:** Done, committed as 60d472a on 2026-10-02.
- **Summary:** `ReviewCommands::start()` runs V1: the clone must be ready, it fetches unless the ref is a full SHA in the clone, resolves the ref with `rev-parse --verify --end-of-options <ref>^{commit}`, writes the pin `refs/holistic-review/reviews/<reviewId>` (D26), and records `review.started`. A failed transaction deletes the pin. The decision reads the repository fresh and refuses a removed access. `close()` serves V4 (D27). `ReviewQuery` serves V2 and V3 with the request counts of each review. `TreeQuery` and `FileQuery` read the pinned commit for V6 and V7. `BlobStream` streams V8 and R7 from a `git cat-file --batch` process of its own (`src/Git/StreamedBlob`), with the byte headers and the caching of docs/specs. Every new route has a cross-tenant case.

- **Deviations and decisions:**
  - `ReviewCommands::start(RepositoryId, ?RefName, ?string $title, Actor): ReviewId` is the V1 flow and generates the review ID. The M07 transaction method is now `recordStarted()` and stays public, because the event-store tests (`CommandFixtures`, `append-events.php`) record reviews without a clone through it.
  - The fetch skip uses `GitReader::hasCommit()`, then `FetchRepository::fetchNow()`, not `CommitAvailability::ensureAvailable()`: the spec skips the fetch only for a full SHA, and `ensureAvailable()` also skips it for a short SHA in the clone. So `public` is dropped only on `ReviewCommands`. `CommitAvailability`, `RequestCommands`, and `EventLogQuery` stay public.
  - Default title, by the orchestrator's docs decision: the 12 SHA characters alone only when `ref` is a full SHA of 40 or 64 characters. A short SHA, a branch, or a tag gives `<ref> @ <12 characters>`, the ref part cut to keep 200 characters.
  - No `ref` and no default branch gives 422 `invalid_input` on `ref`. No document decides this case.
  - The controller validates `ref` with `RefName::fromString()` before the start, so 422 comes before 409 as the check order says.
  - The `review.started` decision reads the repository with `findFresh()` and throws `RepositoryUnavailable` with reason `removed` when `access` is `removed`. The rollback test sets `access` and `syncState` with a DQL update in a `RepositoryFetched` listener, because the entity has no setter before M33. The listener tests disable the kernel reboot, so the listener and the requests share one container.
  - New `ActorNormalizer`, not in the plan's file list: `Review.startedBy` and `closedBy` need `name` and `avatarUrl` of actor.schema.json. A user actor reads its user (login, avatar), an agent uses `agentName`, the system is "Holistic Review". It also completes the normalized `InvalidTransition.details.claimedBy`, the M11 follow-up for M13.
  - `counts.outdated` is 0: no request has a location before M29.
  - V2: keyset on `createdAt` descending, then ID descending. The cursor key is the Unix second and the ID. The filter hash holds `state`.
  - V6 sorts and pages the `ls-tree` output in memory. The key is (directory first, path in byte order); a recursive listing has no directories. Entries whose path `RepoPath` refuses are left out, for example a root `-notes.md` or a path that is not valid UTF-8, because V7 and V8 take only `RepoPath` values and the schema has its pattern. The cursor is decoded before the clone check, so a bad cursor gives 422 before 409. A missing `dir` gives 404 and a `dir` that is not a directory gives 422, also for a submodule.
  - Path lookup: `GitReader::entryAt()` lists the parent directory and picks the exact path. It gives null only for the stable `LC_ALL=C` messages of git for a missing parent (`Not a valid object name <commit>:<parent>`) and for a file or submodule parent (`not a tree object`), so those paths give 404 (the M08 follow-up). Every other git failure, for example a missing clone or a timeout, is rethrown and gives 500.
  - `FetchRepository::readyClonePath()` returns the clone path of a ready repository. V1 and V6 call it inside the service; V7, V8, and R7 call it once in the controller and pass the path to `FileQuery` and `BlobStream`.
  - `FileContent::symlinkTarget()` is null for a target that is not valid UTF-8, which JSON cannot carry.
  - V7 reads a blob of at most 1 MiB through the shared batch process. Above that it reads only the first 8,000 bytes, for `binary`, through `StreamedBlob`. The rules (`tooLarge`, `renderable`, `lineCount`, `symlinkTarget`) live in `FileContent`.
  - `language` comes from the file name in `FileContentNormalizer`, with Shiki-style names (`php`, `javascript`, `markdown`, ...), null for other files. It is an open set.
  - `rawUrl` comes from the router, which keeps `/` unencoded in the query (`raw?path=src/Billing/InvoiceTotals.php`). The spec example encodes it as `%2F`. Both are the same URI reference.
  - `Cache-Control` lists the directives in the framework order: `immutable, max-age=31536000, private` and `no-cache, private`. The directives are those of docs/specs section 6.
  - R7: a malformed `blobSha` gives 422 `invalid_input` from `BlobSha::fromString()`, no route requirement. V8 and R7 open the blob before the 304 check, so an object that is not in the clone gives 404 first. V7 builds its 304 in the controller before it reads the blob.
  - `BlobStream` builds the byte response in the Application layer, because V8 (`CodeController`) and R7 (`BlobController`) share it. The process lives in `src/Git/StreamedBlob`, because `NoProcessOutsideGitTest` allows `symfony/process` only under `src/Git`. The body is a `StreamedResponse` over a chunk generator, so `src` has no `echo`.
  - The `CodeController` actions are `listTree`, `getFile`, and `getRaw`: `file()` collides with `AbstractController::file()`.
  - V1 and V4 carry `#[IsGranted(User::ROLE, message: CurrentActor::SESSION_ONLY)]` and take the actor from M14's `CurrentActor` in the action, not from a `#[CurrentUser]` argument, because arguments resolve before `#[IsGranted]`. `ActorKindTest` covers both. The `repository_scope` filter of M14 already has rules for `Review` and `ChangeRequest`; `TokenScopeTest` now proves the review part through V3 instead of a direct `find()`.
  - `CrossTenantCases`: `schema` is null for a response without a JSON body, bytes or none. The other tenant has a review row without events (`ApiFixtures::storeReview()`), and the `blobSha` placeholder takes a blob of its source.
  - Skills: `make-controller` scaffolded the three controllers (`make:controller --no-template`, `--invokable`), then rewritten to the plan's routes. `make-entity` did not apply: no mapping change. `services`, `configuration`, `components`, `discover`, `make-test`, and `cli-conventions` were followed.

- **Risks discovered:**
  - In `dev`, the web profiler's toolbar listener appends nonces to every `Content-Security-Policy` header, so V8 and R7 send `sandbox ; default-src 'none'; script-src 'unsafe-inline' 'nonce-...'`. `sandbox` still applies. The `test` and `prod` environments send the exact value.
  - Each V8 and R7 request starts one `git cat-file --batch` process, and so does V7 for a blob above 1 MiB. V6 lists the whole directory, or the whole subtree for `recursive`, for every page.
  - A git failure during a stream ends the body after the headers are sent, so the client sees a short body.
  - The M11 worker risk happened again during the manual check: after the stack restart, the worker crashed on a rebuilt container file and kept the clone message. Setting `delivered_at` to null in the worktree's `dev` database released it.
