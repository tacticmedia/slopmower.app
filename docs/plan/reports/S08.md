## Report: S08 One serialization path

- **Status:** Done (awaiting commit).
- **Evidence check:**

  - DTOs without a normalizer go through `ObjectNormalizer`: held. In `src/Application/Query`: `BatchSubmission`, `IndexStatus`, `LinkCommitsResult`, `RepositoryPage`, `RequestCommandResult`, `RequestPage`, `ReviewPage`, `SymbolList`, `TreeListing`, `UpdatedRequest`, `UpdatesPage`.   - A reader cannot tell the path: held in three places. `LocationView` held only an enum and the domain `Location`, and `CodeExcerpt` is schema-shaped, but `LocationNormalizer` and `RequestNormalizer::excerpt()` mapped them by hand. Five normalizers that pass their array back to the Serializer, `SymbolList`, and `MeController` converted value objects and enums with `toString()` and `->value`, while other code passed the objects to the Serializer.
  - Many DTOs wrap an entity and add a few fields: held, `RepositoryView`, `ReviewView`, `RequestSummaryView`, `RequestView`, `CommitLinkView`.
  - REST and MCP share the path (D37): held. `AbstractController::json()` and `McpToolRunner::run()` use the same `serializer` service.
- **Measurement and choice:**
  - A, a normalizer for every response class: the 11 schema-shaped DTOs and the nested `ExtractedSymbol`, `LineRange`, and `CodeExcerpt` would each get one, at about 40 lines each: about 550 lines more. Rejected.
  - B, every response class schema-shaped, normalizers only for values: removes about 30 lines of boilerplate per normalizer, but each view repeats every schema field as a property and as a factory argument. Estimate: about 150 lines fewer, with 13 view classes rewritten, the mapping moved into queries and controllers, the clock and the URL generator injected there, `#[Ignore]` on the fields that queries read (`RequestSummaryView::$state` and `$request`), and the fields of `RequestSummary` and `Event` repeated in `RequestView` and `ThreadEntry`, whose schemas extend them. Rejected: not more direct.
  - C, chosen: a response class is schema-shaped: its public properties are the fields of its schema, in schema order, and `ObjectNormalizer` writes it. A class that cannot be, because it wraps an entity, a recorded event, or an `App\Git` object, merges another schema, or computes a field, has one normalizer named after its schema, and that normalizer also maps its nested parts. Values go through the value normalizers, and an anchor goes through `AnchorCodec::encode()`, the stored payload format. Then fix the classes that break the rule. Result: 1 normalizer fewer, `App\Serializer` 59 lines shorter, `src` 39 lines shorter.

The array literals of A1, A3, V11 and V12, D1, and T1.

  - Nested parts mapped by the normalizer of their schema: `CommitDiffFileView` in `CommitDiffNormalizer`, `IssuedApiToken` (`ApiTokenWithSecret`) in `ApiTokenNormalizer`, the GitHub and local candidates in `CandidateListNormalizer`.
  - Values: `ValueObjectNormalizer`, `ActorNormalizer`, `UtcTimeNormalizer`, and the framework enum normalizer. Anchors: `AnchorCodec::encode()` in `DraftNormalizer`, `RequestSummaryNormalizer`, and `RequestNormalizer`.
  - Still written by hand, both listed under deviations: the `WontDoReason` in `EventNormalizer::body()`, and the token secret in `ApiTokenNormalizer`.
- **Summary:** `ValueObjectNormalizer` writes every value object that reaches a response: typed IDs, commit and blob SHAs, paths, refs, and repository names. `LocationView` is schema-shaped, built with `LocationView::of()`, so `LocationNormalizer` is gone. `CodeExcerpt` goes through `ObjectNormalizer`, so `RequestNormalizer::excerpt()` is gone. The normalizers, `SymbolList`, `MeController`, and `ViewedFileRepository::paths()` pass value objects and enums to the Serializer instead of their strings. The rule is in the plan README code conventions, the developer guide section 5, and D37. The JSON of every REST response and every MCP result is unchanged byte for byte.

- **Deviations and skips:**
  - The views that wrap an entity keep their normalizers: option B above.
  - `ThreadEntryNormalizer` stays apart from `EventNormalizer`, and `RequestSummaryNormalizer` apart from `RequestNormalizer`: thread-entry and request-summary are schemas of their own in docs/specs, and the rule gives each schema one normalizer named after it. A merge would save about 30 lines each, but one normalizer would then write two schemas under the name of one.
  - `EventNormalizer::body()` writes the string of a `WontDoReason`: `body` is a computed field that picks one field per event type, so `WontDoReason` is not a type of `ValueObjectNormalizer`. `ApiTokenNormalizer` writes the token secret by hand, so that no value normalizer can write a secret elsewhere.
  - `RequestQuery::get()` reads the excerpt before the commit links. Both are reads, so the result does not change.
  - `config/reference.php` is regenerated by the cache warmup. It is not part of this commit.
