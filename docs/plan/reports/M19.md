## Report: M19 Settings: API tokens

- **Status:** Done, committed as acfb999 on 2026-10-02.
- **Summary:** The client route `/settings` reads T1 and every page of R1 in its loader, and writes through one route action that `useFetcher` calls with a JSON body: create (T2) or revoke (T3). A Primer `DataTable` shows name, scope, created, last used, expiry, and state, with a "Revoke" button and a `ConfirmationDialog` for active tokens. The create `Dialog` takes the name with the `TokenName` rule as a hint, the scope ("All repositories" or one repository), and an optional expiry date. After T2 the same dialog shows the secret once, with a copy button, the `SLOPMOWER_TOKEN` note, and the `.mcp.json` snippet built from `links.mcpUrl`. M15 is not on `main` at this commit, so the E2E checks that the plan wants through MCP use the REST bearer equivalents (see Deviations).

- **Deviations and decisions:**
  - M15 is not on `main` at this commit, so `/_mcp` and `list_repositories` do not exist. Three E2E cases use the REST bearer equivalent: A1 instead of MCP `initialize` (also for the 401 after revoke), R1 instead of `list_repositories`. Both responses are validated against `me.schema.json` and `RepositoryPage`. `McpHttpClient` is not written, because there is no endpoint to test it against. The plan's "Depends on" line names M14 and M17 only.
  - `tests/Support/E2E/TokenSettings.php`, a trait for `PantherTestCase`, holds what both E2E classes share: sign-in and open `/settings`, fill and submit the create dialog, close the one-time display, read a table cell by its column header, and a bearer GET from the PHPUnit process to `PANTHER_EXTERNAL_BASE_URI` through `symfony/http-client`.
  - Expiry: a date input. The token expires at 23:59:00 of the chosen day in the browser's time zone, sent as UTC with second precision (`DateTime` of docs/specs). The input offers today up to the latest day whose end is not later than now plus exactly 366 x 24 hours, the T2 limit. Counting calendar days fails when a DST fall-back lies in the window. A user who picks today after 23:58 gets the 422 of T2 in the dialog.
  - One route action for both writes, `{intent: 'create', input}` or `{intent: 'revoke', tokenId}`, sent by `useFetcher` with `encType: 'application/json'`. A 422 `invalid_input` or 404 `not_found` of T2 returns to the dialog as data: violations of `name`, `repositoryId`, and `expiresAt` show under their field, others (the limit of 50, an unknown repository) above the form. Other errors go to the error page. React Router revalidates the loaders after each write, so the table updates.
  - The secret lives only in the fetcher of the create dialog. The dialog mounts only while open, so "Done" or the close button drops the secret.
  - While T2 runs, the dialog ignores a second submit (a ref plus `fetcher.state`, because the fetcher state changes in a transition), ignores Cancel, Escape, the backdrop, and the close button, and disables Cancel. So every created secret is shown. `settingsAction` passes `request.signal` to `apiWrite()`.
  - Messages use Primer `Banner`: `critical` for a create failure, `warning` for the one-time notice. `Flash` is deprecated in 38.40.0.
  - The `.mcp.json` snippet shows only in the one-time display, as the plan says. docs/user/connect-your-agent.md says that Settings shows the snippet; it does, after each create.
  - The scope select lists every repository of R1, removed ones included, through all pages with `limit=500`. The table shows `repositoryName` of T1.
  - "Revoke" shows only for active tokens. An expired or revoked token cannot authenticate.
  - `ConfirmationDialog` inside our tree, not `useConfirm`: the hook renders into a second React root outside `ThemeProvider`.
  - Dates use `Intl.DateTimeFormat` in the browser's locale (medium date, short time) inside `<time datetime>`. Null shows "Never".
  - The copy button uses `navigator.clipboard.writeText`. Outside a secure context the API is undefined; the button then shows "Copy failed. Select the text and copy it." It is checked by hand only: headless Chrome needs a clipboard permission, and the button has no rule of ours.
  - The empty state ("No tokens yet.") takes the `table` grid area of `Table.Container`, so it shows under the subtitle.
  - Skills: `make-test` (E2E tests extend `PantherTestCase`, as the plan says), `cli-conventions` (only `make` targets), `components` (`symfony/http-client` for the bearer calls of the tests). `services`, `configuration`, and `discover` had nothing to apply: the milestone changes no PHP in `src/` and no configuration.
