## Report: M25 Drafts, batch review, viewed files

- **Status:** Done (awaiting commit).
- **Summary:** `Draft` and `ViewedFile` are tenant entities with a migration and a `repository_scope` rule each. D1 to D5 and V11 and V12 are session-only routes. D2 captures the anchor with the Q2 `AnchorFactory`, holds a `symfony/lock` lock for the 500-drafts limit, and answers 404 for an unknown request and 422 for a request of another review. D5 (`RequestCommands::submitDrafts()`) reads the caller's drafts under the tenant lock, writes `request.opened` or `request.commented` per draft and then `batch.submitted` in one `CommandExecutor` transaction, and removes exactly the drafts that it read. V4 deletes the closing user's drafts in its `inTransaction` callback. The batch arrives in other windows as one `events` update. The UI has "Start a review" / "Add review comment", Pending draft threads with Edit and Delete, "Finish your review" with a count and a summary overlay, a "Viewed" checkbox, viewed marks in the tree, and the draft warning in the close dialog.

- **Deviations and decisions:**
  - No `DraftService`, `SubmitBatch`, or `ViewedFiles` class (Jan's rule: no service class with one consumer). D1 to D4 live in `DraftController`, D5 in `RequestCommands::submitDrafts()` beside the other request commands (it reuses their fresh state reads), the `BatchSubmission` view in `RequestQuery`, and V11 and V12 in `ViewedFileController`.
  - `ViewedFileSql` writes the marks with `INSERT ... ON CONFLICT DO NOTHING` and a `DELETE`, so V12 stays idempotent under concurrent calls; an ORM unique-violation would close the entity manager. The unique key is `(review_id, user_id, path_hash)` with the SHA-256 of the path, because a B-tree entry holds about 2.7 kB and a `RepoPath` up to 4096 characters.
  - The 500-drafts limit counts and inserts under a `LockFactory` lock per review and user, as `ApiTokenIssuer` does for tokens. The limit violation and "no drafts" use the field `''`.
  - D5 check order: "no drafts" (422) comes before `review_closed` (409), as docs/specs/README.md section 4 orders `invalid_input` first. A closed review usually has no drafts of the closer, so the 409 tests use a draft that stays because a second user of the tenant closed the review.
  - A draft of another user answers 404 through `DraftVoter::OWN` in `#[IsGranted(..., statusCode: 404)]` on D3 and D4. It runs after the class-level session check and before the body mapping.
  - `Review::assertOpen()` throws `review_closed` for both new controllers and `AnchorFactory`. `CurrentActor::sessionUser()` replaces the private copies in the controllers, also in `TokenController`.
  - The code view adds a line with a saved thread and a pending draft once: `stableAnnotations()` deduplicates its lines. The D5 form ignores a second submit while one runs.
  - Draft times are stored in UTC with second precision; D1 and D5 sort by `createdAt`, then by ID.
  - `batch.submitted` lists each request once, in draft order, also when several reply drafts name the same request (`BatchSubmittedEvent` refuses duplicates).
  - UI: reply drafts are API-only. The UI creates and shows only new-request drafts; "Finish your review" counts all drafts. The composer's second button reads "Start a review" without drafts and "Add review comment" with drafts, as on GitHub.
  - UI: the `review` route data is `{review, drafts, viewedPaths}` (D1 and V11 load with V3), so the header count, the close warning, the file drafts, the checkbox, and the tree marks revalidate after every action and live update. The review action takes the form field `intent` (`close` or `submit`). After D5 the action records the batch seq with `eventPositions.written()`, so the own live update causes no second revalidation.
  - UI: the Edit and Delete of a draft sit in its "..." menu, as on GitHub. Delete hides the draft at once and shows it again with the error when D4 fails. Delete asks no confirmation.
  - Tests: `SubmitBatchTest` calls `disableReboot()` for two tests, because in Symfony 8.1 `KernelBrowser` builds a new container per request (`AbstractKernel::shutdown()` drops the container), so a listener or the traceable hub of the test would not see the request.
  - Skills: `make-entity` (maker scaffold of both entities, then ULID IDs and `TenantOwned`; the maker refuses the property name `user` as a reserved word, so it was added by hand), `make-migration` (`make migration`, reviewed, description added), `make-controller` (maker scaffold of `Api\DraftController` and `Api\ViewedFileController`, then `#[Route]`, `#[IsGranted]`, `#[MapEntity]`, `#[MapRequestPayload]`), `make-voter` (maker scaffold of `DraftVoter`, then one `OWN` attribute), `components` (`symfony/lock` for the limit), `configuration` (the limit is the class constant `Draft::MAX_PER_USER_AND_REVIEW`), `services` (autowiring only), `discover` (vendor reads of `KernelBrowser`, `EntityValueResolver`, `WhenValidator`), `make-test`, `cli-conventions`.
