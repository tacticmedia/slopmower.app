## Report: F106 Reload when a code chunk fails to load

- **Status:** Done 2026-11-03.
- **Summary:**
  - A `vite:preloadError` listener in `assets/layout/RouteError.tsx` records each error of a code chunk that did not load. It marks the error for a reload when the tab did not reload for a chunk in the last 60 seconds (`slopmower.chunkReloadedAt` in `sessionStorage`).
  - `RouteError` reloads the page for a marked error, shows the loading spinner, and sends no Sentry event. The reload comes from the error screen, because React Router sets the address of the navigation only after the failed chunk.
  - A chunk error that is not marked shows "Loading failed" and "Part of Slopmower did not load. Check your connection and try again.", sends the Sentry event, and its "Try again" reloads the page. This closes the risk of the F102 report.
- **Files:** `assets/layout/RouteError.tsx`, `tests/ui/ChunkReload.spec.ts`, `tests/ui/support/sentry.ts`, `tests/ui/SentryReports.spec.ts`, `docs/architecture.md` (D106).
- **Tests added:**
  - UI `ChunkReload`: "A click on a request whose screen chunk fails reloads the page once, shows the request, and sends no event".
  - UI `ChunkReload`: "A screen chunk that fails also after the reload shows "Loading failed" and sends one event, and Try again reloads the page".
- **Verification:**
  - Mutations, each restored after the run:

    - A Sentry event also during the reload: both tests fail with 2 events.

    - No 60-second limit: the second test fails, because the page reloads again.
