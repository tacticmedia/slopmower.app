- **Decisions and deviations:**
  - **Split.** The Composer part is complete on the current runtime. `composer.json` keeps `"php": ">=8.5"`, the base image stays `dunglas/frankenphp:1.12.7-php8.5-trixie`, and `.php-version` stays 8.5. The acceptance tests "PHP 8.6 and FrankenPHP 1.14.0" and "`HubIsolationTest` against the hub of the new image" are open.
  - **Doctrine types.** DoctrineBundle 3.4 with DBAL 4.6 and ORM 3.8 gives each connection its own type provider. For a type of `doctrine.dbal.types`, the provider returns an instance that the global registry does not hold, so `Type::lookupName($this)` threw "Type of the class ... is not registered" in `doctrine:schema:validate`. DBAL 4.6 also deprecates `lookupName()` with a runtime deprecation, and `phpunit.dist.xml` fails on a direct deprecation. `IdentifierType` and `StringValueType` take the value class in the constructor and keep their checks. `config/packages/doctrine_types.php` registers one service per value class with the tag `doctrine.dbal.type`. It is PHP, because YAML needs four lines per class. The 17 type names and the schema are the same: `doctrine:schema:validate` reports the schema in sync.
  - **Mapping `alias`.** DoctrineBundle 3.4 deprecates it and it has no effect in ORM 3. Removed from both mappings.
  - **Mercure protocol.** `protocol_version: '0.x'` keeps the tokens, the cookie name, and the `topic` parameter as they were, for the hub of the image and for the production hub in compatibility mode.
  - **Mercure cookie at sign-out.** The bundle 0.7.0 clears the subscriber cookie on `LogoutEvent`. Account deletion calls `Security::logout()`, so its response also clears `mercureAuthorization`. The default stays, because a signed-out browser must not keep a subscriber token. A2 of `docs/specs/rest-api.md` names the cookie.
  - **`COPY --link --chown`.** `make prod-check` failed before any build step: "--chown=www-data:www-data: user and group names can't be resolved when used with --link, use numeric uid[:gid] instead". The `Dockerfile` was the one of `main`, with Docker 29.8.2, buildx 0.37.2, and the frontend `docker/dockerfile:1`, which is 1.29.0 of 2026-11-11. `id www-data` gives 33 in both base images. The line uses `33:33`. The workflow runs `make prod-check`, so `make act` needs it.
  - **Recipes.** None applied. The 0.6 recipe of `symfony/mercure-bundle` belongs to the Mercure 1.x step. The updates of the `doctrine/doctrine-bundle`, `symfony/framework-bundle`, `symfony/security-bundle`, and `zenstruck/foundry` recipes were available before this update.
  - **`SessionLockedMcpController`.** It stays. `mcp/sdk` 0.9.0 answers a POST with its own responses and saves only the changed keys of a session, but it still reads and writes the session without a lock unless a session lock is set. The docblock, D40, and the developer guide say what the SDK does now.
  - **`Origin` header on `/_mcp`.** `mcp/sdk` 0.9.0 checks `Origin` against `http.allowed_origins`, which stays empty, and no longer against the allowed hosts. On the dev site: `Origin: http://evil.example` and `Origin: http://localhost:9999` get 403 "Forbidden: Invalid Origin header.", and the own origin and a request without `Origin` get 200. An agent sends no `Origin`. `docs/specs/mcp.md` does not name the header, so it has no change.
  - **Gotchas of `docs/plan/README.md`, checked in the installed source.** `mcp/sdk` 0.9.0: -32602 for an input-schema failure, -32603 for another exception, the `isError` result of a `ToolCallException`, the output validation, the nullable type order, `items: {}`, and `outputSchema` only from `#[McpTool]`. Not checked again: "object and DTO parameters are not supported". playwright-php 1.6.0: no `allTextContents` action in the Node server, `filter(['has'])` as CSS `:has()`, `toHaveText()` as a substring check, `AssertionException`, the failure screenshot, the launch flags, no download action, and `playwright ^1.62.0`. Not checked again: the `getByRole()` matching and the 30 s poll.
  - **Verified versions.** The Composer rows hold the installed versions. The rows of Symfony, `hwi/oauth-bundle`, and `league/commonmark` were behind `composer.lock` before F125 and are corrected.
