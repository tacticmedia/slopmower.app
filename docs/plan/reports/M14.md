## Report: M14 API tokens

- **Status:** Done, committed as eeee914 on 2026-10-02.
- **Summary:** `ApiToken` stores the SHA-256 hex of an `sm_` secret, a 9-character prefix, an optional repository scope, an optional expiry, and `lastUsedAt` and `revokedAt`. `ApiTokenIssuer` serves T2, and `TokenController` serves T1 to T3. The stateless firewall `api_bearer` comes before `api`: `BearerApiRequestMatcher` selects it, the built-in `access_token` authenticator calls `ApiTokenHandler`, and `BearerAuthenticationFailure` answers every 401 with the Error body and the docs/specs `WWW-Authenticate` header. The handler returns an `AgentUser` (role `ROLE_AGENT`), sets the tenant context, and for a scoped token enables the new Doctrine SQL filter `repository_scope`, so rows of other repositories do not exist for the request and their IDs answer 404. `CurrentActor` gives actor `user` or `agent`. A1 shows the agent caller and the `token` object. Session-only routes deny tokens with 403 through `#[IsGranted(User::ROLE)]`.

- **Deviations and decisions:**
  - `AccessScope` is enforced by a second Doctrine SQL filter, `RepositoryScopeSqlFilter`, not by a condition in each query. The handler enables it through `TenantContext::restrictToRepository()`. `#[MapEntity]` path IDs resolve through it, so a scoped token gets 404 for another repository before any 403, and the review, request, and draft queries of M12, M13, and M25 are scoped without code of their own. Rules: `repository.id`, `review.repository_id`, `change_request` and `review_event` through `review_id`, `comment` and `commit_link` through `request_id`. `User` and `ApiToken` are not scoped. Any other tenant entity throws a `LogicException`, so a new entity fails closed until it has a rule. The subqueries do not name `tenant_id`: the outer table is tenant-filtered and the IDs are global ULIDs. The filter is not a `*Sql` class, the same as `TenantSqlFilter`. `TenantContext::set()` keeps the scope, so a message that `sync://` handles in the request stays in it; `reset()` disables it between worker requests.
  - `ApiTokenSecret` is a domain value object: generation, the format check of the handler, the hash, and the prefix. The base64url conversion uses `base64_encode()` and `strtr()`, so `src/Domain` needs no extension. The pattern has the `D` modifier, so a trailing newline does not match.
  - `ApiTokenState` and `TokenScope` are backed enums, checked by `EnumContractTest`. A revoked and expired token is `revoked`.
  - The actor-kind rule uses roles, not a voter: `User::ROLE` is `ROLE_USER`, `AgentUser::ROLE` is `ROLE_AGENT` (the role that M15 names). R2, R3, and T1 to T3 carry `#[IsGranted(User::ROLE, message: CurrentActor::SESSION_ONLY)]`. `ApiExceptionListener` keeps the 403 message. `TokenController` reads the user with `getUser()`: `#[CurrentUser] User` resolves before `#[IsGranted]` and would deny an agent with a message that names classes.
  - `AgentUser` is not an entity and has no provider: the handler's `UserBadge` loader returns it, so the `make-user` maker does not apply. Its roles are only `ROLE_AGENT`, unlike the skill's "always `ROLE_USER`": `ROLE_USER` means a session caller here. Its identifier is the token ID. It does not implement `TenantOwned`; the handler sets the tenant context, as the plan says.
  - `BearerApiRequestMatcher` matches the scheme case-insensitively (RFC 9110). `HeaderAccessTokenExtractor` accepts only `Bearer`, so `bearer sm_...` gets 401 `invalid_token` instead of a session fallback. `BearerAuthenticationFailure::start()` adds `error="invalid_token"` only when the request has a Bearer header, so the `mcp` firewall of M15 answers a call without a token with the plain challenge.
  - The 401 message with a token is "The API token is malformed, unknown, revoked, or expired."; without one it stays "Authentication is required.". `ApiAuthenticationEntryPoint` now takes its 401 from `BearerAuthenticationFailure` (M10 follow-up).
  - T2: the expiry window is body validation (422, field `expiresAt`) and comes before the 404 of `repositoryId`. The limit of 50 active tokens is a domain rule (422, field `""`) after it. A `LockFactory` lock per user holds the count and the insert together. An expiry with an offset is stored in UTC, because the column type drops the offset. `repositoryId` input is case-insensitive (`#[Assert\Ulid]`). T2 sends no `Location` header; docs/specs names none.
  - `MeController` takes `#[CurrentUser] User|AgentUser`, builds `caller` from `CurrentActor`, and loads the user and token of an agent through the SQL filter. `ApiTokenNormalizer` serves A1, T1, and T2; for an `IssuedApiToken` it adds `secret`.
  - `CrossTenantCases`: `schema` is null for a response without a body (T3, 204).
  - `TokenScopeTest` checks the review part with `find()` under the tenant and scope that the handler sets, because no review route exists before M12.
  - "The secret never appears in var/log": the `test` environment logs through `fingers_crossed` at `error`, so the test also reads every log record of the request from the profiler's logger collector. The test helper `bearerRequest()` marks its secret parameter `#[\SensitiveParameter]`, because the exception trace reaches the test frames.
  - Tests beyond the acceptance list, each for a rule of the scope: the list states and order, the unknown `repositoryId`, 404 before 403, the scope filter for every entity, and the scope reset.
  - Skills: `make-entity` scaffolded `ApiToken` (`--with-ulid`, `--relation=owner:...`, because the maker refuses the name `user`), then it was rewritten to the project shape; the maker's inverse collections on `User` and `Repository` were removed, because the session serializes `User`. `make-migration`: generated, read, description set. `make-controller` scaffolded `TokenController` (`--no-template`), then rewritten. `make-security-custom` did not apply: the built-in `access_token` authenticator fits. `make-voter` did not apply: the actor kind is a role, and visibility is the SQL filter. `services`, `configuration`, `components` (`symfony/lock` for the limit), `discover`, `make-test`, and `cli-conventions` were followed.

- **Risks discovered:**
  - The scope filter adds subqueries to every ORM query on request-owned tables in a scoped bearer request. Fine at proof-of-concept scale.
  - Raw SQL in `*Sql` classes does not see the scope filter. Today it reads by a review ID that a filtered lookup resolved. A raw SQL read that takes an ID from the input directly must check the scope itself.
  - Entities loaded before the handler runs are not scoped, as with the tenant filter. The handler runs at authentication, before any controller loads data.
