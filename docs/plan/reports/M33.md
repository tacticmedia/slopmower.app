## Report: M33 GitHub App repositories

- **Status:** Done (awaiting commit).
- **Summary:** `lcobucci/jwt` 5.6.0 signs the RS256 App JWT. `InstallationTokenProvider` requests a new installation token for one repository with `contents: read` at each clone or fetch. A `LoginSuccessEvent` listener lists the installations and their repositories at each GitHub sign-in with the user token from the `OAuthTokenBadge`, replaces the tenant's `GitHubInstallation` and `GitHubCandidate` rows, updates the connected repositories, and, only after a complete listing, removes the access of connected repositories that the listing lacks: `removed`, `unavailable`, and a `DeleteCloneJob` deletes the clone. R2 lists the GitHub candidates with `githubListedAt` and `githubConfigureUrl`, A1 fills `features.githubApp`, R3 connects a candidate, and the fetch sends the token only as a `GIT_CONFIG_*` extraheader. `GET /github/installed` signs in again through `/connect/github?_target_path=/repositories`. The repositories screen has a GitHub section.

- **Deviations and decisions:**
  - The sync is an `#[AsEventListener]` on `LoginSuccessEvent` of the `main` firewall, as the M32 report planned. The passport's `OAuthTokenBadge` keeps the `OAuthToken` that the authenticator built, with the user token; `DropOAuthTokenListener` replaces only the session token. The plan task said "hook it into GitHubUserProvider"; the review moved it. The listener sets the tenant context, because the firewall authenticates before `TenantContextListener`.
  - A failed or partial listing is logged as a warning, the sign-in continues, and no row changes: no installation, no candidate, no removal.
  - The sync replaces the tenant's installation and candidate rows (DQL delete, then insert) in one transaction under the `LockFactory` lock `github-repositories:{tenantId}`, which the GitHub connect also holds (M06 orchestrator decision: "under the tenant lock").
  - The sync also updates the name, installation ID, and `private` of connected repositories, because docs/specs/README.md section 7 says that each sign-in updates the name. A rename onto a name that another repository of the tenant holds, in any case, waits.
  - Access removal, orchestrator decision: `FetchRepository::removeAccess()` sets `removed` and `unavailable` with a conditional DQL update, then dispatches `DeleteCloneJob` (tenant ID, repository ID) outside any transaction, then the event `RepositoryChanged`. The worker handler takes the `RepositoryLock` and deletes the clone; a repeated run finds nothing to delete. The job needs no repository row, so M31 can reuse it for R6. No index exists before M26, and no Mercure before M24, so `RepositoryChanged` (the name M24 plans) has no listener yet.
  - Installations are filtered by the top-level `target_type` before the payload is denormalized: a documented enterprise account has `slug`, `name`, and `html_url`, but no `login` or `type`. Only `User` and `Organization` installations are recorded; enterprise installations hold no repositories.
  - The listing follows the `next` link of the `Link` header, parsed with symfony/web-link's `HttpHeaderParser`, with `per_page=100`. A next link outside `https://api.github.com/` fails the listing.
  - `Repository` stores `github_installation_id` and `github_private`. `github.owner` and `github.htmlUrl` of R4 come from the name (`https://github.com/<owner>/<name>`), so they follow each rename. `GitHubCandidate` stores `owner` and the short `name` (the plan's fields) and the `htmlUrl` from GitHub.
  - `githubListedAt` is the newest `listedAt` of the tenant's candidates, null without candidates. `githubConfigureUrl` is the install URL of the spec example, `https://github.com/apps/<slug>/installations/new`, with the A1 rule: null without an App (client ID or slug empty) or for a local sign-in. `GitHubApp` holds the rule for A1 and R2.
  - R2: GitHub candidates come first, sorted by full name case-insensitively, then local candidates with the rest of the 1,000-item limit. `LocalRepositoryDiscovery::list()` takes the limit.
  - R3: a case-insensitive name collision with another GitHub repository of the tenant answers 422 `invalid_input` on `githubRepositoryId`. The M06 decision names the check; no source names the error code, and a domain rule failure is `invalid_input`.
  - R3 for a repository whose access was removed returns it with 200, as docs/specs says for an existing repository. It is not reactivated, neither by R3 nor at sign-in: no source specifies it. R6 (M31) deletes its data, then the repository can be connected again.
  - The git base URL is the environment variable `GITHUB_GIT_BASE_URL` (a host, so an environment variable by the `configuration` skill), default `https://github.com`. The extraheader key stays `http.https://github.com/.extraheader` for every base URL, so a changed base URL never receives the token.
  - The JWT: `iat` is now minus 60 s, `exp` is `iat` plus 600 s, both whole seconds (`ChainedFormatter::withUnixTimestampDates()`; lcobucci's default writes floats). A missing client ID or key, or a key that cannot sign, is a `GitHubRequestFailed`, which ends as `lastError`.
  - API headers: `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2026-03-10`, the current version. Its breaking changes do not touch the fields that M33 reads. The requests go through the scoped client `github.client`.
  - The token request sets `extra.trace_content: false`, so the dev profiler does not store the token response on disk. `#[\SensitiveParameter]` marks the token and the secret configuration in `GitRunner`, `BareClone`, `GitHubFetchCommand`, and the sync, so traces with arguments do not show them.
  - GitHub objects are denormalized by the Serializer into `src/GitHub/Payload/*`, which M34 can reuse for the webhook payloads and for `GET /repos/{owner}/{repo}`. Any invalid object fails the whole listing.
  - `RepositoryScopeSqlFilter` fails closed for an entity without a rule, so it got rules: a scoped token sees only the installation and the candidate of its repository. A synchronous fetch in a scoped request reads the installation for the suspension check.
  - R2 reads the user with `getUser()`, not `#[CurrentUser]`: argument resolution runs before `#[IsGranted]`, and a token caller got the wrong 403 message (`ActorKindTest`).
  - Cross-tenant: no new `/api/v1` route. R3 with another tenant's candidate answers 404, R2 omits another tenant's candidates, and the sync leaves another tenant's rows unchanged. `/github/installed` reads no tenant data; its test proves that it needs a session.
  - Test seams: the `when@test` monolog handler `records` (a `TestHandler`), read by `GitHubFetchSecretTest`. `GitHubResponses` serves the listing by user token, and answers the token request with 201 only for an App JWT and a body for one repository with `contents: read`, else with GitHub's 422. `GIT_TRACE` in the test environment records the argv of every git process. `/_e2e/sign-in/{login}?githubUserId=<id>` signs in a GitHub user that the test stored.

They follow the documented shapes on docs.github.com, with values chosen for the tests: `user-installations.json` the installation object of `GET /user/installations`, with the documented enterprise account in its third entry; the repository listings the repository object of `GET /user/installations/{id}/repositories`; `installation-token.json` the 201 example of the token endpoint; `installation-token-invalid.json` and `server-error.json` the documented error body.

- **Risks discovered:**
  - If GitHub refuses the repository listing of a suspended installation, every listing of that user fails, and the candidates stop refreshing. Nothing is removed.
  - A failed dispatch of `DeleteCloneJob` after the access update leaves the clone on disk, and nothing queues the job again. The Doctrine transport uses the same database, so such a failure usually means that the database is down.
  - Sign-in time grows with one GitHub request per 100 repositories per installation.
  - The browser connect of a GitHub candidate is not tested end to end: the e2e site has no GitHub stand-in, so a clone there would call the real GitHub.
