## Report: F29 Symbols for Python, Go, and Rust

- **Status:** Done (awaiting merge).
- **Summary:**
  - The Symbols menu, exact-range symbol anchors, re-anchoring by FQN, quick open, and the sticky scope lines work for `.py`, `.go`, and `.rs` files.
  - Each language is a grammar package, a query file, and a row in `symbols/src/languages.ts`. PHP gets the three ids in `TreeSitterSymbolExtractor::LANGUAGES`, and the V9 ETag is `v3`.
  - The engine gets two capture roles: `@parent` names the parent of a Go method or a Rust `impl` member inside the enclosing container, and `@as` names the trait of a Rust trait impl, which gives `<S as Tr>::m()`.
  - A language row can have no doc comment (Python), and can end the doc comment at a blank line (Go).

- **Decisions and deviations:**
  - At the merge, `make front` on main failed: `symbols/node_modules` existed from F27, so the new grammar packages were not installed. `make front` now depends on `symbols/node_modules/.package-lock.json`, which installs again when `symbols/package-lock.json` is newer. A separate fix commit on main.
  - `@parent` joins the FQN of the enclosing container, so `impl S` in module `a` has the parent `a::S`, which is the FQN of the struct. Opaque node types still apply to a declaration with `@parent`, so an `impl` in a function body is skipped.
  - The trait capture is `@as`, because `@trait` is a `SymbolKind`. The role captures `name`, `parent`, and `as` are exported as `ROLES`.
  - A run of whitespace in the `@parent` and `@as` text becomes one space.
  - `LanguageRow.docComment` is nullable (Python), and the new `docCommentAdjacent` makes a blank line end the doc comment (Go). The D57 table says "the adjacent `//` block".
  - Go has no wrappers. A `type` or `const` declaration with one spec is captured whole through anchored patterns, so its doc comment precedes it. A spec in a group starts at its name. A wrapper would give every spec of a group the range of the group.
  - Go: an embedded field is no property, and a field of an anonymous struct type inside a field is skipped (`field_declaration` is opaque). Interface type elements are no symbols. A method whose receiver is not a plain, pointer, or generic type name has no symbol.
  - Rust: an `impl` member is a method, a constant, or a type. The scope names only methods, but a `const` or `type` in an `impl` would otherwise be a top-level symbol with a wrong FQN. A trait has methods with and without a body, constants, and associated types.
  - Rust: a plain, generic, or reference type of an `impl` gives the type name. Another type keeps its text, for example `<[T] as Tr>::x()` and `<i32 as Tr>::y()` with the parent `[T]` and `i32`.
  - Rust: `block` is opaque, so an item in a function body, a closure, or a constant initializer is skipped. Fields of tuple structs and of enum variants are no properties. `mod a;` is a module symbol. A function signature in an `extern` block is a function.
  - Python: a method is a function directly in a class body, decorated or not.
  - `tests/ui/support/fakeReview.ts` lists the three languages, so the mocked V9 follows the specs. This is test support, not front-end code.
  - No change to `BlobSymbols`, `IndexSql`, the schemas, or the front end was needed.
  - `docs/plan/F04-code-navigation.md` line 13 still names `docs/backlog/more-languages.md` in a code span. Plan F files are outside this scope. The reports S07, S14, and F27 name the file as history and stay as they are.
- **Follow-ups and new ideas:**
  - Python: `@typing.overload` stubs, and a `@property` with its `@x.setter`, share an FQN, so neither becomes a symbol anchor. Go has the same with several `init()` functions.
  - Python: a function in an `if` or `try` of a class body is kind `function` with the class as its parent.
  - Rust: an attribute above the doc comment, `#[a]` then `///`, is outside the range, because the attribute walk stops at the comment.
  - A trailing comment at the end of the line before a declaration joins its doc comment run. This applies to every language of the service.
  - Rust: an `impl` of a path type, such as `impl a::S`, keeps the path in `parentFqn`, so its members do not group with the struct.
