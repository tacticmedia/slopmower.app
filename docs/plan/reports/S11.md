## Report: S11 GitHub duplicates

- **Status:** Done (awaiting commit).
- **Evidence check:**
  - Rename-collision rule twice: held. `src/GitHub/InstallationSync.php` `record()` built a lower-case name map of the connected repositories; `src/Webhook/Handler/RepositoryHandler.php` `record()` called `RepositoryRepository::findGitHubByName()`. Both ran under the `github-repositories:<tenantId>` lock.
  - `payload()` helper twice: held. `InstallationSync::payload()` threw `GitHubRequestFailed`, `GitHubWebhookConsumer::payload()` threw `UnrecoverableMessageHandlingException`. Each guarded a non-array and checked `instanceof` after `DenormalizerInterface::denormalize()`.
  - Tenant lock block in four classes: held. `Application\ConnectGitHubRepository::connect()` (lock, no transaction), `InstallationSync::sync()` and `RepositoryHandler::__invoke()` (lock, `wrapInTransaction()`), `InstallationHandler::locked()` (lock, `wrapInTransaction()`, `TenantRepository::lockActive()`). All four use `ConnectGitHubRepository::lockKey()`.
  - `InstallationSync` writes entities and calls `FetchRepository`: held. Out of scope (S05).
- **Summary:**
  - `RepositoryRepository::nameAfterRename()` is the one rename-collision rule. A changed name that another GitHub repository of the tenant holds, in any case, keeps the current name. Both callers run it under the tenant lock.
  - Both `payload()` helpers go. `denormalize()` already returns the typed object (`@return ($type is class-string<TObject> ? TObject : mixed)`) and throws a `SerializerException` for a non-array, which a probe in the `php` container confirmed for `null`, a string, an integer, a boolean, and a list. `InstallationSync::sync()` catches `SerializerException` next to `GitHubRequestFailed` and `HttpClientException`. `GitHubWebhookConsumer::tenantJobs()` maps it to the same `UnrecoverableMessageHandlingException` "The GitHub delivery has an object of an unexpected shape."
  - The tenant lock block stays. See "Deviations and skips".

- **Deviations and skips:**
  - `payload()`: no copy is kept, instead of one. The framework call does the job of both, so a shared helper would be a wrapper that forwards one call.
  - Tenant lock block: skipped, because no shape is both smaller and more direct. A lock-only service (`run(TenantId, Closure)`, the only shape that keeps the transaction boundaries of `connect()`, which must not run in `wrapInTransaction()`) has about 36 lines in a sketch and removes about 34. A static helper on `ConnectGitHubRepository` that takes the `LockFactory` saves about 10 lines, but it puts two nested closures on each call and hides the standard `symfony/lock` idiom behind a static method with a service argument. The key is already one function, `ConnectGitHubRepository::lockKey()`.
  - `RepositoryHandler` class docblock: the rule text moved to `nameAfterRename()`, and the lock line went, because the code names the lock.
- **Follow-ups:**
  - S05: when the GitHub handlers move to `App\MessageHandler`, `RepositoryHandler::__invoke()` can share `InstallationHandler::locked()` only with its `TenantRepository::lockActive()` check, which skips a tenant that is being deleted. That is a behaviour change for Jan to accept.
