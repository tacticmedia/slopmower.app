- **Facts for Jan's install** (from the trial install of v0.14.0 on 2026-10-07, before the revert):
  - The Composer plugin `symfony/ai-mate-composer-plugin` has `"plugin-optional": true`. When it is not in `config.allow-plugins`, `make composer` (non-interactive, `exec -T`) skips it silently, and only an interactive Composer run asks. Without the entry, Composer never runs `mate discover` after an install.
  - The plugin runs `mate discover --composer` only when `mate/extensions.php` exists. Before `mate init`, it prints "Run vendor/bin/mate init".
  - `mate init` asks for the agent command and writes it to `mate.invocation` and to the generated instructions. Without a TTY, for example through `make mate`, it takes the default `vendor/bin/mate`.
  - `mate init` writes `mate/config.php`, `mate/extensions.php`, `mate/.env`, `mate/.gitignore`, `mate/AGENT_INSTRUCTIONS.md`, `mate/src/`, adds `extra.ai-mate` and the `Mate\` autoload-dev path to `composer.json`, and appends a managed block between `<!-- BEGIN AI_MATE_INSTRUCTIONS -->` markers to `AGENTS.md`. `CLAUDE.md` already imports `AGENTS.md` without Mate's markers, so Mate leaves it alone.
  - `mate discover` copies skills to `.agents/skills/mate-<name>/` and links them from `.claude/skills/`. Mate recommends committing both and does not git-ignore them.
  - Defaults: `ai_mate_monolog.log_dir` is `%mate.root_dir%/var/log`, and `ai_mate_symfony.profiler_dir` is `%mate.root_dir%/var/cache/dev/profiler`. In the container, `mate.root_dir` is `/app`, which matches `config/packages/monolog.yaml` and the `dev` profiler.
  - `php-cs-fixer` scans the whole project, so it scans `mate/`. PHPStan does not scan `mate/`.
