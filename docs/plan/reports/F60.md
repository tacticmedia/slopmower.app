- **Decisions and deviations:**
  - The E2E tests needed no change: they find the title links in `[data-testid="request-list"]`, which is now the `ul`, and each request they open waits for the user or the agent, so it is on Open.
  - `IssueTrackedByIcon` exists in `@primer/octicons-react` 19.38.0, so every icon of the scope is used as named. Open and Closed use `IssueOpenedIcon` and `CheckIcon`, "Agent prompts" `TerminalIcon`, the kebab `KebabHorizontalIcon`.
  - `TurnLabel` had no consumer but the list, and the list shows only its "Waiting for you" variant, so `WaitingForYouLabel` (`data-testid="waiting-for-you"`) replaces it, with the pattern of `PlanToApproveLabel`.
  - The status icon is a `span` with `role="img"`, the status text as `aria-label` and `title`, `data-testid="status-label"`, and `data-status`. The colours come from `data-status` selectors with the colours of the `StatusLabel` variants.
  - The title link is not dimmed for an untitled request: F58 dims only the heading of the request page.
  - The meta line uses `ClaimedBy`, so it reads "claimed by <agent> for <age>", as decision D6 shows the claim age.
  - Open and Closed are router links with `aria-current="true"` and a `CounterLabel`. "Waiting for you" is a toggle `Button` with `aria-pressed`. Open removes `awaiting` from the URL, Closed sets `awaiting=none`, and "Waiting for you" sets `awaiting=user`. Other `awaiting` values in the URL list the Open tab.
  - The menu buttons keep the names "Status", "Filters", and "Sort", as on GitHub. The menus show the selection with check marks, and the rows show the effect of each filter.
  - "Sort": "Recently updated" (`updated`) removes `sort` from the URL. The loader always sends `sort`, because the Q1 default is `created`.
  - The empty state is "No request matches these filters." with the link "Clear the filters", which drops every URL parameter, so the list opens on Open with the default sort.
  - The header is the top bar of the bordered box, with `data-testid="request-filters"`, so the "New request" comment box opens inside it, as `AskForPlan` expects. "Pending drafts" stays above the list, now above the box. The heading "Requests" and its total are gone; the `ul` has the label "Requests".
  - The list loader reads D1 on every load, not only with a filter: Open and Closed always filter, so a reply draft can name a request that the page does not list.
  - The three dialogs keep their content. Their open buttons moved into `ReviewActionsMenu`, which mounts one dialog at a time, so each opening starts with a new fetcher and no old error. "Carry over requests" and "Close review" mount only while the review is open.
  - The header order is "Quick open", "Agent prompts", "Finish your review", "Review actions". The title block has `min-width: 0` and `overflow-wrap: anywhere`, so a long review title wraps at 390 px.
  - The fake answers Q1 `sort` with the Q1 orders and a 422 for an unknown value. No existing test depended on the row order.
  - `docs/user/connect-your-agent.md` and `README.md` named "Copy prompt" in the review header, so they now name "Agent prompts" first. D27 and flow 8 of the architecture name "Review actions".
- **Follow-ups and new ideas:**
  - Show the active filters above a filtered list, like the GitHub link "Clear current search query, filters, and sorts". Today only the menus, the rows, and the URL show them.
  - "Connect your agent" in the overlay has the muted label style of `CopyField.module.css`, so it does not look like a link.
  - Request numbers per review (`#N`) stay a candidate, as the scope says.
