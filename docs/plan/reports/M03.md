- **Deviations and decisions:**
  - The event classes have the suffix `Event`, for example `ReviewClosedEvent`, because the error `App\Domain\Error\ReviewClosed` exists and the M04 deciders use both.
  - `DomainEvent` has a static `type()`, `toPayload(): array<string, mixed>`, and a static `fromPayload(array): self`. `EventType::eventClass()` maps a type to its class, `EventType::decode()` decodes a payload, and `EventType::fromString()` reads the stored `type` column. The round-trip test checks that both directions agree.
  - A corrupt stored payload throws `CorruptPayload`, an `\UnexpectedValueException` and not a `DomainError`. REST and MCP then answer `internal_error`, not `invalid_input`, because the client sent nothing wrong. Event constructors and value objects throw `InvalidInput`. `PayloadReader::build()` converts it to `CorruptPayload` and puts the path in front of each field, for example `anchor.range.endLine`.
  - `PayloadJson` defines the stored JSON: `JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE`, and `{}` for the empty payload of `request.claimed`. The fixtures are its exact output. PostgreSQL `jsonb` reorders keys, so only the encoder output is fixed, not the stored text.
  - `TimeCodec` writes RFC 3339 in UTC with `Z` and second precision. It converts to UTC and drops fractions of a second. It reads only that form. `encode()` throws `\LogicException` for a time that `decode()` cannot read, for example a UTC year above 9999. The write then fails, and the log never holds an unreadable event.
  - `request.opened` writes its keys in the order of the architecture example: `batchId`, `body`, `anchor`. The other payloads follow the order of the architecture table. A stored anchor has all 7 keys, with null for an empty value. A stored actor has `kind`, `userId`, and `agentName`.
  - `RecordedEvent.type` comes from the event. The constructor requires `requestId` for `request.*` events and refuses it for the others, as architecture section 3 says. A violation is a server fault or a corrupt row, so it throws `\LogicException`, not `InvalidInput`. `commit.unlinked` therefore carries its request in the payload.
  - `WontDoReason` is a value object in `App\Domain\Request`: `trim()`, then at least 20 characters by `mb_strlen`. It keeps the text as written. `RequestWontDoEvent` holds it, so M04 gets the rule from the same class.
  - `UniqueIds` checks the ID lists. `requestIds` of `commit.linked`, `commit.found`, and `batch.submitted` must be non-empty and unique. `commentIds` of `batch.submitted` must be unique and may be empty. A duplicate is named by its index, for example `requestIds.2`.
  - `review.started` holds `ref` as a `RefName`. `title`, `body`, `note`, `summary`, and `subject` are plain strings without length or blank checks. `subject` may be empty, because git allows an empty commit message.
  - The D37 docblock is on `PayloadReader`. PHP has no namespace docblock, and the php-cs-fixer rule `phpdoc_to_comment` turns a free-standing docblock into a comment.
  - Tests beyond the acceptance list: `RecordedEventTest`, `ActorCodecTest`, and `TimeCodecTest` cover code that no acceptance test reaches. The second `WontDoReasonTest` case pins the boundary and the kept text. The `EventType` data set of `EnumContractTest` checks the list against `common.schema.json`, as the milestone requires.

- **Follow-ups and open questions:**
  - M04: the event classes do not check a non-blank `body` or a non-blank required `note` (specs README section 2.2, mcp.md semantic checks). The decider or the input layer must.
  - M06 and M07: the `review_event.requestIds` column needs the request IDs of each event. Nothing derives them yet. A `requestIds()` method on `DomainEvent` would fit if M06 needs it.
  - M07: write payloads with `PayloadJson::encode()`. Read them with `EventType::fromString($type)->decode(PayloadJson::decode($json))`, or with `decode()` of the array that the Doctrine `json` type returns. Read actors with `ActorCodec::decode(PayloadReader::of($array))` if the actor is stored as JSON.
  - The `system` actor of `commit.found` is not enforced. The writer, `ResolvePendingCommitLinks` of M16, sets it.
  - The limit of 50 request IDs is an input rule and is not enforced in `CommitLinkedEvent`.
  - 5e29e3c removed `EventType::fromString()` and the unknown event type case of `PayloadStrictnessTest`.
- **Risks discovered:**
  - Readers apply the domain rules again, for example the 20-character reason and the anchor rules. A rule on stored data may only get looser. A tighter rule makes old events unreadable.
  - An older release reads newer events with new fields, but not a new event type or a new enum value, for example a new `SymbolKind`. A rollback after such a write makes those reads fail loudly.
