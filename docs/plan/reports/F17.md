## Report: F17 Project Mate tools

- **Status:** Done (awaiting merge). One commit `feat: F17 project mate tools` on the worktree branch, based on `32e6524`.
- **Summary:**
  - `Mate\ReviewTools` in `mate/src` has two read-only Mate tools on the dev database. `review-list` lists reviews newest first, with the filters `repository` (case-insensitive substring), `state` (`ReviewState`, so the schema has the enum `open`, `closed`), and `limit`. `review-events` reads the event log of one review in `seq` order, with the filters `request` (jsonb containment on `request_ids`), `afterSeq`, `type` (prefix through `STARTS_WITH`), and `limit`.
  - IDs go out as upper-case ULIDs, times as `TimeCodec` UTC, payloads and `requestIds` decoded. Both tools return `ResponseEncoder::encodeUntrusted()`. A bad ULID or a `limit` out of range gives `InvalidInput`, which `tools:call` prints as an error.
  - `mate/config.php` loads `.env` (`mate.env_file`) and registers a `Doctrine\DBAL\Connection` from `DriverManager::getConnection()` with the `DsnParser` result of `DATABASE_URL`.
  - `mate/INSTRUCTIONS.md`, named in `extra.ai-mate.instructions`, describes the tools. `make mate c=discover` put it into `mate/AGENT_INSTRUCTIONS.md`.
  - PHPStan analyses `mate/src`. php-cs-fixer checks `mate/` except the generated `mate/extensions.php`.

- **Decisions and deviations:**
  - The `Connection` argument is the expression `service('mate.dsn_parser').parse(env('DATABASE_URL'))`. A service cannot pass the result of one factory call to another without it. Mate compiles its `ContainerBuilder` without dumping it, so the expression reads `mate.dsn_parser` from the container at run time, and that service must be public. `env()` resolves only when a tool builds the connection, so a missing `DATABASE_URL` breaks only these two tools, not Mate.
  - `DsnParser` maps the scheme `postgresql` to `pdo_pgsql`, as DoctrineBundle does. Checked against DBAL 4.5.0: the query string becomes the `serverVersion` and `charset` parameters.
  - `state` is typed `?ReviewState`. Mate's schema generator and argument caster support backed enums, so the schema lists the values and a wrong value fails before the query.
  - A `limit` out of range is refused, not clamped, so a caller never gets a shorter page than asked without notice.
  - Side effect of `mate.env_file`: `symfony-dotenv-check` measures the Mate process. Before, 13 keys were `declared_not_resolved_in_this_process`. Now the `.env` keys are `file`, and the three keys that `.env.dev` overrides (`APP_TENANT_DATA_DIR`, `MERCURE_URL`, `MERCURE_PUBLIC_URL`) are `ambient_override`, because the Mate process holds the `.env` value. `mate/INSTRUCTIONS.md` states this, so an agent does not take it for a shell override.
  - The developer guide does not name Mate, so it is unchanged. The `make mate` row of the plan README names the project tools.
  - `make mate c=discover` left the `AI_MATE_INSTRUCTIONS` block of `AGENTS.md` unchanged: Mate lists only vendor extensions there, not `_custom`.
  - PHPStan analyses `mate/src` only, as the scope says. `mate/config.php` is checked by php-cs-fixer and by the manual Mate run.
