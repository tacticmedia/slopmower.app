## Report: F16 Carry over on an open review

- **Status:** Done (awaiting merge). One commit `feat: F16 carry over on an open review` on the worktree branch, based on `32e6524`.
- **Summary:**
  - The review header has "Carry over requests" while the review is open. It opens a Primer `Dialog` that loads V2 `?state=all` through a fetcher on the new data route `repositories/:repositoryId/carry-over-sources`, and lists the other reviews of the repository in V2 order, newest first, with "(closed)" after a closed one.
  - "Carry over" posts the intent `carry_over` with `fromReviewId` to the review route action, which calls V15 and returns the `CarryOverResult` or an `ActionResult` error. On success the dialog shows `CarryOverPanel` with a "Done" button, and the router revalidates the review data, so the Requests tab lists the copies. An error shows with `ActionErrorMessage`.
  - `CarryOverPanel` moved to `assets/review/` with its own CSS module. It links to the review from `result.reviewId`, and only when `linkToReview` is true.

- **Decisions and deviations:**
  - The sources load from a data-only route `repositories/:repositoryId/carry-over-sources`, as `diff-sides` does, because the loader needs the repository ID and not the review ID. Its loader returns `{error}` instead of throwing, as `treeLoader` does, so a failed load shows in the dialog and not in the route error boundary. The `repositoryLoader` route is not reused for the same reason.
  - The dialog renders its fetchers in an inner component that mounts only while the dialog is open, as `CreateTokenDialog` does, so each opening loads the list again and starts with the form.
  - The newest other review is selected at first. A carry-over changes nothing in the source review and is idempotent, so no empty choice is necessary.
  - The footer has "Carry over" only while there is a review to choose. While the list loads, the dialog shows "Loading the reviews"; a failed load shows its message.
  - `CarryOverPanel` takes `{result, linkToReview}` and links to `result.reviewId`. `StartedWithCarryOver` is now `{carryOver}`, so `repositoryAction` no longer returns the review that only the panel link used. The start form wraps the panel in `.carryOverResult` for its top margin, so the panel has no margin of its own in the dialog.
  - The user doc also lists the outcome "Carried earlier", which a repeated carry-over into an open review shows.
  - The 422 test uses the same-repository message of `CarryOverController`. A 422 for a closed target is real too, but the revalidation after the action then shows the closed review, and the layout removes the dialog with the review actions.
