- **Deviations and decisions:**
  - `Cache-Control` is `no-store, private`, not `no-store`. `ResponseHeaderBag` adds `private` to every value without `public`, `private`, or `s-maxage`. The listener also sets the session listener's `Symfony-Session-NoAutoCacheControl` header on every `/api/v1` response, so the session listener changes no API cache header, also not the ETag responses of M12.
  - Path IDs use `#[MapEntity(id: 'repositoryId')]`: DoctrineBundle's `EntityValueResolver` is the `ValueResolverInterface` that the plan asks for. Its `find()` runs through the SQL filter. A miss or a malformed ID (`ConversionException`) gives `NotFoundHttpException`, which the listener maps to 404 with a fixed message, so no class name leaks.
  - R2 has `priority: 1` on its route, so `/api/v1/repositories/candidates` matches before `/api/v1/repositories/{repositoryId}`.
  - Query and body type errors: the listener answers 400 for a violation without a constraint only when the failed DTO implements the marker `QueryInput`. A body value of the wrong type stays 422, because docs/specs section 4 names 400 only for unparsable JSON and query values. An unknown enum value in a query, for example `source=svn`, is a type error and gives 400.
  - Query booleans go through `#[MapQueryString]` with `filter_bool`, which also accepts `yes`, `no`, `on`, and `off`. That is relaxed validation, which section 8 allows.
  - `ApiExceptionListener` runs at priority -1: after the firewall exception listener at 1, and after `ErrorListener::logKernelException` at 0, which logs the 500. `framework.exceptions` logs `DomainError` at `info`, because the framework logs every non-HTTP exception as CRITICAL "Uncaught PHP Exception". HTTP exceptions keep the framework level, ERROR.
  - Error messages: a domain error keeps its message. A 403 keeps the exception message, so the actor-kind message of M14 reaches the client. 404, 405, 413, and 415 have fixed messages. A 401 never reaches the listener: the `api` entry point answers it; the 405 message has the form of `error.invalid-input-method.json`. Unparsable JSON gives the violation `{field: "", message: "The body is not valid JSON."}`.
  - `InvalidInput` drops the `": "` prefix for a violation of the whole input (field `""`), so the message reads "Invalid input. The body is not valid JSON." instead of "Invalid input. : ...".
  - `ApiCsrfListener` runs on `kernel.controller_arguments` at priority 0, for unsafe methods on the firewall named `api`. M14's stateless `api_bearer` firewall is out of its scope without a change. The double-submit header name is the value of the manager's stateless token, which is the cookie name.
  - `ApiBodySizeListener` runs at -10050, between `#[IsGranted]` at -10000 and the payload mapping at -10100. It checks `Content-Length` first, then the body length.
  - Spec change by the orchestrator: the `Cursor` `maxLength` in `common.schema.json` is 2048, was 512. Cursors are opaque, and the cursor of a long non-ASCII name exceeded 512 characters (523 for 110 times U+6F22).
  - R2 applies `q` and `includeConnected` inside the scan, through a name predicate of `LocalRepositoryDiscovery::list()`. The 1,000-item limit and `truncated` count the filtered candidates, so a match past position 1,000 is found.
  - `name` and `cursor` of R1 and `q` of R2 carry `#[Assert\Charset('UTF-8')]`, so a non-UTF-8 value gives 422 instead of a PostgreSQL error and 500.
  - `RepositoryPage` has no normalizer: the framework `ObjectNormalizer` emits its public `items` and `nextCursor`. `RepositoryController` has the class-level prefix `#[Route('/api/v1/repositories', name: 'api_repository_')]`; the routes are unchanged.
  - `Cursor`: base64url JSON `{"k": sortKey, "f": hash}`. The hash is the first 16 hex characters of the SHA-256 of the JSON of the declared filters. Unknown query parameters are not in the hash, because section 2.1 ignores them. The R1 sort key is `[LOWER(name) as PostgreSQL computes it, id]`, so the keyset condition and the cursor use one collation. An input cursor has no length limit.
  - R1 `name`: a valid ULID is an ID, a value with `/` is a GitHub name compared case-insensitively, any other value is a local name compared exactly (section 7).
  - `openReviewCount` is the count of open reviews from a correlated subquery. M12 names it, but the schema needs the property now and the `review` table exists.
  - R3 with `source: github` gives 404 `not_found`, because no GitHub candidate exists. `RepositoryNormalizer` throws a `LogicException` for a GitHub repository: the entity has no installation ID, owner, `private`, or `htmlUrl` yet.
  - The DQL of R1 and R4 lives in `RepositoryQuery`, the read-side query that the plan names, not in `RepositoryRepository` as the `make-entity` skill suggests. It joins reviews and pages, and MCP reuses it in M15.
  - `UtcTimeNormalizer` normalizes only, through `TimeCodec::encode()`. Input times keep the framework `DateTimeNormalizer`, so M14's `expiresAt` can carry an offset.
  - `CrossTenantCases`: the path of a case equals the route path, and the inventory test checks the method and path. A `{name}` placeholder takes the other tenant's ID and expects 404. Each case declares the `status` and `schema` of its success response. A case without a placeholder expects that response, validated with `assertApiResponse()`, with none of the other tenant's IDs (tenant, user, repository) in it. R3 is such a case: the other tenant connected `billing` first.
  - `public` is dropped only on `ConnectLocalRepository`. M11 consumes none of `CommitAvailability`, `RequestCommands`, `ReviewCommands`, and `EventLogQuery`, so they stay public.
  - One test beyond the acceptance list: "A malformed cursor gives 422", our own rule.
  - Skills: `make-controller` scaffolded both controllers (`make:controller --no-template`, `--invokable`), then rewritten to the plan's routes. The four listeners were written by hand in the `make-listener` shape: `#[AsEventListener]` on the class, the priority in the attribute, checked with `debug:event-dispatcher kernel.controller_arguments`. `make-entity` did not apply: no mapping change. `services`, `configuration`, `components`, `discover`, `make-test`, and `cli-conventions` were followed.
