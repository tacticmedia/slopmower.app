## Report: S04 One DBAL type per typed ID

- **Status:** Done (awaiting commit).
- **Evidence check:**
  - Conversions: 41 `Ulid::fromString()` and `X::fromString($ulid->toBase32())` pairs in `src/Entity` and `src/Repository`, plus `RequestQuery` with its private `ulid()`, `ReviewQuery`, `RepositoryQuery`, `UpdatesQuery`, `MeController`, `ActorNormalizer`, `AccountController`, `DraftController`, `TokenController`, `DeletionHandler`, `CommandExecutor`, `RequestProjector`, `RequestCommands`, `ReviewCommands`, `RebuildProjectionsCommand`, and `BlobSymbols`. Held: 67 `Ulid::fromString()` calls in `src` outside `BundledSchemas`.
  - Registration: DoctrineBundle 3.3.2 registers a type by class only. `#[AsDbalType]` takes one name, and `ConnectionFactory::initializeTypes()` calls `Type::addType($name, $class)`, so DBAL 4.5 makes one instance per name with no constructor arguments. `Type::lookupName($this)` gives an instance its registered name. So one class serves many names when the name is the value class.
  - ORM resolution, checked in `vendor/doctrine/orm` 3.7.2: `#[ORM\Id]` and association join columns take the type of the target ID column (`PersisterHelper::getTypeOfColumn()`). `find()` and `findBy()` convert criteria with the mapped field type, and the identity map hashes an ID through `__toString()`, which is base32 for both `Ulid` and `Identifier`. DQL parameters infer `STRING` for an object (`ParameterTypeInferer`), so they need the type name. `IDENTITY()` returns the raw string. `ArrayParameterType` lists do not convert through a custom type.
  - SQL filters: `TenantContext` passes `toRfc4122()` strings to `SQLFilter::setParameter()`, which `getParameter()` quotes as strings. No change needed.
  - `#[MapEntity]` finds by the raw route string and maps a `ConversionException` to 404. The ID type must take a ULID string, as `UlidType` does. `ApiErrorModelTest` covers `not-a-ulid` with 404.
- **Summary:** `IdentifierType` serves all ten ID classes, and `StringValueType` serves `CommitSha`, `BlobSha`, and `RepoPath`. `config/packages/doctrine.yaml` registers each under the value class name, so a column maps as `#[ORM\Column(type: TenantId::class)]`, and each type reads its class with `Type::lookupName()`. Entities and `ActorEmbeddable` store and return typed IDs. Repositories, queries, and controllers call `find()` and `findBy()` with typed IDs and bind DQL parameters as `setParameter('id', $id, RequestId::class)`. `Ulid::fromString()` in `src` goes from 67 to 2. `src` loses 1 file and 77 lines. The SQL column types are unchanged.

- **Deviations and skips:**
  - One generic type per kind, not one class per ID class. Ten subclasses of an abstract base would add about 140 lines. The cost is the `types` list in `doctrine.yaml` and the type name convention.
  - The SHA and path types are folded into `StringValueType`, as S01 suggested. `getSQLDeclaration()` keeps `VARCHAR(64)` for the SHAs and `TEXT` for paths with a `match` on the class.
  - `IdentifierType::convertToDatabaseValue()` refuses an ID of another class. `UlidType` took any `Ulid`. No production call passes another class.
  - Kept on `ulid`: the `id` of `GitHubCandidate`, `GitHubInstallation`, and `ViewedFile`, which have no ID class, and the cursor keys that `Cursor::decode()` returns as `Ulid`.
  - `RequestQuery::commentCounts()` and `ReviewQuery::views()` key their counts by the RFC 4122 string that `IDENTITY()` returns, so they convert nothing. `RequestQuery::commitViews()` selects `other.id`, which the type converts.
  - `UpdatesQuery::requestsInOrder()` uses `RequestId::fromString($id)->toRfc4122()` for its list parameter.
  - Phpstan-doctrine has no descriptor for the new types, so `TenantRepository::activeQuery()` declares `array{id: mixed}`.
  - A session stored before this change holds a `User` with `Ulid` properties. Its unserialize throws a `TypeError`, which `ContextListener::safelyUnserialize()` does not catch (it catches `\ErrorException` only), so such a browser gets 500 until its session goes. Bearer tokens are not affected. No migration clears the sessions: no production data exists.
