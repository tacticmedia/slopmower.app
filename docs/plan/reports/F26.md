- **Decisions and deviations:**
  - `git blame` takes `--` after `--end-of-options` as a revision, so the path follows the revision without `--`. Checked with git 2.55 on the host and 2.47 in the container.
  - No mailmap: in a bare clone, git blame reads `HEAD:.mailmap`, and a fetch moves `HEAD`, so the cached answer of a pinned commit would change. `-c mailmap.blob= -c mailmap.file=` turns it off; `authorName` is the name that the commit records, as `commitDetails` (`--no-mailmap`) reads it.
  - The ignore list goes on standard input with `--ignore-revs-file /dev/stdin`: `--ignore-rev` refuses a SHA that the clone lacks, the file form accepts it, and no temporary file exists. git cuts a line at `#` and refuses other text, so the server keeps only full SHAs.
  - The 422 for a file that is not renderable comes after the ETag check, so a 304 never reads the blob.
  - Every row is 20 px, also a one-line block; GitHub makes a one-line block 30 px. The blocks have no avatars, no links, and no "Blame prior to change": Candidates.
  - The age scale counts the days since the author time against the current time, as GitHub does: 9 under 7 days, then 8, 7, 6, 5, 4, 3, 2, 1 under 14, 21, 45, 90, 120, 180, 270, 450 days, else 0.
  - Found during F26: F25 had no shell route for `/reviews/{id}/tree/{path}`. F31 fixed it on `main` before this merge, and F26 adds `shell_review_blame` the same way.
- **Follow-ups and new ideas:**
  - A server-side cache of V17, if a long history makes git blame slow. The browser caches by ETag.
