- **Decisions and deviations:**
  - The scope lists "a cross-tenant review ID gives 404" under `DeclarationsTest`. The inventory case `api_review_declarations` proves it through `CrossTenantRouteInventoryTest`, so `DeclarationsTest` has no copy.
  - The scope's UI acceptance test "opens its declaration with the range selected" is "opens its declaration line", after Jan's decision that a jump selects only `declarationStartLine`.
  - The scope's migration indexes `symbol (tenant_id, repository_id, fqn)`. The index holds `fqn_sha256` instead, as `indexed_file` holds `path_sha256`, because a btree entry of a long multibyte FQN exceeds 2,704 bytes. The lookup matches the hash, then the FQN.
  - `column` counts Unicode characters of the line, from 1. The token events count UTF-16 code units, and `characterColumn()` converts. php-parser counts bytes, and `PhpSymbolExtractor` converts.
  - The click sends the start of the token. A token covers one name or a name segment, so the start falls inside the name.
  - A candidate carries its symbol kinds (`Index\Reference`), because a class and a constant share the FQN format. Each reference is a fallback chain: the first FQN with a declaration of a matching kind wins. This is PHP's run-time fallback for unqualified functions and constants.
  - `self` and `static` resolve to the enclosing class-like, and `parent` to the parent class. A `use` import, also in a group use, resolves by its type. `X::class` gives the class.
  - A typed name resolves with the namespace and imports at the end of the file, so a file with several namespaces uses its last one. A leading `\` makes it fully qualified, and a leading `namespace\`, in any case, makes it relative, as PHP and the click path do. A file that does not parse gives no targets, also for a fully qualified name.
  - Errors as V9: the extension check (422) runs before the clone check (409), the path check (404) after it. A position outside the file gives `items: []`. FQNs compare exactly, also in case. The list is not paginated.
  - `IndexSql::declarations()` drops FQNs that are not valid UTF-8 before the query, because PostgreSQL refuses such a parameter.
  - Cmd or Ctrl count on every platform. A Ctrl-click on macOS opens the context menu and sends no click, so no platform check is needed.
  - The lookup runs through a resource route `declarations` and `useFetcher`, as the Symbols menu does. Its `shouldRevalidate` is false, because a revalidation after a comment would deliver the result again and jump again. A result for a file that the reviewer left meanwhile is dropped.
  - "Go to declaration" is first in the file header, also on a closed review, because navigation reads only. The menu shows each target's path and declaration line.
  - `PhpSymbolExtractor` has two consumers now, so the developer guide's complexity ledger no longer lists it as a single-consumer candidate.
  - The menu is not covered by a UI test, because the scope's acceptance tests do not name it. The probe above checked it.
