- **Decisions and deviations:**
  - The stored `request.opened` payload always has the key `carriedFrom`, null for a request that is not carried, as `batchId`. The three existing event fixtures got the key, and a separate unit case decodes a payload without it.
  - The new requests and first comments are one transaction, without a `batchId` and without `batch.submitted`: "one batch" in the scope is read as one transaction. The actor of both events is the caller.
  - `RequestCommentedEvent` of the first comment is built directly, not through `RequestDecider` with `Reply`, because the request does not exist before the transaction. The decider still decides each `request.opened`, with the review-closed and anchor-commit guards.
  - A closed target review is 422 `invalid_input` with field `""`, as the scope says, not 409 `review_closed`. A target closed between the check and the transaction still gets 409 from the decider. A closed source review is allowed: the call only reads it.
  - "Same kind": a `line` or `range` anchor takes `line` for one located line and `range` for more, because the anchor rules require it. A `symbol` anchor whose FQN no longer names exactly one symbol, for example after a rename (F13), carries as `line` or `range` at the located range. A capture that fails at a located path, for example a file that is no longer UTF-8, gives the file anchor with the snapshot comment.
  - "Orphaned with an existing path": an orphaned `Location` has no path, so the new `Locator::mappedPath()` reuses the rename mapping of `locate()`. `ambiguous` after a deleted file has no path and is not carried.
  - The snapshot comment fences the old lines with a fence longer than any backtick run in them, and cuts them at 60,000 characters, below the 65,536 of a comment body.
  - The source and copy statuses are read again under the tenant lock: a source claimed or carried by another call after the git work is not copied.
  - `CarryOverController` holds the logic, because V15 is its only caller (plan README "Responses" and "Reads"). It checks the clone once, when a carriable source has an anchor, so V15 answers 409 `repository_unavailable` before it locates anything.
  - If V15 fails after V1, the start form says "The review started, but the carry-over failed: ...", because the review exists.
  - The result item holds the whole source `RequestSummary`, so the panel shows its summary and location without a second read.
