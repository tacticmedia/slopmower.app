- **Decisions and deviations:**
  - The notice is in the page flow above the content, not fixed. It covers no control, so the E2E suite needs no change. A fixed banner can cover a button that a test or a user clicks.
  - The notice has the `hidden` attribute, and the script removes it unless the dismissal is stored. So a returning visitor sees no flash of the notice. Without JavaScript, no notice shows; the app needs JavaScript, and the privacy policy lists the cookies. When `localStorage` throws, the notice shows on each page, and "Got it" hides it on that page.
  - The notice uses the light colors of the docs pages and has no dark mode, because the sign-in and docs pages are light. In the app with a dark system theme, it shows as a light strip until "Got it".
  - The markup and the script are in `templates/base.html.twig` itself, as the scope says, not in a partial.
  - The footer of the sign-in page is a `nav` with the label "Legal and support", outside `main`. The docs layout and the app shell do not link the pages, because the scope names only the sign-in page and the docs index.
  - Cookie and storage names come from the code: `PHPSESSID` (no `framework.session.name`, PHP default, `cookie_lifetime` 0), `csrf-token_<random>` with `__Host-` over HTTPS (`SameOriginCsrfTokenManager` deletes it in the response), `mercureAuthorization` (bundle default for protocol 0.x, `exp` of 3600 s in `MercureAuthorizeController`, renewed by `useLiveRevalidation.ts`), and `slopmower.treeCollapsed`, `slopmower.wrap`, `slopmower.tree-width` (Primer `widthStorageKey`).
  - Minimum age 16, in the privacy policy and the terms: the highest age of digital consent in the GDPR, which also covers COPPA. The legal review can change it.
  - Legal bases: contract for the service data, legitimate interests for rate limit counters and server logs. No use relies on consent.
  - Personal data of other people in connected repositories, for example commit authors: the user is the controller and Slopmower the processor. This follows from the service, but the scope does not name it.
  - Server logs "can contain IP addresses": the dev Caddyfile writes access logs, and the production web server is not specified.
  - The terms contain only the governing law, the Marketplace billing (D65), and plain rules of use. They state that the service is given "as it is", but have no limitation of liability, indemnity, or warranty clause, because the brief asks for no boilerplate beyond the scope list.
  - Changes of a policy: the date at the top of the page changes. No mechanism tells users of a material change, and Slopmower stores no email address of its users, so the notice is a `TO CONFIRM` marker.
  - The statements on check runs, plans, and retention follow the code of F41, F42, and F44 on `main` (D64, D65, D66), checked after the rebase. The statement "logs never contain your code or the text of agent calls" depends on F45, which removes the PostgreSQL row values from database errors and merges before F43. In `prod`, no handler takes the channel `mcp` (D66).
  - "Encrypted storage" and "HTTPS" come from architecture section 12 and the "For Jan" item "Production instance". They carry `TO CONFIRM` markers until the production instance proves them.
  - Transfers: an adequacy decision or the standard contractual clauses. The legal review confirms the mechanism for GitHub and for the hosting provider.
