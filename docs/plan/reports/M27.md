- **Summary:** Q2 accepts `kind: "symbol"` with `symbol.fqn`. `AnchorFactory` reads the symbol table through `BlobSymbols::of()`, so a blob that the index job has not reached also works; the symbol's range with its doc comment becomes `anchor.range` (D7), and an unknown or ambiguous FQN gives 422 on `anchor.symbol.fqn`. The gutter "+" of a selection now has an accessible name and opens the box with Enter or Space.

- **Deviations:**
  - The "Symbols" menu is a Primer `SelectPanel`, not an `ActionMenu`. The plan asks for a filterable menu, and Primer's guidelines say to use `SelectPanel` for a filterable list and to keep inputs out of an `ActionMenu`. It keeps the plan's behaviour: a button in the file header, groups, a filter, keyboard navigation, single choice. Architecture section 8 now names `SelectPanel`.
  - Keyboard access to the gutter "+", by the orchestrator's decision (M21 follow-up): listeners on the code view's container (`containerRef`) name the "+" on `focusin` ("Comment on line N" or "Comment on lines A to B") and open the box on Enter or Space. The library's gutter, its pointer gestures, and its DOM stay unchanged (D31). The M21 test that pinned the old result and the architecture row changed with it.
- **Decisions:**
  - Server: a symbol anchor with a `range` gives 422 on `anchor.range`, without a `symbol` 422 on `anchor.symbol` (AnchorInput schema). The FQN lookup needs the clone, so its 422 comes after the renderable and UTF-8 checks. An unsupported language and a parse error give "No symbol of the file has this FQN."
  - Exact-range match: a range matches only when exactly one symbol matches, so the properties of `public int $a, $b;` or a one-line constructor with a promoted property stay a range. A symbol whose FQN occurs more than once in the file, for example two conditional `home()` functions, never matches, because Q2 rejects it as ambiguous; the menu shows such items disabled with "the FQN is not unique" (orchestrator review). The match applies to every comment range: the gutter "+" (click, drag, keyboard) and "Comment on lines". A one-line property or constant commented through "+" therefore becomes a symbol anchor. Before V9 answers, a range stays a range.
  - The menu filters by the short name (`round()`, `$taxRate`, `SCALE`), not by the FQN: every member FQN contains the class name, so an FQN filter matched the whole class. A class-like heads its own group, other top-level symbols go to "Functions and constants". At most 200 matches render, with a notice; the large fixture file has 3,497 symbols, and a grouped `SelectPanel` does not virtualize.
  - V9 loads through a loader-only `symbols` route and `useFetcher().load()`, as the tree does, so the file renders without waiting for a parse. The route's `shouldRevalidate` returns false, because the symbols of a blob at the review commit never change and every comment and live update revalidates active fetchers. The menu and the match load only on an open review and a renderable file.
  - Every new-comment box shows its label as a visible header ("Comment on lines 3 to 4", "Comment on file", "Comment on method <FQN>"), so a symbol anchor is visible before the submit. The header is `aria-hidden`, because the text field carries the same name.
  - Skills: `make-test` (Vitest for pure TypeScript, `WebTestCase` for Q2, Panther for the browser) and `cli-conventions` (`make` targets, `docker compose exec php bin/phpunit --filter`) applied. `services`: one new constructor dependency, autowired. `components`, `configuration`, `discover`: no infrastructure, no configuration value, no new package.
