- **By-ID fetch over `file://` (git 2.47.3):** a commit on a branch, and a commit that only a ref outside `refs/heads` reaches, both land in `refs/holistic-review/commits/<sha>`. One unknown SHA fails the whole fetch with exit 128, as the plan says. The fetch then runs one SHA per command.
- **Decisions:**
  - Git gets only `PATH` from the environment. Without that, `DATABASE_URL`, `APP_SECRET`, and the other Dotenv values reach git. `GIT_CEILING_DIRECTORIES` stops git from walking up into `/app/.git`.
  - `fetch --no-auto-maintenance --prune --end-of-options <url> <refspecs>`. The pending-SHA fetch adds `--no-tags` and does not force, so a pin never moves.
  - `BareClone::init()` takes the object format from `ls-remote`, so SHA-256 sources work.
  - `fetch()` has one time budget for all its git commands, from `ClockInterface`.
  - `GitReader::resolvePrefix()` matches object IDs only, never a ref named like a prefix.
  - The services that tests need before a caller exists are public in `when@test` of `config/services.yaml`.
- **For M09 (must handle, with evidence from the review):**
  - **file:// percent-decoding.** Git 2.47.3 percent-decodes the path of a `file://` URL. A directory named `sub%2f..%2ftarget` fetches `target`, which can be another tenant's clone under `/srv/tenants`, because the realpath check runs on the literal name. Build local URLs in one place and escape `%` as `%25`, or `rawurlencode()` each segment. Checked: `x%252f..%252ftarget` fetches the directory itself. Apply the same to `GitRepositoryBuilder::fileUrl()`.
  - **safe.directory.** For `file://`, git removes the repository-local variables from the environment of the local `git-upload-pack`. So neither `-c safe.directory` nor `GIT_CONFIG_COUNT` reaches it, and `GIT_CONFIG_GLOBAL=/dev/null` removes the global channel. A source owned by another uid (normal on a Linux host, invisible on macOS) fails with "dubious ownership". Working options: a server-owned global config file with only the `safe.directory` entries passed as `GIT_CONFIG_GLOBAL` for local-source commands, or `--upload-pack="git -c safe.directory=<quoted path> -c safe.directory=<quoted path>/.git upload-pack"`. Architecture section 4 and specs section 7 describe `-c safe.directory`, which does not work.
- **Follow-ups:**
  - A timeout stops only git: the source-side processes of a local fetch keep running. Not in the plan.
  - A 40-hex SHA in a SHA-256 clone resolves as an abbreviation.
  - An empty SHA-256 source gets a SHA-1 clone. The first fetch after its first commit fails. Delete the clone and clone again.
  - A detached HEAD in a local source gives `defaultBranch = null`. M09 keeps the stored value.
  - `hasCommit()` is true for an annotated tag's SHA, and a pending SHA of a tree or blob still gets a pin ref. M09 checks the object type.
  - `blobAt()` and `readBlob()` load the whole blob. M12 needs a bounded read for large files.
  - Tests do not cover the per-command time budget or the per-request timeout of the long-lived process.
