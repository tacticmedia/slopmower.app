## Report: M08 Git plumbing

- **Status:** Done (awaiting commit).
- **Summary:** `src/Git` holds the git primitives. `GitRunner` runs every git command with an argument array, a fixed environment, a timeout, and secrets only in `GIT_CONFIG_*` variables, redacted from messages and logs. `BareClone` inits and fetches heads, tags, and pending SHAs, then sets `HEAD`. `PinRefs` writes, deletes, and lists the D26 pins. `GitReader` resolves refs and prefixes, lists trees, and reads blobs through one `cat-file --batch -Z` process per clone. `RepositoryLock` gives the `fetch:<repositoryId>` lock on PostgreSQL advisory locks. `TenantDataPaths` builds the clone path from typed IDs.

- **Deviations and decisions:**
  - `LOCK_DSN="postgresql+advisory://app:!ChangeMe!@database:5432/app"`: `StoreFactory` maps it to `DoctrineDbalPostgreSqlStore` (symfony-docs `lock.rst`). Only `.env` sets it, so `test` and `e2e` lock in the `app` database. Keys contain repository ULIDs, so they do not collide.
  - The primitives take the clone path as `string $gitDir`. Callers get it from `TenantDataPaths::clonePath()`. Tests use temporary directories.
  - `BareClone` does not take the lock. The caller holds `RepositoryLock`: the M09 fetch and clone handlers, the M31 deletion job. M09 polls `acquire(false)`, so the lock must sit at the caller. `RepositoryLock::create()` returns a `LockInterface` without TTL.
  - The functional tests construct the services with `new`. The container removes the unused private `App\Git` services until M09 uses them, and the test container cannot reach removed services. No container mocking. `RepositoryLockTest` gives each holder its own store from `LOCK_DSN`, so each holder has its own database session. In one session the store's in-memory guard decides, not PostgreSQL.
  - `cat-file --batch -Z`: NUL delimits names and records, so a path with LF works. `GitReader` keeps one process per clone and stops them in `reset()` (`kernel.reset`, between requests and messages). Each read has a 60 s timeout: the process timeout is moved forward before each read. Reads go through `Process::getIterator()`, which yields from the Process output buffer. `waitUntil()` lost output: its first `updateStatus()` reads into that buffer, not into the callback.
  - `GitRunner` always sets `GIT_CONFIG_COUNT`, `0` without secrets, so an inherited value never applies. It logs failures at `debug` with the redacted message and throws `GitFailed`.
  - `BareClone::init()` creates the missing parent directories: `git --git-dir=<path> init` does not. `fetch()` has one timeout for all its git commands, because M09 passes the remaining time. After the deadline it throws `GitFailed` before it starts git, and a timed-out pending fetch does not start the one-SHA fallback. `HEAD` changes only when `ls-remote --symref` names a branch under `refs/heads/`.
  - `resolveCommit` and `resolvePrefix` map every rev-parse failure to `CommitNotFound`. `resolvePrefix` also refuses a result that does not start with the prefix, because a ref with the prefix as its name wins in rev-parse.
  - A refused pin move is the `GitFailed` of `update-ref`; the ref stays. Idempotence: after a failed `update-ref`, `create` reads the pin and accepts the same commit.
  - `TreeEntry::$path` is a raw string, not a `RepoPath` (M02 risk: git paths that are not valid UTF-8). `ObjectType` is a backed enum of the four git object types.
  - `RefInjectionTest` calls `GitReader::resolveCommit()`, which takes only a `RefName`. The refusal happens in `RefName::fromString()`. A git run would answer the missing clone with `CommitNotFound` instead.
  - `NoProcessOutsideGitTest` also flags the PHP process functions and backticks.
  - `symfony/filesystem` is now a direct requirement, because `src` uses `Path` and `Filesystem`.
- **Versions:** `symfony/lock` v8.1.8, the latest. `symfony/filesystem` v8.1.6, already installed, the latest.
- **Follow-ups and open questions:**
  - An ambiguous prefix gives `CommitNotFound` today. M09 (`CommitAvailability`) and M12 need `invalid_input`: detect `is ambiguous` in the rev-parse error under `LC_ALL=C`.
  - `lsTree` of a path that is not a directory throws `GitFailed`. M11 or M12 maps it to `not_found`. `blobAt` already returns null for a missing path.
  - M09 adds a parameter to `BareClone::fetch()` for global arguments before the subcommand: `-c safe.directory=<realpath> -c safe.directory=<realpath>/.git`. `$secretConfiguration` cannot carry two `safe.directory` values, and it puts them in the environment.
  - M16 adds `GitReader::commitInfo()`. M31 deletes the clone under `RepositoryLock`.
- **Risks discovered:**
  - `symfony/process` passes the PHP environment to git, including the Dotenv values such as `DATABASE_URL`. Git ignores them, and no message prints them.
  - The by-ID fetch depends on protocol v2, where a want can be any object. `file://` with git 2.47.3 uses it. GitHub must allow it for reachable commits; M33 confirms it.
