## Report: F100 Known issue: the npm and Composer audit gates are red

- **Status:** Done 2026-11-03.
- **Summary:**
  - Composer: `phpunit/phpunit` 13.4.2 to 13.4.6 with its dependencies (`phpunit/php-code-coverage` 14.5.1, `sebastian/git-state` 1.1.0, `theseer/tokenizer` removed), and `symfony/mime` 8.1.7 to 8.1.10. `bump-after-update` raised the constraints to `^13.4.6` and `~8.1.10`. `composer audit --locked` finds nothing.
  - npm: `vite` 8.3.5 and `vitest` 5.1.0, exact pins, and `fast-uri` through `npm audit fix`.
  - D104, chosen by Jan on 2026-11-03: the QA workflow runs `npm audit --omit=dev --audit-level=moderate` and `npm audit --audit-level=high` in place of `npm audit`. `npm audit --prefix symbols` and `composer audit` stay strict.
- **Accepted findings:**
  - `deepmerge` 4.3.1, low, GHSA-gcqx-w48m-w2h4, run time through `@primer/react` 38.40.0. Every version from 4.2.0 is affected, and 4.3.1 is the latest.
  - `glob` 13.0.6 and `minimatch` 10.2.6, moderate, GHSA-3g3m-2fjr-6pw4 and GHSA-g3hv-75wg-m249, build time through `@sentry/bundler-plugins` 11.10.0, which requires `glob` `^13.0.6`. The fix is `glob` 14.0.2 with `minimatch` 11. The plugin is off without `SENTRY_PROJECT` (`vite.config.ts`), and our configuration gives it the pattern `public/build*/**/*.map`.
- **Files:** `composer.json`, `composer.lock`, `package.json`, `package-lock.json`, `.github/workflows/qa.yml`, `docs/architecture.md` (D104, the CI paragraph), `README.md` (the CI paragraph), `docs/plan/README.md` (the verified versions), `tests/Unit/Conventions/QaWorkflowTest.php`.
- **Tests:** `QaWorkflowTest` "Each gate step of qa.yml runs a make target or npm audit, never a command of its own" accepts the two D104 commands and no longer a plain `npm audit`.
- **Verification:**
  - `composer audit --locked`: no advisories. `npm audit --omit=dev --audit-level=moderate` and `npm audit --audit-level=high`: exit 0. With the old `package-lock.json`, `npm audit --audit-level=high` exits 1 on `vite` 8.3.1, so the rule still fails on a high finding.
  - `make cs`, `make stan`, `make lint`: clean. `make test`: PHPUnit 13.4.6, 2218 tests, 21878 assertions. `make front`: 108 tests. `make ui`: 204 passed. `make e2e`: 14 tests, 326 assertions. `make prod-check`: pass.
  - `make act`: the job succeeds, with `composer audit`, both `npm audit` runs, `npm audit --prefix symbols`, and `make prod-check`. A first run failed in `QaWorkflowTest`, which allowed only a plain `npm audit`.
- **Deviations:**
  - The scope named an override to a fixed version that the package accepts. No such version exists for `glob` (`^13`), so no override. A scoped override to `glob` 14 was offered to Jan and not chosen: the upload path of F99 cannot be tested here without Sentry credentials.
  - The change of `qa.yml` waited for Jan's choice of the rule, because it relaxes a CI gate.
  - `README.md` and the CI paragraph of `docs/architecture.md` were changed, which the scope did not list: they named plain `npm audit`.
- **Follow-ups and open questions:** drop the D104 levels for build-time findings when `@sentry/bundler-plugins` requires `glob` 14.
- **Risks discovered:** a moderate build-time finding no longer fails CI. A high one still does.
