- **Choice:** a read that several callers share, REST and MCP (D37) or a controller and a use case, is one method of an `Application\Query` service. A read with one caller stays in its controller. This is the S02 rule "logic with no other consumer stays in the controller" applied to reads, and it is the more direct shape: the reader of an endpoint with one caller finds its read in its action. The other choice, every read in `Application\Query`, adds a query method with one caller for each of Q9, V5, V6, V9, V11, A1, D1, and T1, against that rule, and moves code away from the only action that runs it. Exception: `ReviewQuery::get()` has one caller and stays, because it builds `ReviewView` with the same `select()` and `views()` as `list()`. A move gives the controller a copy of the count query, or makes `views()` public.
- **Summary:** Q9 stays in `CommitDiffController`, which takes the clone path from `FetchRepository::readyClonePath()` instead of `cloneReady()` and `TenantDataPaths`, and passes the located path and the anchor path to `files()` instead of a closure. The server sort stays. `RepositoryQuery::candidates()` moves into `RepositoryCandidateController`, so `RepositoryQuery` drops three constructor parameters. `RequestQuery::batchSubmission()` moves into `DraftController::submit()`, which reads the opened requests with `ChangeRequestRepository::findFresh()` and their summaries with `RequestQuery::summaries()`. `BlobStream` moves to `Application\Query`, because V8 and R7 share it. It builds an HTTP response, but the rule is about callers, so it needs no exception. No MCP tool calls a moved method, and no method that an MCP tool calls changed. Rebased on S09, which merged the tools into `McpTools`. The JSON of every response is unchanged.
