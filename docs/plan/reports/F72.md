## Report: F72 Vertical slice flake after the onboarding connect

- **Status:** Done 2026-10-20. One commit `fix: F72 fetcher redirect aborts a running load` on `main`, from `2ee68f2`.
- **Summary:**
  - The cause is a React Router bug, not the test. `startRedirectNavigation()` sets `pendingNavigationController = null` before `startNavigation()`, which would abort it. For a fetcher redirect, that controller belongs to a load that is still running, here the live revalidation that a `repository` update starts after the Connect redirect. The stale load completes after the Start review redirect started, pushes `/repositories/<id>` with the redirect's `PUSH`, and resets the history action to `POP`. The review navigation then completes without a history entry: the review renders under the repository URL. 8.4.0 and 8.5.0 have the same code.
  - `bin/patch-react-router.mjs`, the `postinstall` of `npm ci`, changes the line to `if (isNavigation) pendingNavigationController = null;` in `dist/development` and `dist/production`. It refuses another React Router version, fails when its anchor is not there exactly once, and skips a patched file (D82).
  - All four fetchers that redirect are fixed at once: Start review (`StartReviewForm`, `LatestCommits`), the onboarding Connect, and Delete review. So is a user navigation that is still loading when a fetcher redirects.
- **Files:**
  - Created: `bin/patch-react-router.mjs`, `assets/fetcherRedirect.test.ts`, `docs/plan/reports/F72.md`.
  - Changed: `package.json` (`postinstall`), `package-lock.json` (`hasInstallScript`), `Dockerfile` (the `assets` stage copies the script before `npm ci`), `Makefile` (`ACT_INPUTS`).
  - Docs: `docs/architecture.md` D82, `docs/developer-guide.md` section 5 (patched npm packages), `docs/plan/features.md` For Jan (the upstream report), the scope file (cause and decisions).
  - `tests/E2E/VerticalSliceTest.php` is unchanged. The instrumentation of the investigation is removed.
- **Tests added:** Vitest `FetcherRedirectTest`: "A fetcher redirect during a live revalidation ends at its target in the router and in the history". It builds a router with `UNSAFE_createRouter` and a memory history, holds the repository loader in `revalidate()`, submits a redirecting fetcher action, releases the revalidation before the review loader, and checks `router.state.location` and `history.location`.
- **Verification:**
  - Investigation: an init script logged `pushState`, `replaceState`, `popstate`, `fetch`, and live updates. The first instrumented run failed at a load average of about 8 and showed the sequence of the scope file.
  - Mutation check: after `npm ci --ignore-scripts`, the test fails with `history.location` `/repositories/1`. After `npm ci`, the `postinstall` patches both builds, a second run of the script changes nothing, and the test passes. `npm audit`: 0 vulnerabilities.
  - `VerticalSliceTest`: 30 of 30 passed while `npm run test:ui` ran in a loop on the host, 8 UI runs, all green, at a one-minute load average of 88 to 215.
  - `make check`: green, exit 0, 12m15s with `make act`. cs 0 of 872 files to fix, PHPStan level 8 no errors, unit and functional 2172 tests, 21259 assertions, Vitest 105 tests in 29 files, UI 186 passed, E2E 13 tests, 324 assertions. `make act` ran, because `ACT_INPUTS` changed: the CI `npm ci` and the `assets` stage of `make prod-check` ran `bin/patch-react-router.mjs`, `npm audit` found 0 vulnerabilities, and the job succeeded.
  - Read-only review by a second session: the patch is correct, only the two router copies exist and both are patched, an aborted live revalidation still resolves the `revalidate()` promise, so `useLiveRevalidation` does not hang. Its note on loader redirects during a fetcher's post-action revalidation is in D82.
- **Decisions and deviations:**
  - The fix is in React Router, not in the forms. The React Router docs recommend `<Form>` with `useNavigation` for a submission that creates or deletes and then navigates, but they also document fetcher redirects, and two of the four forms show an error per row of a table. One line fixes every case, also a user navigation.
  - `patch-package` 8.0.1 was tried first and dropped: through `find-yarn-workspace-root` and `micromatch` it depends on `braces` 3.0.3, whose advisory GHSA-vfj7-8cjw-p6xm (high) has no fixed release, so `npm audit` in CI fails.
  - A Vitest test of the patched router replaces the UI spec of the scope. Against the mocked API, the stale load must complete between the redirect start and the review load, so a spec could only fail by timing.
- **Follow-ups and new ideas:** the upstream report under For Jan. When a React Router release fixes the bug, remove the script and the `postinstall`, and keep the test.
