## Report: F97 Request type: change, question, rule

- **Status:** Done 2026-11-03.
- **Summary:**
  - D102: the open set `RequestType` (`change`, `question`, `rule`) is the PHP enum `App\Domain\Request\RequestType`, `$defs/RequestType` of `common.schema.json`, and `REQUEST_TYPES` of `assets/api/types/common.ts`. `Request`, `RequestSummary`, and `Draft` have the required property `type`. Q2, D2, and D3 take the optional input `type`; an unknown value answers 422 through the enum denormalizer, as `DeliveryInput.workspace` does.
  - `Draft.type` is a column (`VARCHAR(255) DEFAULT 'change' NOT NULL`, migration `Version20261103014441`). `Draft::reply()` stores `change`. `Draft::edit()` refuses a type on a reply with 422 on `type`, and null keeps the value, as for `requireApproval`. `CreateDraftInput` refuses a type on a reply with `When` and `IsNull`.
  - `Open`, `RequestOpenedEvent`, and `RequestState` carry `type` with the default `change`. `RequestDecider` passes it from `Open` to the event, and `RequestReducer` from the event to the state. The payload of `request.opened` and `change_request.state` both read a missing `type` as `change`, so stored events and stored rows need no change and no rebuild. No event changes the type.
  - D5 (`decideDraft`) passes the draft type, Q2 passes the input type, and V15 (`CarryOverController`) copies the type of the source. A suggestion is a `change`.
