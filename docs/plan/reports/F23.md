## Report: F23 Focus mode shortcut

- **Status:** Done (awaiting merge). One commit `feat: F23 focus mode shortcut` on the worktree branch, rebased on `1b93ca2`, after F15, F16, F17, and F18. The review items 1 to 5 are applied, see "Decisions and deviations".
- **Summary:**
  - Cmd+Shift+Enter on macOS and Ctrl+Shift+Enter elsewhere turn focus mode on and off while a file is open, also on the error element of a file and while a file of the tree has the focus. The shortcut does nothing in a text field, in a dialog, and on the review page without an open file.
  - `ReviewLayout` holds the handler next to the Escape handler, and `FocusToggle`, the one "Focus" button that the file header (`FileRoute`) and the file error (`CodeRouteError`) render. The button shows the keys with `KeybindingHint` and sets `aria-keyshortcuts`.
  - `assets/layout/modShortcut.ts` is the one way to read Mod: `isPressed()` for the key event, `hintKeys()` for `KeybindingHint`, and `ariaKeyShortcuts()` for `aria-keyshortcuts`. Quick open, the focus shortcut, and the Mod+Enter submit of `CommentBox` use it.

- **Decisions and deviations:**
  - The two "Focus" buttons are one component, `FocusToggle`, in `ReviewLayout.tsx` next to `useFocusMode()`. It keeps the shortcut constant private and gives one place for the hint. The error element renders it only in focus mode, as before.
  - The shortcut handler is its own effect next to the Escape handler. It is registered while a file route matches, not only in focus mode.
  - Review item 1: the handler listens on the window in the capture phase. Primer `TreeView.Item` takes Enter with any modifier, selects the item again, and stops the propagation, so a bubbling listener never ran while a file of the tree had the focus, which is the normal state after a click in the tree. When it toggles, the handler calls `preventDefault()` and `stopPropagation()`, so the tree does not see the key. The `defaultPrevented` check is gone, because nothing runs before a window capture listener.
  - Review item 2: the shortcut does nothing when its target is inside an element with `role="dialog"`. This covers the modal `Dialog`s of the review header ("Close review", "Delete review", "Carry over requests", "Quick open") and the anchored overlays with that role ("Finish your review", "Comment on lines"). Focus mode would hide the review header, which holds the opener of a dialog and its return focus target.
  - Review item 3: `CommentBox` sends on Mod+Enter through `isPressed()` (`{ key: 'Enter', shift: false }`): Cmd+Enter on macOS, Ctrl+Enter elsewhere, never with Shift or Alt. That is what `docs/user/reviewing.md` says. Before, Ctrl+Enter and Cmd+Enter both sent on every platform, also with Shift or Alt. The only UI spec that presses it uses `ControlOrMeta+Enter`, and no E2E test presses it. Architecture flow 4 now says "Ctrl+Enter, or Cmd+Enter on macOS".
  - Review item 4: see the mutations under "Tests added".
  - Review item 5: the developer guide counts 43 UI specs, the number in `tests/ui/` after the rebase.
  - The helper also builds the `KeybindingHint` keys and the `aria-keyshortcuts` value, so the Meta or Control choice is in one place. Quick open keeps its behaviour: "Mod+K", `Meta+K` or `Control+K`.
  - The hint is inside the button, as in Quick open, so it is part of the accessible name. Primer sorts the keys of a chord and leaves "Mod" unsorted, so the hint shows Shift before Command on macOS, the Apple order, and Shift before Control elsewhere.
