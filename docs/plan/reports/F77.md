## Report: F77 Browser error reporting

- **Status:** Done 2026-10-28, `ff4dfac`. The docs in this report's change (privacy policy, versions row, candidates) and a type fix of `SentryReports.spec.ts` came after that commit.
- **Summary:** The SPA reports to Sentry when `SENTRY_DSN_FRONTEND` is set: errors, a trace per page load and navigation, and session replays. The `<body>` attributes carry the DSN, the release, and the environment at run time. The browser follows D67 through the SDK option `dataCollection`, and `beforeSend` drops an `ApiError` below 500. `RouteError` and `actionError()` capture the errors that React Router and the inline error messages would hide. The SPA footer shows `APP_RELEASE`. The server SDK now takes the same release and environment (D86).

- **Follow-ups and open questions:**
  - Candidates "Source maps for browser reports" and "Lazy Sentry in the SPA".
  - For Jan: the privacy policy has the marker `[TO CONFIRM: session recordings without consent]`. The cookie notice and the policy say that Slopmower needs no consent, and session replay of 10% of all sessions is the weakest part of that claim. Setting `replaysSessionSampleRate` to 0 keeps only the replays of sessions with an error.

- **Risks discovered:** a replay records the page URLs without the query filter. No SPA page URL has a filtered parameter today; a new page with `?q=` in its URL would leak the search text into replays.
