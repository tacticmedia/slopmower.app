## Report: F28 RDS authentication

- **Status:** Done 2026-10-08. The commit also holds Jan's `composer require tacticmedia/rds-auth-bundle` with its lock changes. A `composer update` on Jan's instruction removed `tacticmedia/qa-bundle` and `symfony/stimulus-bundle`, an experiment that was still in the lock.
- **Summary:**
  - `tacticmedia/rds-auth-bundle` runs with its defaults and no configuration file. Its middleware wraps the DoctrineBundle connections `default` and `lock`. `AWS_REGION` with `RDS_IAM_USERNAME` or `RDS_SECRET_ARN` selects the mode, and with neither the parameters pass through.
  - The advisory locks of D39 use the new connection `lock` through a `DoctrineDbalPostgreSqlStore` service. `framework.lock` is off, and `LOCK_DSN` is gone.
  - Browser sessions are files under `var/sessions/<environment>` (Jan's decision). `PdoSessionHandler` is gone, and a migration drops `sessions`.
  - `LogOutdatedDatabasePassword` logs `ConfiguredPasswordOutdated` as an error.

    - "In IAM mode, the lock store signs in as the IAM user with a token": `AWS_REGION`, `RDS_IAM_USERNAME=rds_iam_probe`, static AWS credentials, and `sslmode=disable` on `DATABASE_URL`. A lock from the application's `LockFactory` fails with `password authentication failed for user "rds_iam_probe"`. Without `RDS_IAM_USERNAME` the same test fails with "The lock store signed in without the IAM token.", so it is no false positive. A lock store that bypasses DoctrineBundle signs in with the password of the URL and fails this test.

- **Decisions and deviations:**
  - The lock services are in `config/packages/lock.yaml`, not in `config/services.yaml` as the scope says, so that `framework.lock: false` and the store that replaces it are in one file. The file has no `_defaults`, so the `setLogger` call and the `lock` channel tag are explicit, as the framework's `lock.factory.abstract` has them.
  - The `lock` connection has `profiling_collect_backtrace` too, so its queries look like those of `default` in the profiler.
  - `LockStores::inAnotherSession()` builds its connection from `DATABASE_URL` with DBAL's `DsnParser` and the database name of the `lock` connection, because `Connection::getParams()` is `@internal`. With `LOCK_DSN`, the tests took their locks in the database `app`. Now both sides use the test database with its suffix.
  - The E2E tests that read `sessions` were not in the scope. They now read the session files.
  - `.env` lists the three bundle variables empty, so `debug:dotenv` shows the mode switch. Empty and unset both mean pass-through.

- **Risks discovered:**
  - Session expiry is less strict. `PdoSessionHandler` refused a session older than `session.gc_maxlifetime` (1440 s) on read. PHP's file handler removes it only when the session garbage collection runs, with probability 1 in 1000 per session start here. On a quiet instance, an idle session therefore stays valid much longer than 24 minutes. No requirement states an idle timeout.
  - The credential cache is `cache.app`, a filesystem pool under the share directory. In IAM mode it holds a token for 10 minutes. In master-password mode it holds the current master password. On a deployment, keep that directory on the container's own storage, or set `rds_auth.cache_pool` to an APCu pool.
  - A session file is local to one `php` container: the backlog item above.
