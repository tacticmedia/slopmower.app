## Report: F03 Line wrapping

- **Status:** Done (awaiting merge). One commit `feat: F03 line wrapping` on the worktree branch, based on `0c2657f`.
- **Summary:**
  - A "Wrap lines" toggle button with `aria-pressed` sits first in the file header actions of a text file. A check icon shows the pressed state.
  - `usePreference('wrap')` keeps the choice per browser in `localStorage` key `holistic-review.wrap`, inside `try`/`catch`. The default is off.
  - `CodeFile` and `CommitDiff` take an `overflow: 'scroll' | 'wrap'` prop. `CodeFile` adds it to its memoized options, so only a real change calls `setOptions`. The blank-view fix (memoized file object, held annotation changes) is unchanged. `CommitDiff` picks one of two constant option objects.
  - The Changes tab reads the same preference, so one choice serves the code view and the commit diffs.
- **Files:**
  - Front end: new `assets/layout/usePreference.ts`; `assets/code/CodeFile.tsx`, `assets/code/CommitDiff.tsx`, `assets/routes/reviews/FileRoute.tsx`, `assets/routes/requests/RequestChanges.tsx`.
  - Tests: new `tests/ui/LineWrap.spec.ts`; `tests/ui/LargeFile.spec.ts`; `tests/ui/support/codeView.ts` (`wrapToggle()`, `turnOnWrap()`).
  - Docs: `docs/user/reviewing.md` (section "Wrap long lines"), `docs/plan/README.md` (front-end convention for `usePreference.ts`), `docs/developer-guide.md` (section 3.2, `layout/` row), `docs/architecture.md` (section 8, Review row).
- **Tests added:**
  - UI `LineWrap.spec.ts`:
    - "Wrap lines removes horizontal scrolling": line 4 has 400 characters. With wrap off, `[data-code]` in the shadow root scrolls sideways. After the toggle, its `scrollWidth` is at most its `clientWidth`.
    - "A wrapped line takes a comment": click line 3, shift-click the wrapped line 4, press the "+" on line 4, and submit. The Q2 body has the anchor `range` 3 to 4.
    - "The choice applies to the Changes tab and survives a reload": the commit diff scrolls sideways, then the toggle in the file view turns wrap on, then the Changes tab wraps, also after a reload.
  - UI `LargeFile.spec.ts`: "#L3000 is in the viewport and fewer than 300 rows are rendered in wrap mode", next to the existing case with wrap off.
  - Each `LineWrap` test fails when `CodeFile` and `CommitDiff` ignore `overflow` (checked by changing both to `'scroll'`).

- **Decisions and deviations:**
  - The toggle shows only for a text file, as "Comment on lines" and "Symbols". A binary file has nothing to wrap.
  - The pressed state shows as a leading `CheckIcon`. Primer `Button` has no style for `aria-pressed`.
  - Each `AvailableCommit` of the Changes tab calls `usePreference('wrap')`. The tab has no toggle, so the instances need no synchronisation.
  - The comment test selects lines 3 to 4 instead of one line, so the line number click, the shift-click on the wrapped line, the "+" on the wrapped line, and the annotation below it are all proved by one anchor.
  - The `LargeFile` wrap case turns wrap on through the toggle on another file, then opens the deep link, so it covers the initial render in wrap mode. It asserts `pre[data-overflow="wrap"]` in the code host after the navigation. Its lines are short, so it measures the cost of wrap mode, not of wrapped rows. The probes above cover wrapped rows.
  - `config/reference.php` changes on each cache warmup in the container. It is restored before each commit.
- **Review:** the orchestrator's review, applied in the one commit:
  1. `docs/architecture.md` section 8, Review row: the file header lists "Wrap lines" first.
  2. The `LargeFile` wrap case asserts wrap mode after the navigation. It fails when the hook ignores the stored value on the first render (checked by making the read return false). `make check` ran again after the review: exit 0, same counts.
  3. One `type Overflow` is exported from `CodeFile.tsx`. `CommitDiff.tsx` and `FileRoute.tsx` use `import type`, so the lazy chunk stays separate.
