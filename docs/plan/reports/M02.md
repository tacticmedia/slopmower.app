- **Deviations and decisions:**
  - `details()` returns domain values: IDs, enums, `Actor`, `DateTimeImmutable`, `CommitSha`. The shared normalizers of M11 produce the JSON. `InvalidInput` returns plain `{field, message}` arrays.
  - Parsing constructors take an optional `$field`, so callers name the dotted input path of the violation.
  - `SnapshotCapture` splits lines at LF only, as git counts them. Whitespace is ASCII only: NBSP and other Unicode spaces are neither trimmed nor collapsed. The specs do not decide this. Jan should confirm it.
  - Snapshot lines are valid UTF-8 without NUL: normalization replaces each invalid UTF-8 sequence and each NUL with U+FFFD, and `ContentSnapshot` accepts only normalized lines. Otherwise a Latin-1 source file or a NUL after byte 8,000 gave a snapshot that JSON and `jsonb` cannot hold. Architecture section 5.1 now says so. `composer.json` declares `ext-intl` and `ext-mbstring`.
  - `SymbolKind` and `Action` are closed enums. The schema marks them open sets for clients. `SymbolKind::Class_` is the case for `class`.
  - `Location` has the fields of architecture section 3, without the `target` of `location.schema.json`. The M29 normalizer adds `target`.
  - `RepositoryName` for GitHub checks one `/` with non-empty parts, at most 255 characters, and valid UTF-8. The specs give no character set. `equals()` is exact. The case-insensitive lookup belongs to the query.
  - Anchor kinds: `line` needs `startLine == endLine`, `range` needs `endLine > startLine`, and the snapshot `lineCount` equals the range.
  - `RefName` counts its 255-character limit in characters, as JSON Schema does.
  - `DraftId` was missing from the ID row of architecture section 3. It is added.
