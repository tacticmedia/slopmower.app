- **Deviations and decisions:**
  - `mapPath`: `git diff --name-status -M -z` runs only when the anchor path is no longer a blob at the target. Git pairs a rename only for a path that is gone (no `-B`), so the result is the same, and the common case costs one `ls-tree` instead of a diff of the whole tree. A new path that `RepoPath` refuses, or an entry that is not a blob, counts as deleted.
  - `searchOtherFiles` runs `git grep --files-with-matches -z -I -F -e <line>` instead of `-n`: the line numbers are not used, because each candidate is verified with `SnapshotMatcher::exactMatches()` over the whole file. The searched text is the longest snapshot line, trimmed, so a re-indented copy is found, and cut to 1,000 bytes, because an argument above 128 KiB fails to start git. The already searched path is no candidate; the first 20 other files in path order are. One match gives `shifted`, several give `orphaned ambiguous` (F9: we do not guess).
  - An exact match at the same path and lines gives `exact`, not `shifted` as the pseudo-code writes: section 5.3 defines `exact` as same path, same lines, same normalized content, and F11 expects "exact or shifted". The same rule applies to the untouched range and to a symbol found with an equal hash. Two symbols with the FQN at the target count as none, as in M27's `AnchorFactory`, so the line steps run.
  - A target file that is not renderable (symlink, submodule, binary, above 1 MiB) gives `orphaned content_not_found` for a line, range, or symbol anchor. Section 5.4 does not define this case; it is the only use of that reason. A file anchor gives `changed` as section 5.4 says.
  - `excerpt`: the window starts at `range.startLine - context` and is cut to the first 400 lines; a trailing CR is removed (raw lines without line endings). A location without a range, of a file anchor, shows the file from line 1. `excerpt` is null also for an empty file and for a file that is not valid UTF-8, which JSON cannot carry.
  - `location` is null also when the repository has no default-branch head. Q2's 201 response computes it too, because it is a `Request` and the default target applies. Q3 reads the request again after the fetch of `at`, because that fetch can record `commit.found`.
  - `at` errors: an ambiguous prefix gives 422 on `at` (new field parameter of `GitReader::resolvePrefix()` and `CommitAvailability::ensureAvailable()`). An empty `at=` counts as absent. A value of the wrong type in `context` gives 400, as for every query DTO.
  - Cache: primary key `(tenant_id, opened_event_id, target_sha)`, plus `repository_id` with the index `(tenant_id, repository_id)` for M31, and no foreign key. `LocationCacheSql` writes with `ON CONFLICT DO NOTHING`, so a job and a request that compute one key at once do not close the entity manager; reads go through the ORM under both SQL filters. The repository scope rule is `repository_id`.
  - `RecomputeLocationsHandler`: the flag is null when the clone is gone or the head is null; a `Locator` failure is logged at `error` and keeps the flag, so one request does not stop the others. `FetchRepository::removeAccess()`, the only path that deletes the clone of a repository with reviews, queues the job for each review of the repository, so the flags become null. Requests without a `request.opened` event (test rows) are skipped. It flushes before it publishes, and publishes only when a flag changed, without an update ID.
  - `QueueLocationRecompute` dispatches the job for each open review when the head changed, also to or from null, and for the review of a transaction with `request.opened`. Both events follow a commit, so the dispatch runs outside a transaction. In `e2e`, `sync://` runs the recompute inside Q2.
  - `GitFailed` carries the exit code, so `filesContaining()` tells "no match" (exit 1) from a failure. The `--unified=0` diff compares the anchor blob with the target blob, without pathspecs, which would also match the files of a directory that took the name of the file, and adds `--no-textconv` to the M28 flags.
  - `LocationView` (target and location) and `LocationNormalizer` are shared, so M30 can return the `linked_commit` location of Q9. `CodeExcerpt` is normalized in `RequestNormalizer`, because `RepoPath` has no normalizer.

- **Risks discovered:**
  - Each new default-branch head recomputes every request of each open review, because the cache key holds the target SHA. A far, edited move in a repetitive file costs up to about 1 s per request (the `BestWindow` budget of M28).
  - The cache has no eviction; it grows with each head per request until M31 deletes the repository.
  - A missing anchor path runs `diff --name-status -M` over the whole tree; git's rename limit applies to large changes.
