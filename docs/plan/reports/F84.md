- **Summary:**
  - D88: before each GitHub clone and fetch, `ServerClone::checkUserAccess()` reads the permission of the tenant user's login with the installation token of the fetch. `none`, a 404, or a user without a GitHub ID fails it with `lastError` "The GitHub user has no access to this repository". It keeps the clone and the access. The fetch token asks for Metadata: read next to Contents: read.
  - `RepositorySyncHandler::handleFetch()` clears `fetchRequested` once it holds the repository lock, or when the acquisition fails. A request during the wait reuses the waiting job, so at most one job per repository waits for the lock.
  - D89: the `async` transport retries a failed job 5 times, after about 30 s, 2 min, 8 min, 32 min, and 2 h 8 min.
