- **Decisions and deviations:**
  - Item 1, `ReviewCommands` stays. A prototype of the inlined `ReviewController` has 263 lines against 341 for both classes. About 18 of the 78 lines come from the class boundary (file header, duplicate imports, the forwarding calls, the constructor parameter). The rest is compression that applies in place too. Without the service, `CommandFixtures` (22 call sites in 10 classes), `append-events.php`, `InsertAfterDeleteTest`, `DeletionRaceTest`, and `LocationCacheTest` record `review.started`, and `IndexReviewHandlerTest`, `IndexLiveUpdateTest`, `RebuildIndexCommandTest`, `LocatorSymbolAndTargetCasesTest`, and `BrowserFixtures` run the full V1 start, through a 65-line copy of the write path in `tests/Support`. That is about 47 lines more, and those tests then run a copy of production code. The ledger row records it.
  - Item 3: the move is 8 lines smaller (`RequestCommands` and `DraftController` 516 lines before, 508 after). `decideDraft()` reads the fresh request and its links itself, so `DraftController` has no copy of `RequestCommands::state()`. `submit()` takes `CommandExecutor`, `ReviewRepository`, and `CommitLinkRepository` as action arguments, like `create()` does, so the constructor of `DraftController` is unchanged.
  - Item 5: the trait holds only `toString()` and `__toString()`. `RepoPath` and `CommitSha` keep their own `equals()`, and `RepositoryName` its own, because a trait `equals()` would give `BlobSha`, `CommitShaPrefix`, `RefName`, and `WontDoReason` an `equals()` that nothing calls, which S01 deleted. The seven classes are 49 lines shorter, and the trait has 21 lines. The two `equals()` of the same shape stay.
  - Item 6, not done. phpstan-doctrine 2.0.28, the latest release, finds a descriptor through `Type::getTypesMap()` by the DBAL type class, and `IdentifierType` and `StringValueType` serve one value class per type name. Measured:
    - The documented way, a `ReflectionDescriptor` for each of the two classes, gives `Identifier` and `CommitSha|BlobSha|RepoPath`, and `doctrine.columnType` then reports 46 entity properties ("database can contain Identifier but property expects TenantId").
    - A descriptor per type name works: a `DefaultDescriptorRegistry` subclass that answers both type classes by name, a descriptor class, and an override of the `doctrineTypeDescriptorRegistry` service in `phpstan.dist.neon`: 69 lines of PHP and 4 of configuration. It resolves `TenantRepository::activeQuery()` to `Query<null, array{id: TenantId}>` and the rows of `ViewedFileRepository::paths()` to `list<array{path: RepoPath}>`, and finds no mapping error. But PHPStan reports `phpstanApi.class` and `phpstanApi.method` for it, because `DefaultDescriptorRegistry` is outside its backward compatibility promise. The definition of done allows no new ignores, so the change is reverted. The plan README gotchas record the limit. Orchestrator decision: no new PHPStan ignores. Item 6 stays not done and goes to Jan as an upstream request to phpstan-doctrine.
  - Item 7: the builder calls with `'ASC'` drop the argument, which is the ascending default and triggers nothing. The calls with `'DESC'` take `\SortDirection::Descending`, the PHP 8.6 enum that `symfony/polyfill-php86` provides. The `findBy()` and `findOneBy()` order arrays keep their strings: the repository API types them as `array<string, string>` and triggers no deprecation.
  - Item 8: only `ext-mbstring` is added. `symfony/polyfill-mbstring` stays installed as a dependency.
  - Item 9: git runs only when the `HEAD` file names `refs/heads/.invalid`, the reftable stub. Git for every candidate makes `LocalRepositoryDiscoveryTest::testStopsAtTheLimit` 8.0 s instead of 2.1 s for 1,001 candidates. The `HEAD` file check before git stays, because a FIFO named `HEAD` would block git too. Architecture section 13, row "4, Repository sources", said that discovery runs no git. It now says that discovery runs `git symbolic-ref` only for a reftable candidate, so no other candidate costs a process (M09).
  - The commit message is `refactor: F08 code-quality leftovers`, as the orchestrator asked, not the `feat:` of the brief.
- **Follow-ups and new ideas:**
  - For Jan, item 6: an upstream request to phpstan-doctrine for a type descriptor by type name, for one DBAL type class under several names. It would type the DQL results of the ID and value columns without an ignore.
  - `composer.json` could replace `symfony/polyfill-mbstring`, as it does for ctype and iconv, now that `ext-mbstring` is required.
  - The `ulid` DBAL type remains for the cursor keys, which `Http\Cursor` decodes to `Ulid`.
