## Spike

Measured on 2026-11-04 on the host with git 2.56.0, read-only `gh api` calls, and anonymous git over HTTPS, against public repositories. Not checked: a private repository and an installation token.

### 1. Depth-1 fetch, git grep, GitHub size

`symfony/symfony` at `40aab75ccee6732acda77e54deae22010f9a8b3e`, the head of `8.2`: 16,796 files, 26 of them binary by extension.

```sh
gh api repos/symfony/symfony --jq .size
git init -q --bare sym.git && cd sym.git
time git fetch --depth=1 --no-tags https://github.com/symfony/symfony.git 40aab75ccee6732acda77e54deae22010f9a8b3e
du -sk . && git count-objects -vH
time git grep --files-with-matches -z -I -F --no-color -e '<text>' --end-of-options 40aab75ccee6732acda77e54deae22010f9a8b3e
```

| Measure | Value |
|---|---|
| GitHub `size` | 365,633 KB (357 MiB, full history) |
| Fetch time, 5 runs (3 of the head, 2 of fork commits, item 3) | 5.33 to 5.95 s |
| Bare repository after the fetch | 19.4 to 20.3 MiB: one pack of 19.16 MiB, 18,560 objects |
| `git grep` with the flags of `GitReader::filesContaining`, 3 texts, 2 runs each | 0.139 to 0.148 s, for 0, 6, and 199 matching files |

Meaning:

- The fetch is 1/18 of the GitHub `size`. The D32 check of the GitHub `size` before the fetch (D112 Scratch clone) refuses nothing that Server copy accepts, because a full clone is about the GitHub `size`. It is conservative for Pass-through. A tmpfs sized at `repository_size` per worker fills only to the fetch size.
- `filesContaining` costs about 6 s per call at this repository size, nearly all of it the fetch. `Locator::searchOtherFiles` calls it once per anchor whose code left the mapped path. `RecomputeLocationsHandler` and `CheckRunHandler` locate every open request at one head in one job, so a refactoring that moves the code of N anchors costs N fetches of the same commit. The location cache stops a repeat for the same target.

### 2. Commit files entry: binary file and large text change

```sh
gh api repos/microsoft/vscode/commits/94cba4eb314f52fd18b47b72459954fda65302d0   # 3 modified binary icons
gh api repos/symfony/symfony/commits/a78ec8dc777b8ac32b588e0a6227cc327602ca5d    # added woff2, removed 116 KB text
gh api repos/symfony/symfony/commits/61f443c40c87966a24540f01a321c5a333d188b8    # modified 116 KB text
gh api repos/symfony/symfony/commits/4d56fd077ecaed9ed2c3b613d555e9c1dc561586    # pure renames of text files
gh api repos/microsoft/TypeScript/commits/c9e7428bb76f                            # modified 3.15 MB text
```

| Change | `status` | `additions` / `deletions` / `changes` | `patch` |
|---|---|---|---|
| Binary modified: `resources/win32/code.ico`, `code.icns`, `code.png` | `modified` | 0 / 0 / 0 | absent |
| Binary added: `JetBrainsMono.woff2`, 114 KB | `added` | 0 / 0 / 0 | absent |
| Text modified: `fonts.css.twig`, 116 KB with long lines | `modified` | 8 / 3 / 11 | absent |
| Text removed: the same file | `removed` | 0 / 12 / 12 | absent |
| Text modified: `src/compiler/checker.ts`, 3,151,774 bytes | `modified` | 6 / 2 / 8 | present |
| Text pure rename (7 files) | `renamed` | 0 / 0 / 0 | absent |

`git diff-tree -r -M -z --raw --numstat` (the command of `GitReader::changedFiles`) in a local repository: a binary change gives `-` / `-`; a pure rename and a mode change of a binary file also give `-` / `-`; an added empty file and a mode change of a text file give `0` / `0`.

Meaning:

- A missing `patch` does not mark a binary file: GitHub leaves it out for large text diffs too, and keeps the counts.
- Counts 0 / 0 mark a binary change, and also a pure rename, a mode change, or an empty file.
- Rule for `GitHubCodeReader::changedFiles`: null counts (binary) when `additions + deletions = 0` and the old and the new blob SHA differ, with an absent side as the empty blob `e69de29bb2d1d6434b8b29ae775ad8c2e48c5391`. Two different text blobs always differ in a line, so their counts are above 0.
- Difference from git: a pure rename or a mode change of a binary file gets counts 0 / 0, where git gives null. `diffPlaceholder` then shows "The content is unchanged." instead of "Binary file not shown." Both blobs are equal, so no diff is lost.
- Not checked: a submodule change (mode `160000`).

### 3. Head of a pull request from a fork, through the base repository

```sh
gh api 'repos/symfony/symfony/pulls?state=open'   # PR 67824 from malekkadri/symfony, head e8ddf86f
gh api -i repos/symfony/symfony/git/commits/e8ddf86ff5d2f0692902bf20358204d8e26cfb04
```

| Request to `repos/symfony/symfony` | PR head `e8ddf86f` | Fork-only commit `20af7f46` |
|---|---|---|
| `git/commits/{sha}` | 200 | 200 |
| `commits/{sha}` | 200 | 200 |
| `git/trees/{tree}`, `git/blobs/{sha}` | 200, 200 | not run |
| `commits/{10 characters}`, sha media type | full SHA | full SHA |
| GraphQL `blame` at the commit | 133 ranges | not run |
| `git fetch --depth=1` of the SHA from the base URL | works, 5.77 s | works, 5.91 s |

The fork-only commit is the head of branch `as-closure-service-adapters` of `nicolas-grekas/symfony`: `commits/{sha}/pulls` is empty in both repositories, and `compare/8.2...{sha}` is `diverged`, 3 ahead.

Meaning: the base repository serves every commit of its fork network, also one without a pull request. `GitHubCodeReader` needs no fork path, so D112 holds: the fork path of `CheckRunHandler` stays for `clone` only. On Pass-through, `hasCommit`, `ResolvePendingCommitLinks`, and review start also accept a fork-only SHA.

### 4. `commits/{short}` with an ambiguous short SHA

```sh
git clone --bare --filter=tree:0 --no-tags https://github.com/symfony/symfony.git hist.git   # 87,166 commits, 35 MB, 4.9 s
git -C hist.git rev-list --all | sort | cut -c1-8 | uniq -d                                   # 97cafc72; 25 ambiguous 7-character prefixes
gh api -i -H 'Accept: application/vnd.github.sha' repos/symfony/symfony/commits/97cafc72
```

| Request | Answer |
|---|---|
| `commits/97cafc72` (2 commits), sha media type and JSON | 422 `{"message":"No commit found for SHA: 97cafc72"}` |
| `commits/05be7b2` (2 commits) | the same 422 |
| `commits/fffff0a` (no commit) | the same 422 |
| `commits/ffffffffffffffffffffffffffffffffffffff01` (no commit) | the same 422 |
| `commits/0000dfe` (1 commit) | 200, the full SHA |
| `commits/004c1f`, `commits/0602fb` (6 characters, 1 commit) | 200, the full SHA |
| GraphQL `repository { object(expression: "97cafc72") }` | `null`, as for a missing prefix |

Meaning: GitHub does not tell an ambiguous prefix from a missing commit. On Pass-through, the contract of R9, V1, and the MCP tools `get_request` (`at`) and `start_review` (422 `invalid_input` for an ambiguous prefix) cannot hold. A 422 of `commits/{ref}` becomes `commit_not_found`, which has the same HTTP status 422.

### Scope decisions

| Decision | Result |
|---|---|
| `changedFiles` binary rule | Decided: null counts when `additions + deletions = 0` and the blobs differ (item 2). |
| Fork pull-request head through the base repository | Holds (item 3). Fork-only commits also resolve. |
| Ambiguous short SHA | Contradicts the R9, V1, `get_request`, and `start_review` contract on Pass-through (item 4). Proposed: `commit_not_found`, with a note in those four specs. |
| Scratch clone: depth-1 fetch, D32 check of the GitHub `size` | Holds (item 1). One `filesContaining` costs about 6 s. Proposed: one scratch copy per target commit for the anchors of one job or request. |
| `git grep` inside the scratch copy | Holds: 0.14 s (item 1). |
| Blame through GraphQL | Holds: cost 1 (item 5). The cons line of `code-access.md` names up to 3 s for blame. |

- **Decisions and deviations:**
  - The resolver `CodeReaders` is in `src/Application`, not in `src/Git` as "In scope" names it. `ScratchCopies` takes the fetch URL and the secret configuration, and `GitHubCodeReader` checks the GitHub `size` through a closure that `CodeReaders` gives it. So `Git` imports neither `GitHub`, `Application`, nor `Source`, and F116 adds no namespace pair to the three of developer guide section 3.3.
  - `GitHubRepositoryClient` holds the HTTP part of `GitHubCodeReader`: the token, `buffer: false`, the status mapping, and the body reads. It keeps the reader below the 800-line limit.
  - Cache keys: a tree listing is kept by repository, tree-ish (`{commit}` or `{commit}:{dir}`), and recursion, not by tree SHA, because GitHub gives the tree SHA only in the answer. Commit metadata is kept by repository and SHA, so one tenant never sees a cached answer of another repository.
  - The job of a code access change is `CloneRepositoryJob`. For Pass-through it deletes the clone with its pins under the repository lock, sets the clone size to null, and runs the head sync. After every successful clone job, the index job and the location recompute of each open review are queued; a new repository has none.
  - `RepositoryRepository::recordSuccess()` updates only a row whose code access equals the one the sync ran with, so a sync that started before a change does not end the `cloning` of the change.
  - Index job: `RepositoryUnavailable` and `RateLimited` put the index back to `pending` and are rethrown, so Messenger retries and `StalledIndexHandler` takes over after the retries. A `LimitExceeded` of the scratch size check marks the index `failed`, because a retry gives the same answer. The threshold of 500 blob reads is the variable `APP_INDEX_MAX_BLOB_READS`, so the test can lower it.
  - GitHub answers 409 for an empty repository. The reader treats it as missing, so the head sync of an empty repository records no default branch, as Server copy does.
  - A failed read in Q7 (`link_commits`) leaves the link `pending`, as for a commit that the repository lacks.

  - Q3 and `get_request` give `lines`, `before`, and `after` as null when the rebuild fails. Elsewhere a snapshot without text leaves them out, which the schema allows.

- **Follow-ups and new ideas:**
  - Q9 of a commit with files in many directories reads one tree per directory and commit, concurrently. A commit of thousands of files makes that many requests. Candidate: above a number of directories, read the recursive trees of both commits.
  - A process that dies on a fatal error leaves its scratch copies: neither the reset nor the destructor runs. Candidate: delete scratch directories older than a day at worker start.
  - The pool `github_code.cache` is on disk under `APP_SHARE_DIR` and holds file paths, commit messages, and author names and emails for 1 day. The privacy and deployment docs say so.

## Review fixes

1. Content-Length: GitHub leaves it out of an uncached raw blob. `StreamedBlob::$sizeBytes` is nullable. `GitHubCodeReader::openBlob()` takes the size of a listed tree entry, else `Content-Length`, else null, and `BlobStream` leaves the header out for null. R7 in `docs/specs/rest-api.md` says so. The fake sends no `Content-Length` for blobs. Test: "R7 streams the whole blob when GitHub sends no Content-Length, and leaves the header out".
2. Pins after a change back to Server copy: in a clone job, `ServerClone::restorePins()` fetches the commits of every review and every available link of the repository by SHA (`BareClone::fetchCommits()`, a SHA that the source lacks is skipped as for pending SHAs) and pins them. R10 and `code-access.md` say so. Test: "A review commit on no branch stays readable after a switch to Pass-through and back".
3. D88: Q3 and `get_request` rebuild the snapshot text only through `FetchRepository::readyReader()`, else the text is null. Q7 reads through `readyReader()`, and `RepositoryUnavailable` keeps the link pending. Test: "After a D88 check answers none, get_request returns no snapshot text".
4. Index job: only `RateLimited`, and `RepositoryUnavailable` with `fetch_failed` or `cloning`, put the index back to `pending` and are rethrown. `clone_failed` and `removed` mark the index `failed`.
5. The daily `PruneRateLimiterCacheJob` also prunes `github_code.cache`.
6. `recordFailure()` and `recordAccessFailure()` take the code access of the sync, as `recordSuccess()` does. The dispatch failure of `FetchRepository::queueClone()` passes none. Test: "A head sync that fails while a switch to Server copy waits leaves the clone job able to run".
7. GraphQL blame: errors or a null `blame` give `RepositoryUnavailable` with `fetch_failed`, an error of type `RATE_LIMITED` gives `RateLimited` with 60 s, because GraphQL gives no reset time. Test: "A GraphQL blame answer with errors gives 409 repository_unavailable".
8. Q9 lists no parent tree for an added file and no commit tree for a deleted one. `walk()` reads the parent through the cached `tree()`.
9. Every request of `GitHubRepositoryClient` sets `'extra' => ['trace_content' => false]`.
10. A 401 drops the kept token (`InstallationTokenProvider::forget()`) and sends the request once more with a new one: `GitHubRepositoryClient::answered()`, also for the concurrent tree reads.
11. `ResolvePendingCommitLinks` keeps a link pending when its read throws `RepositoryUnavailable` or `RateLimited`, so `synced()` still reaches the later listeners and the index and recompute dispatches.
12. `pathAfter()` maps only `renamed` (old to new) and `removed`. GitHub `compare` uses three dots: it compares from the merge base of the two commits, which is the anchor commit when the target follows it. The fake compares from the merge base too.
13. `Locator::searchOtherFiles()` catches `LimitExceeded` and searches nothing.
14. The size read before a scratch copy goes through `GitHubRepositoryClient::get()`, so a 403 or 5xx fails the copy instead of skipping the D32 check.
15. `ScratchCopies::onTmpfs()` takes the deepest mount that holds the directory. `copy()` deletes its directory on any failure.
16. `GitCodeReader::filesContaining()` passes the text to `git grep -F -f /dev/stdin` through standard input. So no command line, failure message, or log line holds the code line, which is stronger than a redaction of `-e`.
17. `GitHubCodeReader::readBlob()` keeps blobs up to 1 MiB by SHA until `close()`, which `CodeReaders::reset()` calls after each request and message.
18. `CodeAccessSwitchTest` queues the fetch before the switch and runs it after the clone job of the switch. `PassThroughFlowTest` creates a draft, and lowers `APP_INDEX_MAX_BLOB_READS` to 0, so its index job makes one scratch copy that the end of the flow finds deleted.
19. `docs/deployment/README.md`: swap off, or an encrypted swap device.
