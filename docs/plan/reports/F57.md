- **Decisions and deviations:**
  - `config/bundles.php` registers the bundle for `dev` only, not for `dev` and `test` as the scope and the bundle README say. Flex wrote `['dev' => true, 'test' => true]`, and the first `make check` failed in `CrossTenantCoverageTest`: the 11 `qa_screenshots_*` routes were in the `test` router. Cause: the bundle autoconfigures its controller, so it gets the `routing.controller` tag, and the resource `routing.controllers` of `config/routes.yaml` loads its routes in each environment that registers the bundle, whatever the `when@dev` import says. The `test` environment needs nothing of the bundle: the journeys run in Playwright, and no PHP test reads the page. Without `config/routes/qa.yaml`, `debug:router --env=dev` still lists the 11 routes. The file stays as the import that the bundle documents, so the page stays when a later bundle version stops the autoconfiguration. No comment in `config/bundles.php`: Flex writes the file again when it adds a bundle and drops comments. The README gotcha records the reason.
  - The bundle prompt has no blocks, so the override replaces it. It keeps every variable, loop, and condition of the bundle template, and changes only the prose and the instructions.
  - The journeys build the SPA into `var/journeys/build` (`--outDir`), not `var/ui/build`. The Vite configuration empties its output directory, so a shared directory breaks a `make ui` that runs at the same time. Therefore the web server is a new object with its own command, and only its timeout and the reuse setting repeat the UI suite.
  - `timeout: 120_000` for the journeys. Each capture takes 10 full-page screenshots, and the UI default of 30 s leaves no margin at a high host load. `workers` and `expect` come from `playwright.config.ts` unchanged.
  - The screenshot root is the absolute `var/screenshots` of the checkout of the configuration file, so the global setup never empties another tree.
  - `export JOURNEY_PORT ?= 4174` in the `Makefile`, after the include of `.env.make.local`, so the value of that file wins. `playwright.journeys.config.ts` has the same default for a direct `npx playwright test` run.
  - `npm run test:journeys` in `make journeys`, the same pattern as `test:ui` in `make ui`.
  - `.dockerignore` excludes `playwright.journeys.config.ts`, as it excludes `playwright.config.ts`, so the prod image does not get it. `tests/` is excluded already. The prompt override stays in the image: the Twig cache warmer reads `templates/bundles/<Bundle>/` only for a registered bundle, and `prod` does not register `TacticMediaQaBundle`.
  - One journey test per area, except `RequestStages`, which has two: the order of the captures in a test is the order of the journey, and the two tests run in parallel. 35 labels, not about 40: the scope table gives 32, plus "Repository with open reviews" (the repository page is a screen of the SPA that no row named), "Carry over result", "Create token", and "Issued token", minus a separate "legal links" capture. The legal links are in each full-page Settings capture.
  - "Open with a plan required" is a general request: `seedLines()` has no plan option, and `seedGeneral()` has one.
  - The `ReviewRequests` filter capture uses "Waiting for you". The empty filter result uses the path prefix `docs/`.
  - Two fake methods for states that the UI suite does not build: `FakeReview::agentMarksWontDo()` (Q11 of the claiming agent) and `FakeReview::markOrphaned()` (an orphaned default-branch location, `outdated` true).
- **Follow-ups and new ideas:**
  - `bin/prod-check` (F50): the `curl` of `/login` has no `--max-time`, so a request that never answers blocks the script, and `make prod-check` in CI, without a limit. `--max-time 5` would make the 60-second retry loop cover it.
  - Upstream, `tacticmedia/qa-bundle`: the controller service is autoconfigured, so a host with `routing.controllers` in `config/routes.yaml`, as the `symfony/routing` 7.4 recipe writes it, gets the routes in every environment that registers the bundle. Its README tells hosts to register it for `dev` and `test`. Either the README says `dev` only, or `config/services.php` excludes the controller from autoconfiguration and tags it `controller.service_arguments`.
  - The captures show layout defects at 390 px and 768 px, for example the review table of the repository page and the token table of Settings overflow to the right. They are input for Jan's review, not fixed here.
  - Candidate: captures of the typed confirmation dialogs of Settings ("Delete data" of a repository, "Delete account"), which no journey opens.
  - qa-capture resizes the viewport and switches the colour scheme, then takes the screenshot at once, with no wait for the page to settle. The examined captures show the right theme and layout: Primer reads the colour scheme through `useSyncExternalStore`, which renders synchronously. A screen that renders asynchronously after a resize, for example a virtualized list that loads rows, could show a gap. That is a question for qa-capture.
