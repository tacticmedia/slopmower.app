## Report: F34 Double-submit CSRF on Twig forms

- **Status:** Done 2026-10-08.
- **Summary:**
  - An inline script in `templates/base.html.twig` gives each Twig form with the stateless `_csrf_token` placeholder a fresh double-submit token and its cookie on submit, by Symfony's protocol. Every CSRF-checked browser request now sends both proofs, so the downgrade check of `SameOriginCsrfTokenManager` never refuses a form of the app (D61).
  - `ResetCsrfStrategyListener` (F30) and its `LogoutTest` case are deleted. The record that the listener reset does no harm now, also in a session that loses its user without a logout, which the listener did not cover.
- **Files:**
  - Templates: `templates/base.html.twig`.
  - Source: `src/Security/ResetCsrfStrategyListener.php` (deleted).
  - Tests: `tests/E2E/SignInTest.php`; `tests/Functional/Security/LogoutTest.php` (the F30 case removed, the file as before F30).
  - Docs: `docs/architecture.md` (section 4 "CSRF", D61), `docs/developer-guide.md` (`App\Security` count), `docs/plan/features.md` (F30 row, F34 row, the Symfony upstream report), `docs/plan/F30-sign-in-after-sign-out.md` (the decision that rejected this fix), `docs/plan/reports/F30.md`.
- **Tests added:**
  - E2E `SignInTest`: "After the double-submit sign-out, a Twig form with the stateless CSRF placeholder passes the check". The test signs in, signs out with the header button, then adds a form with `_csrf_token=csrf-token` that posts to `/logout` to `/docs`, a Twig page, and submits it with `requestSubmit()`. It reaches `/login`. Without the script the same test fails at the wait for `/login`, and the `e2e` log has "CSRF validation failed: double-submit info was used in a previous request but is now missing."
- **Verification:**
  - `make check`: exit 0, 4m09s.
    - `make cs`: 0 of 748 files to fix.
    - `make stan`: level 8, no errors.
    - `make lint`: container, YAML, Twig, mapping correct, schema in sync.
    - `make test`: OK, 1747 tests, 17298 assertions.
    - `make front`: Vitest 26 files, 86 tests.
    - `make ui`: 126 passed.
    - `make e2e`: OK, 10 tests, 241 assertions.
  - Manual check in the dev app (Chrome, a new isolated context): "Sign in as jan", "Sign out", "Sign in as jan" again ends on `/`, and `/api/v1/me` answers 200 with `jan`. The dev log has "CSRF validation accepted using both origin and double-submit info." for both sign-ins and the sign-out.
- **Decisions and deviations:**
  - The script checks the field value against `^[-_a-zA-Z0-9]{4,22}$` before it replaces it, as Symfony's snippet does: a stateless placeholder is the cookie name, and a session token is longer. It keeps the cookie name in `data-csrf-cookie`, so a second submit of the same form gets a new token too.
  - An inline script, not a Vite entry: the Twig pages load no bundle, and the sign-in page then works without the Vite dev server. The token code repeats `doubleSubmitCsrfToken()` of `assets/api/client.ts` in a few lines.
  - The E2E case adds its form to `/docs` and not to `/login`. The test then waits for a change of URL, and `/docs` has no form of its own. A click on an added button was not actionable on `/docs`, so the case submits with `requestSubmit()`, which dispatches the same `submit` event.
  - `AccountController::delete()` keeps its own handling, so that the 202 response starts no session.
- **Follow-ups:** the Symfony upstream report under "For Jan" in `features.md`, narrowed to the carry-over into the new session at logout.
