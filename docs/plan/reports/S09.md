## Report: S09 MCP tools as thin delegations

- **Status:** Done (awaiting commit).
- **Evidence check:**
  - 12 tool classes, each one line of real work: held in part. `src/Mcp/Tool` had 12 classes with 680 lines, plus `src/Mcp/McpToolRunner.php` with 85 lines. Each tool ran one closure through `McpToolRunner::run()`. Nine closures held one delegation. The six request-command tools repeated the same three lines: parse the request ID, get the actor, call `RequestQuery::commandResult()` with the `RequestCommands` result. `get_updates` and `list_requests` look up the review first, so `not_found` comes before the cursor and filter checks, and `list_reviews` resolves the repository by name first (R1, then V2).
  - Several `#[McpTool]` methods in one class: supported. `symfony/mcp-bundle` 0.14.1 does not use the SDK file discovery. `McpBundle::registerMcpAttributes()` autoconfigures `#[McpTool]` on each method of a service and tags the service `mcp.tool` with that `method`. `McpPass` reflects each tagged method at compile time and adds one `addTool()` call with the handler `[class, method]`. `ReferenceHandler` gets the instance from a service locator by class name. `registry.tools` takes a service ID, a class name, or a namespace prefix (`ElementMatcher`). `Registry::getTools()` keeps the registration order, and `ListToolsHandler` pages 20 tools at a time. Autoconfiguration tags the methods in declaration order, so the method order is the `tools/list` order.
  - `BundledSchemas` stays generated: held. `outputSchema` comes only from the `#[McpTool]` attribute, so it must be a constant expression. `app:schema:bundle` and `BundledSchemasUpToDateTest` are unchanged.
- **Summary:** `App\Mcp\McpTools` holds the 12 tools as `#[McpTool]` methods, in the order of today's `tools/list`, which is alphabetical by tool name. Its private `run()` and `errorJson()` are the error mapping of `McpToolRunner`, unchanged, and `requestCommand()` holds the three lines that the six request-command tools repeated, so each of them is one `RequestCommands` call. The `validate()` step of `list_requests`, its only caller, is inline. The `#[Schema]` pattern constants are private. `config/packages/mcp.yaml` names the class in `registry.tools`. One class, not one per spec area: a split into reads and writes reorders `tools/list`, because the order is class by class and today's order interleaves reads and writes, and it keeps `McpToolRunner` as a shared service or repeats `run()`. `src/Mcp` has 4 files and 3043 lines (12 files and 345 lines fewer). `McpTools.php` has 422 lines, under the 800-line limit.
