## Report: F94 File tree entries as links

- **Status:** Done 2026-11-03.
- **Summary:**
  - A file of the tree renders `TreeView.Item as="a"` with the `href` of the file. A plain click and Enter call `preventDefault()` and navigate in place. A click with Meta, Ctrl, Shift, or Alt, and a middle click return without `preventDefault()`, so the browser opens the link. Ctrl or Cmd with Enter also returns without it; that the browser then opens a tab is not tested. The browser context menu works on the link.
  - `FileTree.module.css` resets the link colour and underline, so a file looks as before.
  - Submodules keep no link.
- **Files:** `assets/review/FileTree.tsx`, `assets/review/FileTree.module.css` (new), `tests/ui/CodeView.spec.ts`, `docs/user/browse-code.md`.
- **Tests:** UI `CodeView`: "A file in the tree is a link: a Ctrl or Meta click and a middle click open a new page, and a click opens it in place". It also checks the colour and that a hover shows no underline.
- **Verification:**
  - `CodeView` and `DirectoryView`: 11 passed. `make front`: 108 tests. `make ui`: 205 passed.
  - Mutation check: with the old `FileTree.tsx`, the test fails on the missing `href`.
- **Deviations:** directories are no links. Primer renders the subtree of an item inside the item element (`TreeView.js`, `children: [container, subTree]`), so a directory link would hold the links of its children and the chevron, and a click on the chevron would follow the link. Jan asked for files. The directory table already has links for directories.
- **Follow-ups and open questions:** none.
- **Risks discovered:** none.
