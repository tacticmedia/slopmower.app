## Report: S03 One cursor helper, one UUID helper

- **Status:** Done (awaiting commit).
- **Evidence check:**
  - Cursors: `RepositoryQuery`, `ReviewQuery`, and `CodeController::listTree()` each had a private `sortKey()` that checked the decoded key, and `RequestQuery` had `afterKey()` for the check and `sortKey()` for the encode side. All four built `nextCursor` by hand with `array_slice()`, `end()`, and `Cursor::encode()`. Held. `UpdatesQuery` uses the integer event number of `specs/README.md` section 5, not `Cursor`. Out of scope.
  - UUID: `DeletionSql`, `EventStoreSql`, `IndexSql`, `LocationCacheSql`, and `RequestQuery` each had a private `uuid()`. Held. The same conversion was also inline as `Ulid::fromString($id->toString())->toRfc4122()` in `ViewedFileSql`, `ReadSnapshotSql`, `TenantContext`, `ReviewQuery`, `TokenBoundSessionStore`, and 12 test sites.
  - Git layer (ledger, added to scope): `CatFileBatch` and `StreamedBlob` each had a header parse, a read loop over the Process iterator, and the 60 s timeout. Held.
- **Summary:** `Http\Cursor` holds keyset pagination: `decode()` takes the sort key types (`int`, `string`, `ulid`, `time`) and returns the converted key, `next()` makes `nextCursor`. The four private key checks and the four hand-built `nextCursor` blocks are gone. The encoded keys and `encode()` are unchanged, so the code issues the same cursor bytes. `Identifier::toRfc4122()` replaces the five `uuid()` helpers and every inline conversion of a typed ID. `CatFileBatch` holds the one header parse, read loop, and timeout, and `StreamedBlob` reads through a `CatFileBatch` of its own. `src` loses 115 lines (191 added, 306 removed), with the same file count.

  - Plan README, Code conventions: "Paginated lists use `Http\Cursor`: `decode()` checks the sort key types, and `next()` makes `nextCursor`." and "Raw SQL, the SQL filter parameters, and DQL list parameters take a typed ID as `Identifier::toRfc4122()`".
- **Deviations and skips:**
  - UUID: one shared function, not the DBAL binding. `UlidType::convertToDatabaseValue()` takes a `Ulid` or a base32 string, not a typed ID. A binding needs a types entry per parameter in every statement, and it cannot cover the positional bulk inserts of `IndexSql` or the DQL `IN` lists, because `ArrayParameterType` has no custom types. `Identifier::toRfc4122()` covers all of them and is smaller. S04 can use it inside the typed DBAL types.
  - Behaviour change for crafted cursors only: V2 now refuses a cursor time outside the years 1 to 9999 with 422 `invalid_input`, as Q1 did. Before, V2 answered 500 `internal_error` for a time below year 1 or beyond the PostgreSQL range, and 200 for a time from year 10000 within it. The code never issues such a cursor, and `specs/README.md` section 5 gives 422 for a bad cursor. A probe test confirmed both answers before and after; it is not committed.
  - `CatFileBatch` drops `-Z`. It only reads blob SHAs since S01, so LF delimits as well as NUL. `CatFileBatch::open()` returns the type and the size from the header. `blob()`, the shared path of `GitReader`, takes the bytes of any object type to keep its process in step. `StreamedBlob::open()` stops its process at the header of an object that is not a blob, as before. `StreamedBlob` keeps the input open until `close()`, which closes it and stops the process.
  - `CodeController::compare()` takes the decoded key as `list<mixed>`: `decode()` returns `list<mixed>`, and PHPStan level 8 refuses it for `array{int, string}`.
  - `UpdatesQuery::requestsInOrder()` keeps `Ulid::fromString($id)->toRfc4122()`: its IDs are strings, not typed IDs.
  - `RequestQuery::ulid()` stays: it feeds `UlidType` parameters like the 41 `Ulid::fromString()` calls of S04.
  - `config/reference.php` is regenerated by the cache warmup with a different Mercure default comment. It is not part of this commit.
- **Follow-ups:**
  - S04: `RequestQuery::ulid()` and the `Ulid::fromString($id->toString()), UlidType::NAME` parameters go with the typed DBAL types. Their `convertToDatabaseValue()` can call `Identifier::toRfc4122()`.
