## Report: M23 Public docs and downloadable skill

- **Status:** Done (awaiting commit).
- **Summary:** `DocsController` serves `docs/user/*.md` at `/docs` and `/docs/<slug>` without sign-in, the raw skill at `/docs/skill/SKILL.md` with a SHA-256 ETag, `public, max-age=300`, and 304, and the files of `docs/specs/schemas/` at `/docs/schemas/v1/<name>.schema.json` as `application/schema+json`. `DocsCatalog` builds every whitelist from a directory listing, so no path comes from input. Templates render the Markdown with `markdown_to_html` of `twig/markdown-extra`; `twig_extra.commonmark` escapes raw HTML and drops unsafe links, the GFM extension renders tables, and the CommonMark extension `DocsLinkRewriter` turns `<slug>.md` links into `/docs/<slug>`. Settings shows the `curl` install command built from `links.skillUrl` with a link to `/docs/connect-your-agent`, and the agent prompt of the review header links to the same page.

- **Deviations and decisions:**
  - `MarkdownSafetyTest` is a functional test (`tests/Functional/Docs`, `KernelTestCase` with a booted kernel), not a unit test. `config:dump-reference twig_extra` has the keys `html_input` and `allow_unsafe_links`, so the configuration is bundle configuration, and only the booted kernel applies it. A unit test would build its own converter and test the library. The test renders `{{ markdown|markdown_to_html }}` through the container's Twig. No factory class: the keys exist.
  - No `MarkdownRenderer` class and no Twig extension: `templates/docs/page.html.twig` calls `markdown_to_html` (skills review; `make-twig-extension` "Before writing one").
  - GFM: twig_extra has no key for tables. `League\CommonMark\Extension\GithubFlavoredMarkdownExtension` gets the tag `twig.markdown.league_extension` in `config/services.yaml`. It is a vendor class, the case where the `services` skill allows a YAML definition. Full GFM, not only tables, so the pages render as on GitHub.
  - `DocsLinkRewriter` is a CommonMark extension, tagged through `#[AutoconfigureTag('twig.markdown.league_extension')]`. On `DocumentParsedEvent` it rewrites a link `<slug>.md`, with an optional `#fragment`, to the route `docs_page` when the slug is in the catalog. Other links stay unchanged. It applies to every `markdown_to_html`; the docs pages are the only user.
  - Firewall `docs` (`^/docs(/|$)`, `security: false`). `TenantContextListener` reads the user on every main request. `UsageTrackingTokenStorage` then marks the session as used, and `AbstractSessionListener` replaces the skill's `Cache-Control` with `max-age=0, must-revalidate, private` (seen in dev and e2e). Without a firewall, nothing reads a token on `/docs`. The pages need no user.
  - `/docs/index` also renders the index: one slug rule for every file, no special case.
  - File name: `assets/settings/skillInstallCommand.ts` and its test, not `skillInstall.ts`. `SkillInstall.tsx` and `skillInstall.ts` differ only in casing. On the case-insensitive macOS file system, `../../settings/SkillInstall` resolved to the `.ts` file and `tsc` failed (TS1261, TS2305).
  - The two documentation links are plain `href="/docs/connect-your-agent"` (a full page load to the Twig page), like the literal `/api/v1` paths of the client. The install command uses `links.skillUrl`, as the plan says, because `curl` needs the absolute URL.
  - Settings: an "Agent skill" section under the token table with the command in a `pre`, a copy button (`CopyButton` of M18), and the link. Review header: a "Connect your agent" link after "Copy prompt". The architecture's "links to /docs" is the link to the `/docs/connect-your-agent` page.
  - `?download` is `#[MapQueryParameter] bool`: `1`, `true`, `on`, or `yes` give `attachment`. A value that is not a boolean gives 404, the default of the attribute.
  - `Content-Disposition` is written literally with the quoted file name of docs/specs. `HeaderUtils::makeDisposition()` leaves `SKILL.md` unquoted, because it is a token.
  - Schema files: `BinaryFileResponse` with `Content-Type: application/schema+json`. No ETag or `Cache-Control` of our own: section 7 names none.
  - `SkillMatchesToolsTest` reads the code spans in the first column of the "Tools" and "Errors" tables of the skill. It compares names only, as the acceptance list says; the parameter columns are M35's content check.
  - No E2E test: the acceptance list has the Vitest test only, and the components show strings. The existing settings and review E2E tests render both components.
  - Skills: `make-controller` (scaffolded with `make:controller DocsController --no-template --no-interaction`, then rewritten; `AbstractController`, attribute routes with the `docs_` prefix, `#[MapQueryParameter]`, `#[Cache]` for the skill's `public, max-age=300`), `templates` (snake_case names, `path()`), `make-twig-extension` (the "Before writing one" check: `markdown_to_html` covers it), `services` (autowiring, `#[Autowire]`, `#[AutoconfigureTag]`; one YAML entry for the vendor extension), `configuration` (the 300 s are a class constant), `components` (`symfony/finder` for the listings), `discover` (`config:dump-reference twig_extra`, `debug:router`, vendor sources of `TwigExtraExtension`, `LeagueCommonMarkConverterFactory`, `UsageTrackingTokenStorage`, `AbstractSessionListener`, `HeaderUtils`), `make-test` (`WebTestCase` for HTTP, `KernelTestCase` otherwise), `cli-conventions` (`make` targets only). context7: league/commonmark 2.10 security options, twig `markdown_to_html` and the extra-bundle `commonmark` configuration. The Agent Skills limits come from https://agentskills.io/specification.

- **Follow-ups and open questions:**
  - Jan, operations: no change is needed now. No `Dockerfile` stage copies the application source, because compose mounts `.:/app`, so the `docs/` and `**/*.md` exclusions of `.dockerignore` have no effect today. A future production stage that copies the source must re-include `docs/user` and `docs/specs/schemas` with `!` lines after both exclusions, because `DocsCatalog` reads both directories. `Finder::in()` throws on a missing directory, so `/docs` would answer 500.
  - M35: the content check of `docs/user/` and of the skill's parameter columns against the implementation.
- **Risks discovered:**
  - Every response of the `main` firewall is `private, max-age=0, must-revalidate`, because `TenantContextListener` reads the user on every request. That is harmless for the shell and the API, but a future public cacheable route outside `/docs` needs the same treatment as the `docs` firewall.
  - CommonMark adds no heading IDs, so a `<slug>.md#fragment` link keeps its fragment but does not jump. No page uses one today.
