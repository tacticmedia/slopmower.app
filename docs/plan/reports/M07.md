## Report: M07 Event store and command service

- **Status:** Done (awaiting commit).
- **Summary:** `CommandExecutor` is the one write path for events and projections. It refuses an open transaction, locks the tenant row with `SELECT event_seq FROM tenant WHERE id = :tenantId FOR UPDATE`, decides, numbers the events from `event_seq + 1`, appends through `EventStoreSql`, runs `inTransaction`, projects every event through `RequestProjector` and `ReviewProjector`, commits, and then dispatches `EventsCommitted`. On any exception it rolls back and clears the entity manager. `RequestCommands` and `ReviewCommands` have one method per command, `EventLogQuery` reads one review's events after a cursor, and `app:projections:rebuild [--tenant]` replays the log one tenant at a time through `CommandExecutor::rebuildProjections()`. `RawSqlTenantAuditTest` enforces the raw SQL rule.

- **Deviations and decisions:**
  - Signature: `CommandExecutor::execute(ReviewId $reviewId, Actor $actor, \Closure $decide, ?\Closure $inTransaction = null): list<RecordedEvent>`. The plan lists `execute(reviewId, decide, ?inTransaction)`. The actor is a parameter, because `DecidedEvent` carries no actor and every event of one command has the caller as actor. `decide` returns `list<DecidedEvent>`. `inTransaction` gets the recorded events.
  - Order in the transaction: lock, decide, append, `inTransaction`, flush, then per event both projectors and a flush. The projectors read the stored rows, so each event is flushed before the next one is projected.
  - Reads under the lock use the new `findFresh()` repository methods, a DQL query with `Query::HINT_REFRESH`. A plain `find()` returns an entity from the identity map, which a controller or an earlier read may have loaded before another process committed. A decision on it would lose that update. `FreshStateTest` proves the rule.
  - `review.started` has no repository in its payload, so `ReviewProjector` cannot insert a `review` row. `ReviewCommands::start()` creates the row in `inTransaction` with the seq of `review.started`. `ReviewProjector` requires the row for every event and folds `ReviewSnapshot` through `ReviewReducer`. Architecture section 3 lists only `ChangeRequest`, `Comment`, and `CommitLink` as projections. So the rebuild recomputes existing `review` rows in place and does not insert them. A missing `review` row fails the rebuild of that tenant.
  - `Review::project(ReviewSnapshot, int)` and `Review::toSnapshot()` replace M06's `close()` and `setLastEventSeq()`, which nothing else used. `ChangeRequest::opened()` lets the rebuild recompute the `request.opened` columns of an existing row.
  - `ReviewCommands::start()` takes the `ReviewId` from the caller, because M12 writes the review pin before the transaction and deletes it after a rollback.
  - `RequestCommands` methods take the domain command and the actor, for example `claim(Claim, Actor)`. `open()` also takes the `ReviewId`. `linkCommits()` and `markReadyForReview()` take the `CommitInfo` list of M04. Each returns the recorded events. The ID of an opened request is the `requestId` of its event. `linkCommits()` with no request IDs throws `invalid_input` on `requestIds`, because the review comes from the first ID.
  - The rebuild goes through `CommandExecutor::rebuildProjections()`, so `CommandExecutor` stays the only writer of projections. Per tenant, the command sets `TenantContext`. The rebuild holds the tenant row lock, so it waits for and blocks writers of that tenant. `TenantFilter::suspend()` reads the tenant list, or `find()`s the one tenant of `--tenant`, which `TenantId::fromString()` parses, so a lower-case ULID works.
  - Deviation from "every statement names tenant_id": the SELECTs name `tenant_id` through the SQL filter, and the bulk deletes `CommentRepository::deleteOfTenant()` and `CommitLinkRepository::deleteOfTenant()` (DQL, as the make-entity skill puts queries in repositories) name it explicitly. The UPDATE and DELETE statements of the ORM flush go by the primary key of rows that were loaded under the filter, and do not name `tenant_id`. The raw SQL rule applies to `*Sql` classes, and the rebuild runs no raw SQL.
  - `occurredAt` is the clock time truncated to the second in UTC, so the in-memory projection equals the stored one.
  - `EventsCommitted` derives `lastSeq` and `requestIds` (deduplicated, in event order, from `RecordedEvent::requestIds()`) in its constructor. Nothing is dispatched for a command that records no event, for example a repeated claim.
  - `RawSqlTenantAuditTest` checks only literals with an upper-case SQL keyword (`SELECT`, `INSERT`, `UPDATE`, `DELETE`, `FROM`, `INTO`, `JOIN`, `WHERE`, `TRUNCATE`), so an exception message that says "tenant" or "review" does not count. A table matches by word boundary in any case. Only `final` classes named `*Sql` are exempt from the scan. The scan derives the SQL-running methods from reflection: the public methods of DBAL `Connection` whose first parameter is `$sql`, `$query`, or `$table`, and the ORM methods whose first parameter is `$sql` (`createNativeQuery`). `insert`, `update`, and `delete` count only in a file that uses the DBAL connection, because the ORM query builder has `update()` and `delete()` for DQL. Each audit asserts on a sample source that it can fail.
  - Orchestrator decision: `RequestProjector`, `ReviewProjector`, and `EventStoreSql` stay separate classes, although each has one consumer, `CommandExecutor`. The plan names them, and the raw SQL rule requires `EventStoreSql`.
  - `RequestCommands`, `ReviewCommands`, and `EventLogQuery` carry `#[Autoconfigure(public: true)]`, as M05 did for services without a consumer. The compiler removes an unused private service, and the tests and `append-events.php` need them.
  - `append-events.php` boots the test kernel through an anonymous `KernelTestCase` subclass, so it reads the test container as a test does and PHPStan resolves its services.
  - `PostCommitNotificationTest` opens the second connection with `DriverManager::getConnection()` and the parameters of the default connection, `Connection::getParams()`, which DBAL marks `@internal`.
  - Skills: `make-command` scaffolded the command. `make-listener` and `make-entity` did not apply: M07 adds no listener in `src/` (M24 and M29 add the `EventsCommitted` listeners), and no entity field changed.

- **Risks discovered:**
  - The rebuild replays one event at a time with fresh reads and a flush per event, and loads the whole log of a tenant into memory. A tenant with a very long log rebuilds slowly and holds its tenant row lock for that time.
  - A flush failure closes the entity manager. `clear()` does not reopen it, so the rest of that request or message fails. The worker resets the manager between messages and requests.
  - `reviewOf()` in `RequestCommands` reads the request with `find()`, which returns an identity-map hit without the SQL filter. The review of a request never changes, and the fresh read under the lock goes through the filter, so a request of another tenant still answers `not_found`.
