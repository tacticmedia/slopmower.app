- **Deviations and decisions:**
  - No `CommitDiffQuery`: the controller is its only consumer (Jan's rule: no service class with one consumer). `CommitDiffController` holds the lookup, the errors, and the file list; the git commands are in `GitReader`, the location comes from `Locator::locate()`.
  - A malformed or upper-case SHA in the path gives 422 `invalid_input` on `commitSha`, as R7 and Q8 do: the common errors of rest-api.md apply to every endpoint (orchestrator decision).
  - Check order: a pending link gives 409 `commits_not_available` before the clone check, because it needs no clone. Q9 does not fetch for a pending link: the spec names no fetch. An available link whose commit is no longer in the clone also gives 409 `commits_not_available` (orchestrator decision).
  - `truncated` is true when git lists more changed files than `files` holds: beyond 300, and also when a rejected path is left out.
  - The file order is git's path order, with the files that touch the anchor first, so the cut at 300 keeps them. The UI sorts them first again, because the order is not part of the contract.
  - A changed path that `RepoPath` refuses (for example a leading `-` or invalid UTF-8) is left out of `files`, because the schema and JSON cannot carry it.
  - `tooLarge` is true when the old or the new object is above 1 MiB (`TreeEntry::MAX_RENDERABLE_BYTES`). `binary` is git's numstat `-`, so the repository's `.gitattributes` can make a file binary.
  - `message` is the raw message (`%B` with `format:`), `subject` is `%s`, the author is read with `--no-mailmap`, and `committedAt` is the committer time, as in `CommitLink.committedAt`.
  - Tabs: docs/specs section 7 names only `/requests/{id}` as a shell path, so the "Changes" tab is `/requests/{id}?tab=changes`, not a new path. A tab change revalidates the root and the request loader, as any search change in React Router. The counter of "Changes" is `commitCount`. An available commit in the "Linked commits" list links to the tab, which the user docs already describe ("Click it to see its changes").
  - Loading: Q9 loads through a loader-only route `requests/:requestId/commits/:commitSha` and `useFetcher().load()`, R7 through `repositories/:repositoryId/diff-sides?old=&new=`, both with `shouldRevalidate` false, because a linked commit and its blobs never change. `CommitDiff` is a `React.lazy` chunk; the diff library is a shared chunk of `CodeFile` and `CommitDiff` and stays out of the shell.
  - `CommitDiff` shows a placeholder instead of a diff for a binary file, a file above 1 MiB, a submodule (R7 has no blob for it), and equal blobs such as a pure rename, because `parseDiffFromFile()` gives no hunks for equal contents and the diff would be empty. Diffs are unified, with our own file header (path, status, "Anchored here", counts) and `disableFileHeader`.
  - `LocationInfo` shows the target and short SHA, the status as a `Label`, the located `path:Lx-Ly`, and the confidence in percent, or the orphan reason. The detail shows it for Q3's default-branch location, and each commit section for Q9's `linked_commit` location. A null location shows "The location is not known."
  - The "Outdated" label is the `attention` variant, as on GitHub, and shows only for `outdated: true`. In the list it sits in the status cell.
  - `ClosedRequestReadOnlyTest` (M22) now checks for buttons outside the tab navigation: Primer 38.40.0 `UnderlineNav` always renders its "More" overflow button, hidden by CSS, so "no button in the detail" no longer holds. The action buttons are in the header and still covered.
  - `config/reference.php`: the first cache warmup reordered two `Default` comments, a later one restored the file, so the commit does not contain it.
  - `GitRunner::run()` takes the standard input for `cat-file --batch-check`, one process for all objects of the diff.
  - Skills: `make-controller` scaffolded `Api\CommitDiffController` (`--no-template --invokable`), then rewritten with `#[Route]` and `#[MapEntity]`. `make-test` (`WebTestCase` for Q9, Panther for the browser, Vitest for the pure placeholder rule), `cli-conventions` (`make` targets, `docker compose exec php bin/phpunit --filter`), `services` (autowiring only), `configuration` (the limit is the class constant `CommitDiffController::MAX_FILES`), `components` (no new infrastructure; Process input for git), and `discover` (git 2.47.3 output formats of `diff-tree --raw --numstat -z` and `cat-file --batch-check` checked in the container). context7: `@pierre/diffs` `FileDiff` with `parseDiffFromFile`; the installed type definitions and sources confirmed the props and the worker pool singleton; a Node run confirmed zero hunks for equal contents.
