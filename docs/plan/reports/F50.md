## Report: F50 Production image

- **Status:** Done 2026-10-16.
- **Summary:**
  - `docker build --target frankenphp_prod` builds the production image: the stage `assets` runs the Vite build, `frankenphp_prod_builder` installs the packages without the dev packages, dumps a classmap-authoritative autoloader and `.env.local.php`, and warms the `prod` cache, and `frankenphp_prod` starts from `frankenphp_base` and runs as `www-data` with `docker/frankenphp/Caddyfile.prod` (D74).
  - One entrypoint for dev and prod. `MIGRATE_DB` migrates and, without `MIGRATE_DB_AND_CONTINUE`, exits 0, so one release container migrates. In dev, the php service sets both, the entrypoint also creates and migrates `app_test` and `app_e2e`, and it runs `composer install` when `vendor/composer.lock.md5` does not match `composer.lock`.
  - `make prod-check` (`bin/prod-check`), a gate step of `qa.yml`, builds the image, runs `lint:container`, and requests `/login` with `APP_PUBLIC_HOST=prod-check.example`.
  - `docs/deployment.md` is now `docs/deployment/README.md` (shared variables), `manual.md` (host install), and the new `dockerised.md`.

  - The check images and containers are removed.
- **Deviations:**
  - `debug:container --env-vars` is not in `make prod-check`. Without debug, the command finds no XML dump and lists no variable. With debug, it exits 1 in every environment, because the processor `rds_region` throws while `AWS_REGION` is empty. A candidate records it.
  - The smoke check is the target `make prod-check` with the script `bin/prod-check`, not steps of their own in `qa.yml`, because `QaWorkflowTest` allows only `make` targets in gate steps (D62). It needs no database: `/login` reads none.
  - `.dockerignore` also excludes the dev tooling: `.agents/`, `mate/`, `Makefile`, `bin/act-run`, `bin/phpunit`, `bin/prod-check`, the PHPUnit, PHPStan, and Playwright configuration, `config/reference.php`, `test-failures/`, and the Vite metadata in `public/`. The builder copies no input of the stages `assets` and `symbols`.
  - The image has `/srv/slopmower/tenants`, `var/sessions`, and `var/mcp-sessions` as `www-data`, so new named volumes get that owner. `dockerised.md` describes the session volumes, which the scope does not name: without them, each new web container signs every user out.
  - The share directory of the image is `/app/var/share`. The cache warmup compiles `APP_SHARE_DIR` into the container, which a test with a warmed `prod` cache confirmed, so a runtime value has no effect. `README.md` and `.env.prod.dist` say so.
  - `Caddyfile.prod` has no access log. nginx logs the requests.
  - The orchestrator added the migration of `app_e2e` in dev.
  - `frankenphp_base` installs `pcntl`, so a worker stops after its current job on `SIGTERM`. Without it, `docker stop` killed a worker in a job, and Messenger delivered the job again after the redelivery timeout of 1 hour. The worker command of `dockerised.md` has `--stop-timeout 610`, above the 600 s limit of a clone or fetch job. The dev image gets `pcntl` too.
- **Versions:** nothing installed. The upstream template `dunglas/symfony-docker` was checked on 2026-10-16.
