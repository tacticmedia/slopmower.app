- **Deviations and decisions:**
  - `ClaimAge.tsx` of the plan is `ClaimedBy.tsx`. `ClaimAge.tsx` and `claimAge.ts` differ only in case: on the macOS host `tsc -b` resolved `./ClaimAge` to `claimAge.ts` (TS1149, TS1261). The component renders the agent name and the age, so `ClaimedBy` names it.
  - Entry point to the list: an `UnderlineNav` with "Code" and "Requests" (counter `counts.total`) at the bottom of the review header. The plan names no link to the list. The header's own bottom border is gone; the navigation draws the line.
  - List: Q1 with `sort=updated` (latest agent work on top), `limit=200`, all pages. The `SegmentedControl` has "All" plus one segment per status, a dropdown on narrow screens. URL names equal the Q1 names: `status`, `awaiting=user`, `path`. An unknown `status` counts as "All", a leading `/` of `path` is dropped (Q1 rejects it). The summary is the row header and links to the detail; `path:Lx-Ly` links to the file view with the line hash. The "Turn" column shows `awaiting`. The `outdated` filter is M30.
  - Detail: "Resolve conversation" sends Q12 at once without a note, as GitHub resolves a conversation with one click. "Reopen", "Close as won't do", and "Unassign" open a `Dialog` (`NoteDialog`); the submit stays disabled until the note is not blank or the reason has 20 code points after trimming (`noteRule.ts`; `Assert\Length` counts code points). The text is trimmed; an empty optional note is sent as null. Server errors show in the dialog, or below the buttons for "Resolve conversation".
  - Writes: one `useFetcher` for the commands, `{intent, input}` JSON to the route action, intents named after the `allowedActions` values. The action also takes the `reply` intent of `ThreadBox`; it posts to the request of the route parameter. The busy state comes from `useTransition` (the M21 rule: the fetcher state does not change while an async transition runs). Cancel clears the error of a failed dialog command. While a command runs, the buttons are disabled and the dialog neither submits again nor closes. A dialog closes when its command succeeds; React Router revalidates Q3, so the buttons follow the new `allowedActions`.
  - `ThreadBox` takes `showHeader`; the detail shows status and lines in its own header. Entries without a body (a claim, `commit.found`) stay out of the thread, as in M21; the claim shows as "Claimed by".
  - The commit list shows short SHA, state, subject, linker, and `otherRequestIds` as links. The commit note is not repeated, because it is the body of the `commit.linked` entry in the thread. Snapshot lines show without the `before` and `after` context.
  - `StatusLabel` text moved to `statusText.ts`, so the segments reuse it without a non-component export from a `.tsx` file.
  - Slice test: the user opens the request detail after issuing the token, so step 7 is a reload of that page. The agent's results are checked against the `outputSchema` and the schema files through `McpAssertions`. A last `list_requests` confirms `verified` on the server.
