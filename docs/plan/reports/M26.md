## Report: M26 Symbol index

- **Status:** Done (awaiting commit).
- **Summary:** `nikic/php-parser` 5.9.0 parses PHP 8.5. `PhpSymbolExtractor`, tagged through the `SymbolExtractor` interface, gives the symbol table of a blob. V1 queues `IndexReview` after the `review.started` transaction. The worker writes the path list of the commit into `indexed_file`, then parses each PHP blob without an `indexed_blob` row through `BlobSymbols`, the one parse-on-demand path, and records the progress in the review. `IndexSql` writes all index rows with `ON CONFLICT DO NOTHING`; a blob row and its symbols commit together. V5 returns the `IndexStatus`, V9 returns the `SymbolList` and parses a blob that the job has not reached. The job publishes `index` updates at most once per second plus the final state. `app:index:rebuild` resets and queues the job, `--reparse` first deletes the parsed blobs. The review header shows a Primer `ProgressBar`.

- **Deviations:**
  - `SymbolExtractor::extract()` returns a `SymbolTable` (`language`, `parseError`, `symbols`), not a bare list, so a syntax error gives `parseError` and an empty list, and V9 gets `language` from the extractor.
  - The rebuild command's arguments are named `tenant-id` and `review-id`: Symfony derives kebab-case names from the `__invoke()` parameters. They are positional, so the call is `app:index:rebuild <tenantId> <reviewId> [--reparse]` as planned.
  - `config/packages/messenger.yaml` is unchanged: `#[AsMessage('async')]` routes `IndexReview`, as it routes the M09 jobs.
  - The fixtures under `tests/Fixtures/php` are excluded from PHPStan (undefined names) and php-cs-fixer (the tests expect their line numbers). The syntax-error input is a string in the test.
- **Decisions:**
  - `IndexReview` is dispatched in `ReviewCommands::start()` after `recordStarted()` returns (the M12 follow-up), not from an `EventsCommitted` listener, so the fixtures that record reviews without a clone queue no job.
  - The three entities are `readOnly` mappings without constructors or setters; only `IndexSql` writes them. The composite primary keys are the unique keys: `indexed_file (tenant_id, repository_id, commit_sha, path_sha256)` with `path` as a plain `TEXT` column, because a btree entry of a path above about 2,700 bytes exceeds the PostgreSQL limit (orchestrator decision in review), `indexed_blob (tenant_id, repository_id, blob_sha)`. `symbol` has a `BIGINT` identity ID and the index `idx_symbol_blob (tenant_id, repository_id, blob_sha)`. `repository_id` is a plain column without a foreign key, so M31 deletes by tenant and repository.
  - Counters: `filesTotal` counts every listed entry whose path `RepoPath` accepts (the V6 rule), `filesDone` counts the processed entries, `symbolsTotal` sums the symbols of each supported path, so a blob at two PHP paths counts twice. The counters are flushed at each publish and at the end, not per file.
  - A blob that is not parseable (submodule, symlink, binary, above 1 MiB) gets no `indexed_blob` row, because the row marks a parsed blob. V9 gives such a PHP file `language: "php"`, `parseError: false`, and no items.
  - The throttle is a local timestamp in the handler: an update at the start (`running`), then when at least 1 s passed since the last one, then the final state. RateLimiter was considered; the interval belongs to one job, so it needs no shared storage.
  - The handler catches every failure, logs it at `error` level, and records `failed` with the message of a `DomainError` or "The index job failed.", so `indexError` never carries git stderr or server paths. The job is not retried; `app:index:rebuild` queues it again.
  - FQN formats beyond the two examples of architecture section 3: `Ns\Type`, `Ns\Type::CONSTANT`, `Ns\Enum::Case`, `Ns\function()`, `Ns\CONSTANT`. Promoted constructor parameters are properties with the lines of the parameter. Each item of a statement with several items (`public int $a, $b;`) gets the lines of the statement. Anonymous classes and their members have no symbols. Symbols whose FQN is not valid UTF-8 or longer than 1,024 characters are left out (symbol.schema.json). php-parser attaches no doc comment that stands between the attributes and the declaration, so such a symbol has `docStartLine: null`.
  - V5 and V9 live in their own invokable controllers, as the plan's file list names them. `IndexStatus` is shared by V5 and `Review.index`; V9's ETag is `W/"v1-<blobSha>"` with `Cache-Control: private, no-cache`, built before the parse, like V7.
  - UI: the bar shows while the state is `pending` or `running`, with "Symbol index queued" or "Symbol index: N of M files". `ready` shows "Symbol index ready: N files, M symbols", `failed` the error. The layout's loader data feeds the component; the M24 hook already revalidates on `index`.
  - Skills: `make-entity` scaffolded the three entities and repositories, then adapted (read-only, composite keys, typed IDs, no setters). `make-migration` generated the migration, reviewed and described. `make-controller` scaffolded both invokable controllers. `make-command` scaffolded the command, renamed to `RebuildIndexCommand`. `services`: `#[AutoconfigureTag]` and `#[AutowireIterator]`, no YAML. `configuration`: the interval and the limits are class constants. `components`: Messenger for the job; no lock, because the writes tolerate conflicts. `discover`, `make-test`, and `cli-conventions` were followed.

- **Risks discovered:**
  - Every V1 now queues an index job. In `e2e`, `sync://` runs it inside V1, so V1 takes longer for a larger repository.
  - Each `index` update revalidates every loader of the open route, at most once per second during a job, including the V7 and V8 reads of the open file.
  - Each job reads a binary PHP blob again for the binary check, because it has no `indexed_blob` row.
  - Two jobs of one review at the same time, for example a rebuild during a job, both write the counters.
  - Test gotchas: `createPantherClient()` boots a new kernel, and `KernelBrowser` reboots it before each request after the first. Both empty the in-memory queue of the PHPUnit process, so a test runs queued messages before either happens.
