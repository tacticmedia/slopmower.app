- **Deviations:**
  - `watch` has explicit patterns: `src`, `config`, `templates`, `.env*`, `vendor/composer/installed.php`. A bare `watch` also matches `var/`, where test runs write PHP files, and reboots every PHP thread, the `:8081` site included.
  - The `:8081` Mercure block has its own Bolt `path`. Two hubs with the same transport configuration share one transport, so the dev and e2e hubs would cross-talk.
  - Global `frankenphp { max_threads auto }`: the classic `:8081` site otherwise gets one PHP thread.
  - The Dockerfile has no `ENV APP_ENV` and installs `php.ini-development`. The image ships no `php.ini`, so `variables_order` is EGPCS and a container `APP_ENV` would make `KernelTestCase` boot the dev kernel.
  - Only the dev stage. No `safe.directory`, `apcu`, `file`, `nonroot` user, Dockerfile `HEALTHCHECK`, Caddy `--watch`, access log, or `vulcain` from the template.
  - `pcntl` is installed and `init: true` is set. Without them the worker ignores SIGTERM as PID 1 and is killed after 10 s, and Chromium processes of the E2E suite stay as zombies.
  - `MESSENGER_TRANSPORT_DSN` has `get_notify_timeout=1000`. The default 60 s notify wait made `make worker-restart` take up to 111 s.
  - The entrypoint prepares the project only for `frankenphp`. The worker starts when `php` is healthy. `setfacl` runs only when a probe on `var` succeeds: macOS bind mounts (Docker Desktop, OrbStack) return "Operation not supported", which stopped `make up`.
  - The worker has no healthcheck: the upstream image probes the Caddy admin API, which only `php` runs.
  - Port `127.0.0.1:8000:80`, not `8000:80`: on all interfaces, the LAN could read the profiler, which shows the secrets. Task 8 now says so.
  - `restart: unless-stopped` on the database, so a Docker or host restart does not leave php in a crash loop.
  - `make db-reset` stops php and the worker, runs `dropdb --force` and `createdb`, and starts the stack. The php entrypoint migrates. `doctrine:database:drop` failed while the worker held its LISTEN session.
  - `.env.e2e` sets `APP_SECRET`: `.env` leaves it empty. `composer.json` `extra.runtime.test_envs` is `["test", "e2e"]`, so `e2e` does not load `.env.local`.
  - A `when@e2e` Monolog stream handler writes `var/log/e2e.log`.
  - `QueuedMessages` adds `ConsumedByWorkerStamp` next to `ReceivedStamp('async')`, as the worker does, because the Doctrine ping and close middlewares and `RouterContextMiddleware` check it. It reads the queue with a fetch size, because `InMemoryTransport::get()` returns one envelope by default.
  - `/healthz` has `data-environment` on `<html>`, so the smoke test proves that the browser reaches the `e2e` site.
  - `.env.test` keeps the recipe value `PANTHER_APP_ENV=test`. With `e2e`, Panther's fallback server would pass the smoke test without the `:8081` site.
