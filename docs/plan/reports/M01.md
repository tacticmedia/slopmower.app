- **Deviations:**
  - Orchestrator additions, which rank above the plan: the `php` port is `127.0.0.1:${HTTP_PORT:-8000}:80`, and the database port is `127.0.0.1:${DATABASE_PORT:-5432}:5432`. The Makefile starts with `-include .env.make.local`. `.dockerignore` lists `.claude/`.
  - Caddyfile `watch`: `/app/src/**/*.php`, `/app/config/**/*.{php,yaml}`, `/app/templates/**/*.twig`. No pattern for the `.env` files. A pattern for a file at `/app` makes `/app` the watched root, and the recursive watcher then walks every worktree under `/app/.claude/worktrees`, with its `vendor/` and later `node_modules/`. Edit a `.env` file, then restart the stack or touch a watched file.
  - `cors_origins http://localhost:{$HTTP_PORT:8000}` and `MERCURE_PUBLIC_URL=http://localhost:${HTTP_PORT:-8000}/...` in `.env.dev`. Compose passes `HTTP_PORT` to `php`. Without this, a worktree's dev page would subscribe to the hub of the main stack. With the default port, the values equal the plan's.
  - The `:8081` hub uses `transport local`. Mercure 0.24.2 shares one bolt transport, keyed by its configuration, between every hub that uses the default, so `dev` and `e2e` would see each other's updates and history.
  - The entrypoint prepares the project only for the `frankenphp` command, not for `php` or `bin/console` as the template does. So the worker, which starts after `php` is healthy, does not run Composer and the migrations again.
  - `setfacl` runs only when the file system supports ACLs. Docker Desktop bind mounts on macOS return "Operation not supported", which stopped the first `make up`.
  - The migrate calls use `--allow-no-migration`, so a checkout without migrations starts too.
  - `make up` is `docker compose up -d --wait --build`, so a changed Dockerfile, Caddyfile, or ini file takes effect without a manual build. A cached build takes a few seconds. The image has the Caddyfile built in, so the dev stage has no `frankenphp run --watch` CMD. Run `make up` after a Caddyfile change.
  - `make db-reset` stops the worker, drops the database with `dropdb --if-exists --force` in the database container, creates and migrates it, and starts the worker. `doctrine:database:drop` fails while the worker holds a session on `app`.
  - No `ENV APP_ENV=dev` in the image, unlike the template. `.env` sets it. An environment variable would win over `.env` files in every process of the container, and `php_server` must set `e2e` for `:8081`.
  - No `HEALTHCHECK` in our Dockerfile. `php` has the compose healthcheck on `/healthz` (interval 30 s, start period 300 s for the first Composer install, start interval 2 s). `worker` disables the healthcheck of the upstream image, which checks the Caddy admin endpoint.
  - Not taken from the template: `apcu`, `file`, the `vulcain` directive, the `hot_reload` site option (it needs anonymous subscribers), `useradd nonroot`, the system-wide `safe.directory` (task 4), the prod stages.
  - `QueuedMessages` has `asyncTransport()` and `runQueuedMessages()`. Tests assert queued messages with `self::asyncTransport()->getSent()`. `InMemoryTransport::get()` returns one envelope per call by default, so the loop runs until `get()` returns nothing. It dispatches each envelope with `ReceivedStamp('async')`, then acknowledges the returned envelope, as the worker does. PHPStan reports an unused trait (`trait.unused`), so `QueuedMessagesTest` uses it. That test is one case of our own rule; it uses the framework's `RedispatchMessage` and `RunCommandMessage` handlers, because M01 has no message classes.
  - `when@e2e` gets a Monolog handler like `when@test`: errors only, 404 and 405 excluded, into `var/log/e2e.log`. Without it the `e2e` kernel logs nothing.
  - `when@e2e` sets `session.storage_factory_id: session.storage.factory.native` explicitly, although it is the default, to record D34 next to the `test` override.

- **Risks discovered:**
  - Mercure 1.0 makes the top-level `publisher_jwt` and `subscriber_jwt` directives a configuration error unless `protocol_version_compatibility 8` is set, and modern mode needs `issuer` blocks and tokens with `iss`, `aud`, and `exp`. The first FrankenPHP release that bundles Mercure 1.x breaks this Caddyfile, and M24 must check what `symfony/mercure-bundle` 0.5.0 puts into its tokens.
  - The `e2e` hub uses the in-memory `local` transport: no history across a FrankenPHP restart. That suits tests.
  - Each worktree stack builds its own `<project>-php` and `<project>-worker` images from the shared layer cache, and keeps four named volumes until `docker compose down --volumes`.
