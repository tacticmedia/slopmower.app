## Report: F112 Drop the pull request choice of Q15

- **Status:** Done 2026-11-04.
- **Summary:**
  - Q15 takes `{proposalEventId, note?}`. A body with `pullRequest` answers as one without it, because the input class has no such property. The 422 for `pullRequest: true` on a local repository is gone with the field.
  - `request.proposal_approved` writes no `pullRequest`. `PayloadReader` ignores the field of a stored payload, and the projection reader ignores it in a stored `proposal`, so neither needs a migration or a rebuild.
  - `Proposal` is `{eventId, state}`. `RequestState::delivery()` is gone, and `RequestNormalizer` emits `Review.delivery` as `Request.delivery`. A stored approval with `pullRequest` no longer changes it (D108).
  - The server instructions, `docs/specs/mcp.md`, and `SKILL.md` no longer ask the agent to read `get_request` again after an approval.
