- **Summary:**
  - V16 `GET /api/v1/reviews/{reviewId}/search?q=&limit=` returns a `SearchHitList` `{reviewId, partial, items}`. A hit is a `FileHit` `{kind: "file", path}` or a `SymbolHit` `{kind: "symbol", path, fqn, symbolKind, declarationStartLine}`.
  - One SQL query in `IndexSql::search()` reads the `indexed_file` rows of the review commit and the `symbol` rows of their blobs, matches a case-insensitive substring of the path or the symbol name, and ranks in SQL. No new index.

  - "Quick open" in the review header, and Cmd+K on macOS or Ctrl+K elsewhere, open a Primer `Dialog` with a `FilteredActionList`. Enter opens a file, or a symbol at `path#L<declarationStartLine>` with only that line selected, as F04 does.

- **Decisions and deviations:**
  - The scope gives a file hit as `{kind: "file", path}` and a symbol hit with three more fields. The schema is a `oneOf` of `FileHit` and `SymbolHit` with a `const` `kind`, as `live-update.schema.json` is, so a file hit carries no null fields. `kind` is an open set, listed in the specs README section 8 next to the live-update `type`. The client skips a hit of an unknown kind.
  - `q` is 1 to 1,024 characters, as the `name` of V14, without a NUL byte, because libpq cuts a bound string at NUL: `q=%00` matched every path. `limit` is 1 to 50, default 20. A value outside the range gives 422, a value of the wrong type 400, as the specs README section 4 says.
  - A symbol matches by its short name, the `name` of V9, not by its FQN. A file matches by its path, and its name for the ranking is the last path segment. The ties after the scope's order: path in byte order, files before symbols, `declarationStartLine`, then `fqn` in byte order.
  - Submodules give no hit, because V7 refuses them and the file view cannot open them. Symlinks give hits.
  - `partial` is true for `pending`, `running`, and `failed`. The dialog shows "Index in progress", or "Index failed: hits may be missing" when the index of the review failed, because the review header that shows the failure is hidden in focus mode.
  - V16 reads only the index, so it has no `repository_unavailable` case.
  - The shortcut is Cmd+K on macOS and Ctrl+K elsewhere, through `isMacOS()`. It is off in an editable element (`isEditableElement()`) outside the dialog. The dialog is modal, so while it is open, Cmd+K closes it.
  - `@primer/behaviors` 1.11.0 is now a direct, exact dependency for `isEditableElement()` and `isMacOS()`. `@primer/react` 38.40.0 already installed it, and 1.11.0 is the latest version on npm.
  - The dialog is a Primer `Dialog` with `FilteredActionList` from `@primer/react/experimental`, the list of `SelectPanel`. The modal `SelectPanel` has Cancel and Save buttons for a selection, which a command does not need. The `Dialog` takes Escape with `preventDefault()`, so the focus-mode listener of F02 ignores it.
  - The dialog lists hits only for the answer to the current query, so Enter never opens a hit of an earlier query. There is no debounce: the query takes milliseconds, and `useFetcher` aborts the previous load. The `search` route does not revalidate, so the hits do not change while the reviewer moves through them.
  - The scope's cross-tenant case is the inventory case `api_review_search`, as in F04.
  - The scope names two UI acceptance tests. The spec has six: the file, the symbol, and the keyboard-only path for those two, and one each for the text-field rule, focus mode, and the partial message.
  - The scope names "the architecture endpoint list". Architecture section 7.4 lists only the endpoint groups and links the specs, so it does not change, as in F04. Section 4, section 8, and D48 describe the feature.
  - Developer guide counts after the rebase: functional 155 classes and UI 37 specs, the actual counts. The unit (61) and Vitest (20) counts were already correct on `main`. `assets/code/` stays 9, because the front-end table counts TypeScript files without tests, and the tenth file of `assets/code/` is a CSS module.
