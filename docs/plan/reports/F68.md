- **Summary:**
  - The new endpoint R9 `GET /api/v1/repositories/{repositoryId}/commits?ref=&limit=` (S, B) returns `CommitLog` `{repositoryId, ref, items}` with the first `limit` commits of `git log`, 1 to 50, 10 by default, newest first. It reads the clone without a fetch. Without `ref` it resolves `refs/heads/<defaultBranch>`. Decision D76.
  - `GitReader::log()` runs `git log --no-mailmap -z -n <limit> --format=format:%H%x00%an%x00%at%x00%ct%x00%s --end-of-options <sha>` and reads records of 5 NUL-separated fields. The action in `RepositoryController` resolves the ref first with `resolveCommit()`, so the errors are those of V1 without the fetch.
  - The repository page shows "Latest commits on `<branch>`" under "Start a review": "As of the last fetch", and per commit the subject on one line, the author, "committed" with the age, the short SHA with a copy button, and "Start review", which posts V1 with the full SHA. A clone that is not ready shows "Commits show when the clone is ready." The open reviews come first when there are any.

- **Decisions and deviations:**
  - The index row names the path without the optional query, as V2 does. The R9 section names `?ref=&limit=`.
  - The loader calls R9 after V2, because V2 gives `defaultBranch`, which decides whether R9 runs. A 409 or 422 of R9 gives `log: null` with the `ApiError`. The section shows "Commits show when the clone is ready." for `repository_unavailable` and the error message for a 422. Other errors reach the error boundary.
  - Page order: the review list comes before "Start a review" only while an open review exists. Without one it stays below, so "Show closed" stays reachable and the list does not move when it is toggled. F69 hides the empty list.
  - `LatestCommits` is an `h3` section inside the "Start a review" section, through a `children` prop of `StartReviewForm`, below the form and the carry-over result. It is not inside the form element, so `[data-testid="start-review-form"] button[type="submit"]` of the existing tests still finds one button.
  - Each row has its own fetcher, so a failed start shows its error in its row. The button is named "Start review at <short SHA>" so the rows are distinct for assistive technology. The row sends no title and no carry-over, so V1 gives the short SHA as the title and the action opens the review.
  - The copy button is `CopyButton` with `iconOnly` and the label "Copy the full SHA of <short SHA>".
  - git 2.47.3 does not map `%an` through a mailmap, also with `--use-mailmap`; only `%aN` is mapped. `--no-mailmap` stays as D76 and `commitDetails()` have it, so the mailmap test guards the field choice and the flag together.
  - `log()` returns an empty list for empty output, which a resolved commit does not give.
