- **Deviations and decisions:**
  - The decider returns `DecidedEvent` values, each a domain event with its request ID. The command service of M07 wraps them into `RecordedEvent`.
  - Awaiting rule 2 counts every user event on the request: a message, a note, or a status change. Before, a user's reopen after an agent's question left `awaiting = user`, and the agent never saw the request again. `thread-entry.schema.json` makes every request event a thread entry, and the MCP instructions expect reopened requests to await the agent. Architecture section 6 now says so. Jan may want to confirm.
  - Text inputs reject U+0000 and invalid UTF-8, because `jsonb` cannot store them. Markdown fields (body, reason) follow the Markdown type: 1 to 65,536 characters with one non-whitespace character. Optional notes follow docs/specs README section 2.2: null or 0 to 65,536 characters.
  - The check order of docs/specs README section 4 is literal. So `unlink_commit` of a commit that is not linked gives `invalid_input` also on a closed review. It writes nothing, so D27 does not apply.
  - A wrong actor kind for an action (claim by the user, verify by an agent) gives `invalid_transition` in the domain, as the `allowedActions` table requires. Only `open` by an agent gives `forbidden`, because `invalid_transition` has no request to name.
  - The decider does not write `commit.found`. `mark_ready_for_review` counts a pending link as available when the availability lists it.
