- **Deviations and decisions:**
  - Signature: `RequestDecider::decide(RequestCommand $command, list<RequestState> $states, ReviewSnapshot $review, Actor $actor, list<CommitInfo> $availability = []): list<DecidedEvent>`. `ReviewDecider::decide(StartReview|CloseReview, ?ReviewSnapshot, Actor)`. `RequestReducer::apply(?RequestState, RecordedEvent)` and `ReviewReducer::apply(?ReviewSnapshot, RecordedEvent)`. All are static functions of `final` classes, as `SnapshotCapture`.
  - `DecidedEvent` carries the `DomainEvent` and the `requestId` column, which request events need. `Open` gets a new `RequestId` from the decider, and `Reply` a new `CommentId`. The application reads them from the result.
  - `availability` is the list of `CommitInfo` (SHA, subject, commit time) that the application found in the server clone. `link_commits` takes `available`, `subject`, and `committedAt` of `commit.linked` from it. `mark_ready_for_review` counts a link as available when its state is `available` or the list holds its SHA. The decider does not write `commit.found`. The fetch follow-up of M16 writes it in its own transaction, as Q10 says.
  - M16 can decide once: a refused command throws review_closed or invalid_transition before commits_not_available. Only `CommitsNotAvailable` means "fetch, read the links again, decide again".
  - invalid_input checks in the decider: a body or required note without a non-whitespace character (`trim()`, the same whitespace as `WontDoReason`), the 20-character reason, `question: true` by a user, `requestIds` empty, repeated, more than 50, or of another review (field `requestIds.<index>`), and an unlinked commit for `unlink_commit`. Length maximums stay with the input layer. This closes the M03 follow-up about non-blank text.
  - Wrong actor kind for an action gives invalid_transition, because the `allowedActions` table is per caller and the property test needs it. `open` by an agent, any command by `system`, a review command by a non-user, and an `Open` anchor that is not at the review commit throw `\LogicException`: no interface can send them, so they are server faults (500).
  - A repeated claim by the holder on a closed review gives review_closed: the review check comes first.
  - Orchestrator decision: a user comment is the hand-back of `AwaitingPolicy` rule 2. "Thread message" means a `request.commented` entry, as requirements.md says: "The user's reply hands the turn back to the agent." `RequestState` keeps `lastUserCommentSeq`, `lastAgentEventSeq`, and `lastAgentEventIsQuestion` for rules 2 and 3. Every event with an agent actor is an agent event. `commit.found` is not.
  - `RequestState` stores `resolution` and `wontDoBy` (set exactly while `wont_do`). `closed()` and `AwaitingPolicy::evaluate()` derive from them, so M06 stores `awaiting` as a computed column. `RequestState::with()` copies through PHP 8.5 clone-with and checks the invariants again: claim fields exactly while `in_progress`, `wontDoBy` exactly while `wont_do`, and `resolution` fits the status.
  - `lastEventSeq` and `updatedAt` follow the thread entries of thread-entry.schema.json: request events, `commit.linked`, `commit.unlinked`, `commit.found`. `RequestReducer` returns the state unchanged for review events and `batch.submitted`, and throws `\LogicException` for a thread entry that does not name the request.
  - `ReviewSnapshot` holds the review event data: `id`, `title`, `ref`, `commitSha`, `startedBy`, `createdAt`, `closedAt`, `closedBy`, `closeNote`. `Review.lastEventSeq` stays with the M07 projector. `StartReview` takes the final `title`. M12 computes the default title.
  - Symfony Workflow is not used: `src/Domain` imports only `App\Domain`, `Symfony\Component\Uid`, and PHP core, and the guards depend on claim holders, links, and the review state.
  - Tests beyond the acceptance list: `CheckOrderTest`, `RequiredTextTest`, and the last two `LinkCommitsRulesTest` cases each cover one rule of the decider that no acceptance test reaches.
