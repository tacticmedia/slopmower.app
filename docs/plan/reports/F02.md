## Report: F02 Focus mode

- **Status:** Done (awaiting merge). One commit `feat: F02 focus mode` on the worktree branch, rebased onto `d0374d9`. The review items 1 to 3 are applied, see "Review".
- **Summary:**
  - A "Focus" toggle with `aria-pressed` is the last file command in the file header. Focus mode hides the app header, the review header, and the closed banner. Above 768 px the code layout fills `100vh` across the full window width: the tree column and the file column scroll on their own, and the page does not scroll.
  - The file column is a flex column: the file header, the file-level threads (at most a third of the height, own scroll area), and the code view with `flex: 1`. At 768 px and below only the headers are hidden.
  - The state lives in `ReviewLayout` and reaches `CodeLayout` and `FileRoute` through the outlet context (`useFocusMode()`). It persists through `usePreference('focus')`, the hook for per-browser UI preferences that F02 and F03 share.
  - Escape leaves focus mode, except in a form (comment boxes, "Comment on lines") and except when a menu or dialog already took the key.

- **Decisions and deviations:**
  - Focus mode applies only while a file is open (`/reviews/:reviewId/files/*`). The preference stays stored, but the Code tab without a file and the Requests tab show the normal layout. Reason: the toggle is in the file header, so with no file open the user would see no way out.
  - Escape is ignored inside any `form`, not only inside a comment box. The only other form in focus mode is "Comment on lines", where the user is also typing. The listener is on `window`, so the Primer menus that call `preventDefault()` on the document run first. The Symbols menu and the thread action menus close without leaving focus mode.
  - CSS hides the headers (`display: none`). They are not unmounted, so their components keep their state. `RootLayout` hides its header through `.page:has([data-focus-mode])`, and `ReviewLayout` sets that attribute. This keeps the state in `ReviewLayout`, as the scope file says, and needs no context above it.
  - Above 768 px, focus mode also removes the `max-width` and the padding of `main`, so the layout uses the full window with an 8 px padding of its own.
  - The toggle is the last child that `FileRoute` passes to `FileHeader`, after "Viewed". `FileHeader` renders "Copy path" after its children, so the header reads "Wrap lines", "Comment on lines", "Symbols", "Comment on file", "Viewed", "Focus", "Copy path".
  - Primer `Button` has no style for `aria-pressed`. A pressed toggle shows a leading `CheckIcon`, the same style as the "Wrap lines" toggle of F03.
  - Rebase: `usePreference.ts` differed only in its docblock, and the version on `main` is kept. `LargeFile.spec.ts` combines the wrap loop of F03 and the focus loop into four runs.
  - `config/reference.php` is regenerated by the container. I restored it and it is not part of the commit.
- **Review:** the orchestrator's review, applied in the one commit:

  - Focus mode on the Requests tab and the Changes tab stays out of scope.
