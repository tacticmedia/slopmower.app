- **Decisions and deviations:**
  - Selection commits come from `onLineSelectionEnd`, not `onLineSelected`. React `File` calls `setSelectedLines()` without `notify: false` on each render, so `onLineSelected` also fires for the controlled selection. Its hash write cancelled the push of a Cmd-click navigation in `CodeNavigation.spec.ts`. In `InteractionManager.js` every gesture fires `notifySelectionEnd` with the same range right before `notifySelectionCommitted`, and only `setSelection()` fires the commit alone.
  - A scroll to a line runs once per frame from `onPostRender` or a new selection, until the rows are below the header. It waits up to 10 s while `getLinePosition()` still answers a height of 0, which means that the view does not know the lines yet, and it moves the window at most 60 times. A scroll that relied on `onPostRender` alone stopped: without a scroll, no render follows.
  - The sticky header sets `scroll-padding-top` of the root to the toolbar height plus the 44 px stuck row. The scroll to a line, the page keys, and `dragFromPlus()` respect it. The scope lines are not part of it, so they follow the first line below the toolbar and cannot change that line.
  - The `display: contents` header keeps `data-testid="file-header"` around the breadcrumbs and the toolbar. The sticky part sticks against the file section, which has no overflow clip.
  - The toolbar has more commands than GitHub's. At 1280 px it has two rows, 82 px. "Raw", "Copy raw file", and "Download raw file" are one `ButtonGroup`, as on GitHub, and `CopyButton` got `iconOnly`.
  - The pane width is stored by Primer under `widthStorageKey` "slopmower.tree-width". The plan README rule on browser storage names it.
  - At 768 px and below the pane stacks above the file and is not sticky. GitHub hides its pane below about 1012 px.
  - The Code tab index loads V6 of the root twice: once for the tree, once for the table. A tree directory that holds the open directory is also listed twice. Both are small reads.
  - The "Expand file tree" button shows before the breadcrumbs, in the path row and in the stuck row.
  - `CodeRouteError` and `NoFileSelected` are gone. The code routes use `RouteError embedded`.
  - The open web debug toolbar of `dev` covers the bottom 36 px of the tree pane. The F21 rule for it is gone, because the window scrolls.
  - Scope kinds: class, interface, trait, enum, function, and method. F27 adds struct and module, whichever of F25 and F27 lands second.
  - No decision row beyond D55.
- **Follow-ups and new ideas:**
  - README anchors such as `#port-overrides-and-saved-variables` go nowhere: react-markdown gives headings no `id`. GitHub prefixes them with `user-content-`.
  - The scope lines are plain text. GitHub highlights them.
  - The reveal of the current tree item does not subtract the sticky "Files" header of the pane, so an item at the top edge can sit under it.
