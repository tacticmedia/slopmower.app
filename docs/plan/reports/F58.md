A reply box keeps the `aria-label` of its text field. The UI spec and E2E locators changed from `textarea[aria-label="..."]` to `form[aria-label="..."] textarea`.
  - The focus on open stays in the Description, so the keyboard flows do not change. Enter in the Title field moves the focus to the Description: the implicit form submission would send "Add single comment". Mod+Enter still submits.
  - The title fields have `maxLength` 200, the raw limit of the `Title` schema, from one constant `TITLE_MAX_CHARACTERS` in `CommentBox.tsx`. The UI sends the trimmed title.
  - The title edit uses `useRequestCommand`: its dialog state is the edit state, which closes when Q23 succeeds and stays open with the error when it fails, and its ref guard sends one write at a time. `useSubmitOnce` submits the form data of a `fetcher.Form`, and `requestAction` reads JSON intents.
  - An unchanged title closes the editor without Q23. The fake refuses a retitle to the current title, as it refuses an unchanged plan requirement.
  - "Add a title" opens an empty field, not the summary.
  - The editor replaces the h1 while it is open, as on GitHub.
  - `DraftView` has `title`. The edit of a new-request draft sends `{title?, body, requireApproval}`, so a cleared field removes the title (D3), and a reply draft sends `{body}`.
  - The optimistic thread of Q2 takes its summary from the title or the first non-blank line of the body, in `pendingThread()`. No Vitest, because no new function.
  - The fake Q2, D2, and D3 trim the title. The fake D3 replaces the title together with the body.
