- **Deviations and decisions:**
  - `templates/base.html.twig` has no Reprise tags. `shell.html.twig` extends it and renders `reprise_entry_link_tags('app')` and `reprise_entry_script_tags('app')`. With the tags in the base, `/login` would boot the SPA, and `strict_mode` would throw on every page without a build. The base also got `lang="en"`, the viewport meta, and the default title "Holistic Review".
  - The recipe files `assets/styles/app.css` (a skyblue body) and `assets/app.js` are not committed.
  - `app.tsx` imports `@primer/primitives/dist/css/primitives.css`, which contains the motion CSS that the plan names plus the size, space, and typography tokens. Without them, `var(--base-size-16)` in our CSS modules resolved to nothing in the browser.
  - `ThemeProvider` comes from `@primer/react/next`, with `colorMode="auto"`. The root export is deprecated in 38.40.0.
  - CSRF proof: every POST, PUT, PATCH, and DELETE sends the double-submit of the M10 protocol, generated like Symfony's former `csrf_protection_controller.js`: 18 random bytes as base64url (24 characters), the header `csrf-token: <token>`, and the cookie `csrf-token_<token>=csrf-token; path=/; samesite=strict` (`__Host-` and `secure` on HTTPS). Reads send nothing. The browser adds `Sec-Fetch-Site` and `Origin` itself.
  - Sign-out, by the orchestrator's decision: a "Sign out" button in the header submits a `useFetcher` form to the client route `/sign-out`. Its action calls `signOut()` in `client.ts`, which POSTs `/logout` with the same proof as `apiWrite()` (header and cookie), plus the token in the `_csrf_token` form field that the logout listener reads, and `redirect: 'manual'`. The 302 of the logout listener is the success; any other response throws `ApiError` into the error page. The action then returns `redirectDocument('/login')`. A plain HTML logout form would fail after one SPA write, because the session then refuses a write without the double-submit.
  - `ApiError` keeps `status`, `code`, `message`, and `details`. A failed response without an Error body becomes `internal_error` with a message that names the HTTP status. `apiWrite()` resolves to `undefined` for a response without a JSON body (202, 204).
  - One `errorElement` on the root route. An unknown path is a 404 of the root route, so the error page replaces the layout; it links to `/`. A 401 from the loader shows "Signed out" with a link to `/login`.
  - The header links "Repositories" and "Settings" point at paths that get client routes in M18 and M19. Until then they show the error page. `ShellTest` navigates to an unknown path with `history.pushState` plus a `popstate` event, so it stays valid after M18.
  - `{id}` in the shell routes keeps the default requirement `[^/]+`; the client router decides what an unknown ID shows. One invokable action carries the eight routes; `#[IsGranted('IS_AUTHENTICATED')]` sends an anonymous user through `LoginRedirectEntryPoint`, which stores the target path.
  - Reprise in `test` and `e2e`: `strict_mode` throws without `entrypoints.json`, so `when@test` and `when@e2e` set `reprise.output_path` and `framework.assets.json_manifest_path` to `public/build-e2e`, the key that `config:dump-reference reprise` shows. `vite build --mode e2e` sets the plugin options `outputPath: public/build-e2e`, `publicPath: /build-e2e/`.
  - `vite.config.ts`: the entry is the Vite 8.2+ top-level `input`, as the Reprise documentation shows; `envDir: false`, because the `.env` files in the root belong to Symfony; the Vitest options live in the same file (`test.include: assets/**/*.test.ts`). Vitest does not start the Reprise dev-server hook and writes nothing to `public/`.
  - `@symfony/reprise` is in `dependencies`, as the plan lists it; the Reprise documentation installs it with `--save-dev`. npm also installed the peer `react-is` 19.3.0 of `@primer/react` into the lock file.
  - TypeScript: a solution `tsconfig.json` with `tsconfig.app.json` (`assets/`, `vite/client` types, `strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`, `erasableSyntaxOnly`) and `tsconfig.node.json` (`vite.config.ts`), both `noEmit`. JSON fixtures and schemas are imported from `docs/specs/` directly.
  - API types: an enum whose schema is `anyOf [enum, string]` (symbol kinds, actions, event types, thread entry types, error codes) is `Known | (string & {})`. `if`/`then` rules become unions on their discriminant (actor, anchor, location, repository source and access, review state, commit link, draft, token scope, inputs). `ErrorBody.details` is `ErrorDetails | null` for every code, because the code is an open set. `Location.confidence` is `number`. Lengths, patterns, and item counts are not modelled. Live-update fixtures are checked against their own union member, because a widened `type` matches every member.
  - `LocalSignInAuthenticator::onAuthenticationSuccess()` redirects to `getTargetPath($session, $firewallName) ?? '/'` and removes the target path, as the GitHub sign-in does through the default success handler. Tested as a unit test, because `POST /login/local` exists only in `dev`.

- **Risks discovered:**
  - A write that fails before the CSRF check (401, 404) leaves its `csrf-token_<token>` cookie in the browser until the next validated write, whose response clears all of them.
  - `npm run dev` writes `public/build/entrypoints.json` with the dev-server origin `http://[::1]:5173`. After the dev server stops, shell pages load scripts from a dead origin until `npm run build` runs. The dev worker keeps the parsed file in memory (`EntrypointsLookup::reset()` of `reprise.entrypoints_lookup` reloads only a missing file); the Caddyfile pattern `watch /app/public/build/entrypoints.json` restarts the worker after each rewrite. Its watched root is `public/build`; a pattern for a file directly in `/app` would walk all of `/app`, worktrees included (M01).
  - The shell bundle is 330 kB of JavaScript (105 kB gzip) and 191 kB of CSS, because the Primer CSS has side effects and ships whole.
