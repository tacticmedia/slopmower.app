## Report: M05 Tenancy persistence and isolation

- **Status:** Done (awaiting commit).
- **Summary:** `Tenant` and `User` are Doctrine entities with one migration. `TenantSqlFilter` is on by default and adds `tenant_id = :tenant` to every ORM query on a `TenantOwned` entity, and `id = :tenant` on `Tenant`. Without a tenant parameter it throws `MissingTenantContext`. `TenantContext` sets the parameter and implements `ResetInterface`: `reset()` disables and enables the filter, so a worker request never inherits a tenant. `TenantFilter::suspend()` is the only tenantless path: it uses `FilterCollection::suspend()` and `restore()` in `finally`, and a nested call runs its callable directly. Tests get the `ResetDatabase` trait and the `TenantFixtures` builder.

- **Deviations and decisions:**
  - The user table is `app_user`, because `user` is a reserved word in PostgreSQL. Raw SQL then needs no quoting.
  - `tenantId` is a plain `ulid` column, not a `Tenant` association, as architecture section 3 lists it and as M06 maps IDs. So `app_user.tenant_id` has no foreign key. It has the index `idx_app_user_tenant`.
  - `TenantSqlFilter` also scopes `Tenant` by its `id`. So a query on the `tenant` table fails closed too, and `find()` of another tenant returns null. Sign-in and purge read tenants inside `TenantFilter::suspend()`.
  - Without the parameter, the filter throws `MissingTenantContext` (a `LogicException`), not Doctrine's generic "Parameter does not exist". `TenantContext::get()` throws the same exception.
  - The filter parameter is the RFC 4122 form of the tenant ULID. The `ulid` column type is a native `uuid` on PostgreSQL, and `SQLFilter::getParameter()` quotes the string value and ignores the parameter type.
  - `TenantContext::set()` inside `TenantFilter::suspend()` sets the parameter on the suspended filter instance, so the new tenant applies after the callable. `enable()` would replace the suspended instance, and `restore()` would then throw. M10 sets the context after a tenantless user lookup.
  - `TenantContext` and `TenantFilter` carry `#[Autoconfigure(public: true)]`. No service in `src/` consumes them yet, so the compiler removes them, and the test container cannot return a removed service.
  - `githubUserId` and `eventSeq` are `BIGINT`. DBAL 4 returns `int`.
  - The partial unique index on `login` has the predicate in the form that PostgreSQL returns, `((sign_in_method)::text = 'local'::text)`. With `sign_in_method = 'local'`, `doctrine:schema:validate` reported a difference.
  - `SignInMethod` is a domain enum in `src/Domain/User`. `EnumContractTest` compares it with `me.schema.json`.
  - `User` has the named constructors `local()` and `gitHub()`, so only a GitHub user has a `githubUserId`. It has no method that updates `lastSignInAt` or the profile. That is sign-in, M10 and M32.
  - `TenantFixtures` takes the `ObjectManager` of the public `doctrine` registry and the time from `Clock::get()`, the global clock that `ClockSensitiveTrait` sets and that the `clock` service delegates to. phpstan-symfony reports a private service fetched outside a `KernelTestCase`. `create()` flushes and clears the entity manager, so later reads go through the filter and not the identity map.
  - `ResetDatabase` is a `#[Before]` hook. PHPUnit runs `#[Before]` methods before `setUp()`, so fixtures that `setUp()` creates survive. It shuts the kernel down at the end, because `WebTestCase::createClient()` refuses a booted kernel.
  - `EntityTenancyConventionTest` requires a field named `tenantId` of type `ulid` on the column `tenant_id`, which matches the plain-column decision above.

- **Risks discovered:**
  - The filter does not cover identity-map hits. `TenantContext::set()` to another tenant does not clear the entity manager. A message that the `sync://` transport handles for tenant B inside a request of tenant A (M09, `e2e`) can get an entity of A from `find()`.
  - `TenantContext::reset()` initializes the lazy entity manager after every worker request, also when the request did not use the database. It opens no connection.
