# Report: M05 Tenancy persistence and isolation

- **Status:** Done, on `main`, 2026-09-29.
- **Summary:** `Tenant` and `User` entities with their migration. `TenantSqlFilter` scopes every ORM read to the tenant and throws without a tenant context. `TenantContext` resets through the services resetter and drops the filter parameter. `TenantFilter::suspend()` is the one tenantless path. `ResetDatabase` and `TenantFixtures` support the functional tests. The implementation ran in a worktree against its own databases. A two-lens review found three isolation holes and three test gaps, and all are fixed. Each acceptance test failed once on a deliberate break, 14 breaks in all.
- **Files:** `src/Entity/{Tenant,User}.php`, `src/Repository/{Tenant,User}Repository.php`, `src/Domain/User/SignInMethod.php`, `src/Tenancy/{TenantOwned,TenantSqlFilter,TenantContext,TenantFilter,TenantWriteGuard,TenantOwnership,MissingTenantContext,TenantMismatch}.php`, `config/packages/doctrine.yaml`, `migrations/Version20260929080625.php`, `tests/Support/Database/ResetDatabase.php`, `tests/Support/Fixtures/TenantFixtures.php`, `tests/Functional/Tenancy/*Test.php`, `tests/Functional/Support/ResetDatabaseTest.php`, `tests/Unit/Conventions/NoStoredQueryTest.php`, `tests/Unit/Domain/EnumContractTest.php`, `docs/plan/README.md` (gotchas).
- **Tests added:** every acceptance sentence of the milestone, plus: the tenant table is scoped and throws without a context; a GitHub user ID is unique; `ResetDatabase` empties every table but `doctrine_migration_versions`; the write guard refuses a write of another tenant or without a context; `set()` refuses a different tenant; a tenant set after the services resetter scopes queries; a DQL join of two tenant tables returns only the context tenant's rows.
- **Verification:** `make check` exit 0: php-cs-fixer 0 files, PHPStan 0 errors, lints OK, schema in sync, 1001 unit and functional tests, 1 E2E test. Dev and test databases up to date.
- **Deviations and decisions:**
  - IDs are Doctrine `ulid` columns, PostgreSQL `uuid`, with typed-ID getters, as M06 decides. `TenantContext::set()` converts the tenant ID through the `ulid` type, because ORM 3.7 `SQLFilter::getParameter()` quotes the string and ignores the parameter type.
  - The `user` table is named `app_user`, because `user` is reserved in PostgreSQL.
  - The partial unique index on the local login comes from the mapping, with the predicate written as PostgreSQL returns it (`((sign_in_method)::text = 'local'::text)`), so `doctrine:schema:validate` stays in sync.
  - `githubUserId` and `eventSeq` are `BIGINT`. Timestamps are `datetimetz_immutable`, which stores whole seconds.
  - The filter also scopes the `tenant` table by its `id`. Without it, any tenant row could be read without a context, which breaks the Done criterion.
  - `TenantWriteGuard` (an `onFlush` listener) makes a flush outside `suspend()` throw when it writes a row of another tenant or runs without a context. `getReference()` plus `remove()` plus `flush()` deleted another tenant's row before.
  - `TenantContext::set()` refuses a different tenant without `reset()`, and `reset()` clears the entity manager. `set()` and the end of `suspend()` detach loaded entities of other tenants, so the identity map cannot return them.
  - A Doctrine `Query` object keeps its first tenant constraint. The README gotcha "Doctrine Query objects" forbids keeping one, and `NoStoredQueryTest` fails on a property typed as a query.
  - `TenantContext` and `TenantFilter` are public services for now, because no `src` service uses them yet and the compiler would remove them from the test container.
- **Versions:** no packages added.
- **Follow-ups:**
  - M09 `TenantContextMiddleware` must call `reset()` before it sets another tenant, because `set()` refuses a different tenant.
  - M10 and M32 create the tenant and user inside `suspend()` or after `set()`. `set()` inside a `suspend()` callable throws, because a suspended filter is not enabled.
  - Remove `#[Autoconfigure(public: true)]` from `TenantContext` and `TenantFilter` when M10 injects them.
  - Extend `TenantWriteGuard` to collection updates when a later milestone maps a many-to-many association.
  - `docs/architecture.md` section 4 does not mention the write guard and the detach step yet.
- **Risks:** An uninitialized reference of another tenant that a `suspend()` callable created stays in the identity map. Its first property access throws `EntityNotFoundException`. That fails closed, but a caller that maps null to 404 gets a 500.
