- **Decisions and deviations:**
  - Tables: the page already did not scroll sideways at either width. Primer wraps each `DataTable` in a `ScrollableRegion` with `overflow: auto`. The defect in the F57 captures is the frame: Primer draws it on the outer cells, so the clipped table had no right edge and looked like an overflow. `ScrollingTable.module.css` moves the frame to the region (`.TableOverflowWrapper`, a stable class name of Primer 38.40.0) and removes the outer cell borders. The two acceptance tests passed before this change, and they guard against a page overflow. Only the two named tables use the class, as the scope says.
  - The token table's `Table.Container` is in `SettingsRoute.tsx`, so the class goes there, not into `TokenTable.tsx`.
  - Sidebar: `LocationInfo` has the prop `showPath`. The sidebar passes false. The Changes tab passes true, because there no `AnchorLink` shows the path, and the lines in the linked commit can differ from the anchor.
  - Summary: `GithubFlavoredMarkdownConverter` with `html_input: strip`, because the UI renders GitHub Flavored Markdown with remark-gfm. `strip` removes raw HTML, where `escape` would put the tags into the text. The normalizer builds the converter in its constructor: the Twig converter of `twig_extra` escapes raw HTML and has the docs link rewriter, and a service definition for one consumer adds configuration without a gain.
  - Summary edge case, not in the scope: a line without plain text (`---`, an HTML comment, an image) gives an empty string, and `summary` has `minLength: 1`. The rule skips such a line, and a body without any plain text gives its first non-blank line, trimmed. The schema descriptions and D80 say so.
  - Specs: the `summary` values with backticks in the fixtures and in the examples of `rest-api-requests.md` are plain text now, so the examples follow the amended rule. The `list_requests` description in `McpTools`, `mcp.md`, and `tools-list.json` says "as plain text". D80 records the decision. D75 keeps its text, and the check run headline stays the Markdown line.
  - The fake summary of `tests/ui/support/builders.ts` follows the new rule with `unified`, `remark-parse`, `remark-gfm`, and `mdast-util-to-string`. `remark-gfm` is a dependency; the other three come with `react-markdown` and `remark-gfm`. The fake also cuts with U+2026 now, as the contract says.
- **Added at the merge:** `unified`, `remark-parse`, and `mdast-util-to-string`, which the UI fake imports, are dev dependencies with the versions of the lock. They came in only through `react-markdown`.
- **Follow-ups and new ideas:**
  - The other `DataTable`s (Usage, Repository data, connected repositories, candidates) lose their right edge in the same way at 390 px. They could use `ScrollingTable.module.css`.
  - `RequestRow.tsx` has a private `plural()`, and `RequestDetail.tsx` writes the plural inline. One shared helper would serve both.
  - The check run headline (`CheckRunOutput::headline()`) cuts the Markdown line at a fixed length, which can split a Markdown construct, for example a code span, so GitHub shows a stray backtick.
