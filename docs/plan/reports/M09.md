## Report: M09 Local repository source

- **Status:** Done (awaiting commit).
- **Summary:** `LocalRepositoryDiscovery` lists the direct children of `APP_LOCAL_REPOSITORIES_DIR` that are repositories, and skips a child or `.git` that is a symlink. `ConnectLocalRepository` implements R3 for `source: local`. `FetchRepository` holds the sync state machine: the R5 trigger with the `fetchRequested` flag, the synchronous fetch with one 60 s deadline, and the clone and fetch job handlers, all single flight under `RepositoryLock`. `CommitAvailability` resolves a SHA or prefix, fetches once on a miss, and gives `invalid_input` for an ambiguous prefix. `TenantContextMiddleware` carries the tenant from the dispatcher to the handler in a `TenantStamp` and fails closed without one.

- **Deviations and decisions:**
  - `safe.directory` goes into the `--upload-pack` command, not before the subcommand of the fetching git as the architecture and M08 put it. Git removes `GIT_CONFIG_PARAMETERS` and `GIT_CONFIG_COUNT` from the environment of a local transport, so `-c` on the fetching git never reaches the `upload-pack` that reads the source (probe above). The spec rule "every git command gets `-c safe.directory=<realpath>`" holds for the git command that reads the source. `BareClone::fetch()` got `?string $uploadPack`, used for `fetch` and `ls-remote`. Git runs it through `sh`, so `LocalFetchCommand` single-quotes the paths. The URL is percent-encoded per segment, because git percent-decodes `file://`.
  - The safe.directory test uses a directory under `sys_get_temp_dir()`, because the bind mount does not keep a changed owner. It asserts the owner before it connects.
  - The job handlers are `#[AsMessageHandler]` methods of `FetchRepository`, not classes in `src/MessageHandler`. One class holds the sync state machine, and no class only delegates. The messages route with `#[AsMessage('async')]`.
  - The sync state changes only through conditional DQL updates in `RepositoryRepository`, because the `php` and `worker` processes change one row concurrently. The entity has no setters for these columns, and reads go through `findFresh()`. `recordSuccess()` and `recordFailure()` touch only rows in `cloning` or `fetching`, so an `unavailable` that M33 sets stays.
  - The fetch job fetches in `idle` or `fetching` (`startFetch()`), not only in `fetching`: a running fetch that ends after the job cleared the flag sets `idle`, and a check for `fetching` would drop the requested fetch.
  - Every lock wait polls `acquire(false)` every 0.1 s through `Symfony\Component\Clock\ClockInterface::sleep()`, which the PSR clock lacks. Jobs wait without a deadline. A blocking acquire cannot be tested in one process: the store's in-memory guard throws, and a second session blocks the test process.
  - A missed lock deadline leaves the row as it is, without `lastError`, because no fetch ran.
  - The jobs give git 600 s (`JOB_TIMEOUT_SECONDS`), because a first clone of a large repository takes longer than 60 s. The Doctrine transport redelivers after 3,600 s.
  - The clone also dispatches `RepositoryFetched`, with a null previous head: it is the first successful fetch of section 2.2.
  - `defaultBranch` and `defaultBranchHead` come from the clone `HEAD` after the fetch (new `GitReader::headBranch()`). `BareClone` moves `HEAD` only when the remote names a branch, so a detached source `HEAD` keeps the last default branch. An unborn branch gives null for both.
  - A failed dispatch of the fetch job clears only the flag, as the plan says. A failed dispatch of the clone job sets `failed` with `lastError` "The clone job could not be queued.". Both rethrow.
  - `LocalRepositoryDiscovery::find()` applies the listing rules to one name and has no 1,000-item limit, so a connect checks only that name. The plan says "in a fresh discovery listing". The result differs only after the 1,000th candidate. The name must be an exact entry of `scandir()`: on a case-insensitive mount, such as the virtiofs bind mount of a macOS host, `realpath()` also resolves `BILLING` for `billing`, which would connect one source twice.
  - Discovery reads the `HEAD` file instead of running git, which would be up to 1,000 processes per R2 call. The guarantee: a candidate and its `.git` are not symlinks, and the real path parent check covers the candidate. A bare candidate also needs `HEAD`, `objects`, and `refs` that are not symlinks. The entries inside `.git`, `objects`, and `refs` are not checked. Names that break the `LocalDirectory` rules, and a branch that breaks `RefName`, are skipped. Finder is not used: the listing is one `scandir` level with explicit link and real path checks.
  - `FetchRepository` records a failure for `GitFailed`, `SourceUnavailable`, and a Filesystem `IOExceptionInterface`, then removes a partial clone. The failure is recorded first, so a failing removal cannot leave the row in `cloning`. A default branch that `RefName` refuses gives a null head.
  - `ConnectLocalRepository` holds a `LockFactory` lock keyed by the tenant ID and the directory around the lookup, the insert, and the flush, so a second concurrent connect returns the existing row instead of failing on `uniq_repository_name`. It releases the lock before it queues the clone.
  - `LocalRepositoryCandidate` also carries `realPath`, for the fetch. It never goes into a response.
  - The tenantless list is the parameter `app.tenantless_messages`, empty. The `test` environment adds `TenantlessProbe`.
  - The middleware switches the context only for a received envelope: the worker, `sync://`, and retries. A tenantless message without a stamp runs with the context reset, and the previous context returns afterwards. Fail closed is `UnrecoverableMessageHandlingException`, so the worker sends the message to `failed` without retries.
  - `GitReader` gives `invalid_input` for a short SHA that matches two commits: the field is `commit` in `resolvePrefix()` and `ref` in `resolveCommit()`. The test uses two crafted commits with fixed dates whose SHAs share `0806e1e`.
  - `ConnectLocalRepository` and `CommitAvailability` carry `#[Autoconfigure(public: true)]`, because nothing consumes them before M11 and M12. M09 consumes none of `RequestCommands`, `ReviewCommands`, and `EventLogQuery`, so they stay public.
  - `connect()` returns `ConnectedRepository` with `created`, for the 201 or 200 of R3.
  - The migration adds the column with `DEFAULT false` and then drops the default, so existing rows get `false` and the schema matches the mapping.
  - The fetch passes no pending SHAs. M16 adds them.
  - `fetchNow()` and the triggers refuse an open transaction.
  - Test seams: `SleepHookClock`, installed with `Clock::set()` in tests that use `ClockSensitiveTrait`, acts while the code polls. The probe handler is a `when@test` service. A lock in its own database session stands for a fetch in another process.

- **Risks discovered:**
  - A failed dispatch of the fetch job leaves `fetching` with no job until the next fetch ends or R5 runs again. The Doctrine transport uses the same database, so such a failure usually means the database is down.
  - `lastError` holds git stderr with server paths: the clone path and the source real path. The tenant sees it through the API.
  - A message without a transport would run in the dispatch pass under the context of the caller, not of its stamp. Every `App\Message` class routes to `async`.
  - A clone holds the repository lock up to 600 s. A synchronous caller gets `fetch_failed` after 60 s meanwhile.
  - A source in the reftable format has `ref: refs/heads/.invalid` in `HEAD`, so its candidate shows `headBranch: null`.
