- **Deviations:**
  - The inventory assertions of `CrossTenantRouteInventoryTest` and `McpCrossTenantInventoryTest` moved into `CrossTenantCoverageTest`, so one test owns "every surface has a case" and no check runs twice. The case runners stay.
  - `CrossTenantCoverageTest` also classifies the routes outside `/api/v1` (`mcp`, `webhook`, `docs`, `shell`, `sign-in`), so a new route fails until somebody names its surface. The route table is that of the `test` environment: `/login/local` (`dev`) and `/_e2e/sign-in` (`e2e`) are not in it.
  - Topic and path builders get generated cases instead of a hand-written table: every public method is called for two tenants, every output must have the tenant ID as a path segment, and no output of one tenant may match or contain one of the other. A builder with a parameter that is not a typed ID fails the test until it gets a case. `LiveTopicsTest` keeps its narrower case.
  - `SchemaCoverageTest` counts only PHP tests, because they assert the server's output. The UI suite validates the bodies of its own fakes, and `ContractFixturesTest` validates the spec examples. A schema is each file root that is not only a `$defs` container, plus every `$defs` entry. A literal counts only when it is a whole schema reference that resolves.
  - The manual run used a repository inside the worktree and a curl agent, not `~/dev` and Claude Code: Jan's rules keep agents inside the repository and leave Claude Code configuration to him. The steps above cover the rest.
