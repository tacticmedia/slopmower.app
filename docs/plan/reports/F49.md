- **Decisions and deviations:**
  - The recipe's `AppStory` is deleted. It was empty, and a second fixture makes `foundry:load-fixtures` without a name ask which one to load.
  - The recipe's `FoundryExtension` in `phpunit.dist.xml` stays. Foundry boots through it on PHPUnit 10 and later, and only when a test uses Foundry.
  - `config/services.yaml` shares the `App\Factory\` and `App\Story\` entries of `when@dev` and `when@test` through YAML anchors. A `_defaults` block in `when@test` would change the wiring of the existing test services.
  - The story also refuses an empty `APP_LOCAL_SIGN_IN`. Without that check, `provision('')` creates a user with an empty login.
  - The repository step skips on `InvalidInput` and `NotFound`, with a warning on the `app` channel. `LimitExceeded` fails the load.
  - A second load changes the sign-in time of the user, because `LocalUserProvisioner::provision()` records a sign-in.
  - Only `DevStory` uses `ApiTokenFactory` now. `TenantFactory`, `UserFactory`, and `RepositoryFactory` serve the candidates "Demo fixture set for qa-bundle screenshots" and "Test helpers on Foundry factories".
  - The developer guide counts of `src/`, `assets/`, `tests/`, `BundledSchemas.php`, and `tests/Functional/` are the measured values.
- **Versions:** zenstruck/foundry v2.14.1 and fakerphp/faker v1.24.1, both `require-dev`.
- **Follow-ups and open questions:**
  - A factory call needs a tenant context, because Foundry's `isPersisted()` calls the ORM `find()`, and the tenant filter also covers `Tenant`. The developer guide says so.
  - If `APP_LOCAL_SIGN_IN` changes to another login, the old tenant still holds the dev token, and the insert fails on `uniq_api_token_hash`. Remove the old token in Settings, or set a new `APP_DEV_API_TOKEN` in `.env.dev.local`.
  - `tests/Functional/Usage/PlanConfigurationTest.php` calls `expectExceptionMessage()`, which PHPUnit 13.4 deprecates. F52 takes it.
