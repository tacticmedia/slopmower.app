## Report: F99 Source maps for browser reports

- **Status:** Done 2026-11-03.
- **Summary:**
  - With the build arguments `SENTRY_ORG` and `SENTRY_PROJECT` and the secret `SENTRY_AUTH_TOKEN`, the image build writes hidden source maps, `@sentry/vite-plugin` writes a debug ID into each chunk and its map, uploads them to the browser project, and deletes the maps (D100).
  - Without `SENTRY_PROJECT`, the build output is byte-identical to the output before F99.
  - A missing organization or token, or a failed upload, fails the build. The build creates and injects no release (D86 holds), and the telemetry of the plugin is off.
  - `bin/prod-check` fails when `public/` of the image holds a `.map` file.
- **Files:**
  - Build: `vite.config.ts`, `package.json`, `package-lock.json`, `Dockerfile`.
  - Checks: `bin/prod-check`, `Makefile` (help line of `prod-check`).
  - Docs: `docs/deployment/README.md`, `docs/deployment/dockerised.md`, `docs/architecture.md` (D100), `docs/plan/README.md` (verified versions).
- **Tests added:** `bin/prod-check`: "the image serves no source map".
- **Verification:**
  - Host builds: without Sentry variables, `diff -r` of `public/build`, `entrypoints.json`, and `manifest.json` against the build of the old configuration finds no difference, and no `.map` file exists. The same holds for `public/build-e2e` of `npm run build:e2e`. `SENTRY_PROJECT` with the token and without `SENTRY_ORG`, and with `SENTRY_ORG` and without the token: exit 1 with the message of `vite.config.ts`. All three with `SENTRY_URL=http://127.0.0.1:9`: exit 1 with `SentryError: fetch failed` at the upload, 0 `.map` files left.
  - Prepared upload (`SENTRY_TEST_OVERRIDE_TEMP_DIR`): 334 chunks and 334 maps. In the chunk of `assets/api/client.ts`, the `//# debugId=` of the chunk equals the `debugId` of its map, the map has `sourcesContent` for each source, and `source-map-js` resolves `async function Nl(` to `assets/api/client.ts:47` `apiGetAllPages` and the `fetch` in `Il` to `assets/api/client.ts:92`, the two frames of the report of 2026-11-03. The served chunk holds the same debug ID. No chunk holds `SENTRY_RELEASE={id`.
  - 334 of 336 served chunks have a debug ID. The two others are `worker-*.js` and `wasm-*.js` of the `@pierre/diffs` worker.
  - `docker build --target assets --build-arg SENTRY_PROJECT=...` without the secret: exit 1 with the message of `vite.config.ts`, so a missing secret leaves the variable unset. With `--secret id=SENTRY_AUTH_TOKEN`, the token reached the build.
  - `make front`: `tsc -b` clean, Vitest 108 passed.
  - `make prod-check`: pass, `GET /login` gives 200. Mutation: with `sourcemap: 'hidden'` always on, it fails with "the image serves source maps: public/build/ClaimedBy-BwJGPTWC.js.map".
  - `npm audit`: exit 1, as on `main` (F100). F99 adds `glob` and `minimatch`, both moderate, from `@sentry/bundler-plugins`. `npm audit --prefix symbols`: exit 0.
  - Not run: `make cs`, `stan`, `lint`, `test`, and `e2e`, which need a Docker stack, `make ui`, which builds with `tests/ui/vite.config.ts`, and `make act`. F99 changes no PHP, test, or asset file, and without the Sentry variables the build output is byte-identical, so these gates see the inputs of efeadc3b, where the `make check` of the peer session passed every suite and `make prod-check`. A worktree stack needs about 2 GB, and the disk had 15 GB free. `make act` stops at the two audit steps (F100).
- **Deviations:**
  - The Candidate named only the token. The upload also needs `SENTRY_ORG`: the CLI `sentry` 0.45.0 does not take the organization from an organization auth token, and without it the plugin only warns.
- **Versions:** `@sentry/vite-plugin` 11.10.0 of 2026-10-28, the latest. `@sentry/react` 11.10.0 exists; the project pins 11.9.0.
- **Follow-ups and open questions:**
  - F100: the npm and Composer audit gates are red on `main`.
  - Candidate: network errors in browser reports.
  - `merge.sh` matches scope files with `docs/plan/F[0-9][0-9]-*.md`, which misses `F100-*.md` and later IDs.
- **Risks discovered:**
  - The upload runs only where the release image is built. Jan builds it outside this repository; that build needs the two arguments and the secret.
