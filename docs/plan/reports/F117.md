## Report: F117 Browser only code access

- **Status:** Done (awaiting merge).
- **Summary:** A GitHub repository has the third code access `browser` (Browser only), picked at connect or on the repository page. The server reads no file content: `GitHubCodeReader` in Browser only answers each content read with `repository_unavailable` `code_in_browser`, Q9 and `pathAfter` come from a walk of the differing trees (`GitHub\TreeDiff`), the index holds paths only, and re-anchoring compares blob SHAs, with the new status `unverified` for a changed file and `orphaned` for a deleted one. The new endpoint R11 gives the browser the kept installation token of the server for the repository, after the suspension and D88 checks. The SPA reads blobs, diff sides, and the README from `api.github.com`, builds the outline in a worker with `symbols/src/extract.ts`, and hides go to declaration, symbol anchors, the symbols menu, and Raw. Scratch copies older than 1 hour are deleted before a new one.

- **Decisions and deviations:**
  - Twig has no outline in Browser only, and `tree-sitter-twig` is not added. The published `tree-sitter-twig` 0.8.2, the latest on npm, ships a wasm with the old `dylink` section, which `web-tree-sitter` 0.27 refuses ("failIf" in `getDylinkMetadata`, checked in Node). `docs/user/code-access.md` says so.
  - The grammars stay in `symbols/package.json`, because their install scripts compile Node bindings (`tree-sitter-twig` runs `node-gyp rebuild`), which only `--ignore-scripts` avoids. The SPA bundles them from `symbols/node_modules` through `import.meta.glob`, so the `Makefile` targets that build the SPA and the `assets` stage of the `Dockerfile` install them. The build output gains 15 wasm files of 20,074,235 bytes, the runtime and the 14 grammars of `BROWSER_LANGUAGES`, loaded per language on demand. `tree-sitter-php` 0.24.2 is the latest version on npm.
  - The PHP outline of the browser gives FQNs without the namespace and joins every member with `::`, for example `Invoice::$total` is `Invoice::total`. The scope allows names that differ.
  - The front end tells Browser only from the contract, not from a new field: V7 `rawUrl` null, a Q9 file with `binary` null, and V8 `code_in_browser` for the README. It reads the repository ID of a review once per page from V3 (`reviewRepositoryId()`), because a file loader has no repository ID.
  - R11 is an action of `RepositoryController`. `ServerClone::browserToken()` runs the suspension check, then the D88 check with the token of `contents: read`, `metadata: read` that `InstallationTokenProvider::withExpiry()` keeps for the reads of the server, and answers that token with its expiry. A failed check answers `clone_failed`, which the error table of the specs already names for a failed access check, and a GitHub failure `fetch_failed`. Order: `code_on_server`, the sync state, the `code_token` limiter, then the checks. The limiter is `APP_RATE_LIMIT_CODE_TOKEN_PER_HOUR`, default 600.
  - R10 deletes the rows, not the clone job, because only R10 knows the old mode. Leaving Browser only also deletes the location cache, because its `unverified` entries would otherwise stay after the recompute of the new mode.
  - `unverified` has `confidence` 0, and is only for another blob at the path of the anchor; a path that is gone, without the same blob at another path, is `orphaned` with `file_deleted`. A `file` anchor on a changed file is `unverified` too; it is outdated in every mode.
  - V9 and V14 refuse in the controller for every file, not only through the reader, so the contract is one rule. V7 of Browser only has the ETag `W/"v2-browser-<blobSha>"`, so a cached body of the other modes does not come back after a switch. V17 refuses only a symlink and a file above 1 MiB, because the server cannot tell a binary file.
  - Q2 in Browser only requires a regular file of at most 1 MiB for `line` and `range`, and checks neither UTF-8 nor the file length.
  - "ETag reuse" is the HTTP cache of the browser: GitHub sends an `ETag` and `Vary: Authorization`, and `fetch` revalidates with it. `githubCode.ts` has no cache of its own.
  - README images come from `contents/{path}?ref={commitSha}`, because the README names a path and no blob SHA; R11 in the specs names this endpoint. They render as `blob:` URLs through `GitHubImage`, and `readmeUrl()` resolves their `src` to the repository path in Browser only.
  - The file view of Browser only does not read a file above 1 MiB, so its placeholder says it is above the limit, also for a binary file. The download button is hidden, because there is no V8 URL.
  - The flow test keeps one kernel (`disableReboot()`), because the transport log of the fake lives in one container: with a reboot the assertion saw only the last request, and a mutation that called `compare` passed. `commits/{ref}` with the SHA media type stays for refs, because it returns a SHA only; the test refuses `git/blobs/`, `compare/`, `contents/`, and `commits/{40 hex}`.
  - The scratch leftovers are deleted in `ScratchCopies::emptyRepository()`, so the copies and the empty diff repositories are covered. The age is the modification time of the directory against the clock; a directory that another process removes meanwhile is skipped.

## Review fixes

1. Browser only `Locator`: a mapped entry of null is `orphaned` with `file_deleted`; `unverified` stays for an existing path whose blob differs. The specs README, `common.schema.json`, architecture 5.3, 5.4, and D114, and `code-access.md` say so. Test: "A carry-over of a request whose file is deleted gives not_carried with file_deleted"; with the old branch it answered 422.
2. An anchor that Browser only stored without a snapshot gets one from its blob in the other modes: `Locator::snapshotText()` captures it when the snapshot is null and the range is set, and returns null for a range past the end of the file. `compute()` checks the rebuilt snapshot, so such an anchor locates by its lines, and Q3 shows its lines. Test: "A range request of Browser only locates with its range after a switch to Server copy"; with the old code the location was `changed` without a range.
3. R11 runs the D88 check with the kept token of the server and answers that token (`InstallationTokenProvider::withExpiry()`, which replaces `mint()` as a public method), so tabs and reloads share one GitHub token. The limit is 600 per hour per user. `githubCode.ts` asks again 4 minutes before `expiresAt` and at most once a minute, and at once after a 401. R11 in `rest-api.md`, the specs README, D114, `code-access.md`, and `privacy.md` say so.
4. `IndexReviewHandler` reads the code access again with `findFresh()` before each write of parsed blobs, and stops without the write when R10 changed it during the job. `Locator::locate()` does the same before it writes the location cache.
5. Test: "The reader of Browser only refuses every read of file content without a call to GitHub" calls `readBlob`, `openBlob`, `unifiedZeroDiff`, `filesContaining`, and `withLocalCopy`.
6. `ScratchCopies::markInUse()` sets the modification time of a copy to the time of the clock; `GitHubCodeReader::withLocalCopy()` calls it before each callback, and `writeBlob()` before each write.
7. `githubCode.ts`: a 403 with `retry-after` is `rate_limited`, with the seconds of `retry-after`.
8. `gitHubImage()` builds the image Blob with the type of the file extension: svg, png, jpg, jpeg, gif, and webp. `GitHubImage` makes no `blob:` URL after the abort of its read.
9. `symbolsData.ts`: `onerror` of the outline worker answers every pending outline with null, clears the map, and drops the worker, so the next outline starts a new one.
10. `githubCode.ts` keeps up to 64 blobs and 16 MB in memory by SHA, the least recently read first out.
11. `TreeDiff` collects the added and deleted subtrees of a level and lists them in one `prefetchTrees(..., true)`.
12. Tests: "R11 refuses while the installation is suspended"; "R11 answers 429 past the code_token limit of the user"; "Leaving Browser only parses the symbols of the open reviews again"; the entering test asserts the `location_cache_entry` rows (1 before R10, 0 after); the R11 test asserts the token request body `repository_ids: [812345]`, `permissions: {contents: read, metadata: read}` through `GitHubResponses::installationTokenRequests()`; UI "A 401 of GitHub asks R11 for the token again and reads the blob with it".
13. `code-access.md`, `privacy.md`, `getting-started.md`, and the connect choice say that Slopmower never reads the files of the repository, and that the text people and agents write is stored as in the other modes.
14. `outlineWorker.ts` lists the 14 grammars of `BROWSER_LANGUAGES` as literals; Vitest "The outline worker of the SPA bundles the grammar of every browser language" checks the list. The wasm assets of `npm run build:e2e`: 16 files, 21,076,642 bytes before; 15 files, 20,074,235 bytes after, without `tree-sitter-php_only.wasm`.
