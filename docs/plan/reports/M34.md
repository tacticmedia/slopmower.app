## Report: M34 GitHub webhooks

- **Status:** Done, committed as a3a1b63 on 2026-10-03.
- **Summary:** `symfony/webhook` 8.1.7 and `symfony/remote-event` 8.1.0 serve `POST /webhook/github`. `GitHubRequestParser` matches a JSON POST with `X-GitHub-Event` and `X-GitHub-Delivery`, checks `X-Hub-Signature-256` with `hash_equals()` on the raw body (an empty secret refuses every delivery), and returns a `RemoteEvent` for every verified delivery; the response is 202. `ConsumeRemoteEventMessage` goes to `async` and is tenantless. `GitHubWebhookConsumer` skips a delivery that `webhook_delivery` holds, reads the tenants of the delivery inside `TenantFilter::suspend()`, queues one job per tenant with a `TenantStamp`, then records the delivery and purges rows older than 7 days. The jobs request fetches on `push`, record, suspend, and delete installations, add and remove candidates, remove access by D22 through `FetchRepository::removeAccess()`, rename repositories, and publish `candidates_changed`.

- **Deviations and decisions:**
  - The secret is `%env(string:default::GITHUB_APP_WEBHOOK_SECRET)%`. docs/specs writes `%env(GITHUB_APP_WEBHOOK_SECRET)%`; the README rule `default::` keeps a `.env` value from winning over the vault, and `string:` turns an unset secret into `''`, because `WebhookController` passes it to a `string` parameter, where `null` is a `TypeError`. The parser refuses `''` with 403.
  - Composer constraints are `8.1.*`, as for every other `symfony/*` package; the lock holds 8.1.7 and 8.1.0.
  - `make:webhook github` scaffolded the parser, the consumer, and `config/packages/webhook.yaml`. They were renamed to the plan's `GitHub*` names, and the consumer moved from `src/RemoteEvent` to `src/Webhook` (plan over skill). No recipe writes `webhook.yaml`, so it has a header comment.
  - Request matcher: `MethodRequestMatcher('POST')`, `HeaderRequestMatcher`, and an anonymous matcher for the media type `application/json` (parameters ignored). `IsJsonRequestMatcher` validates the body, so unparsable JSON with a wrong signature would get 406 before the 403 of the signature check.
  - The parser decodes with `Request::toArray()`. A body that is not a JSON object throws a `RequestExceptionInterface`, which `AbstractRequestParser` answers with 406.
  - `ping` gets the name `github.ping` and is a no-op in the consumer. Every verified delivery, also `github.ignored`, gets a `webhook_delivery` row.
  - A firewall `webhook` (`^/webhook/`, `security: false`): the signature authenticates GitHub, and without a session no tenant context stamps `ConsumeRemoteEventMessage` at dispatch.
  - `webhook_delivery`: `id VARCHAR(255)` primary key, `received_at`, and an index on `received_at` for the purge. `WebhookDeliverySql` holds the check, the `INSERT ... ON CONFLICT (id) DO NOTHING`, and the purge, because raw SQL lives only in `*Sql` classes. The entity has no repository class, against the `make-entity` skill, because no ORM query reads it. It is not tenant owned, so `RepositoryScopeSqlFilter` ignores it.
  - The consumer reads with `findBy()` inside `TenantFilter::suspend()` and clears the entity manager afterwards, because the SQL filter does not cover identity-map hits (`sync://` in `e2e` runs the jobs inside the consumer run). It dispatches each job with an explicit `TenantStamp`, after the suspension ends.
  - Seven job messages in `src/Message` (`#[AsMessage('async')]`) and three handler classes in `src/Webhook/Handler`. `InstallationHandler` takes all installation and candidate changes, so the tenant lock and the `candidates_changed` publish live in one class; `RepositoryHandler` repeats the four-line lock, as `InstallationSync` and `ConnectGitHubRepository` do.
  - A verified delivery with an unexpected shape throws `UnrecoverableMessageHandlingException`, so the worker sends it to the failure transport without retries, and no delivery row is written.
  - `installation.deleted` routes to tenants with an installation row, a candidate of the installation (`installation_repositories.added` creates candidates without a row), or a repository that has the installation ID, because a repository keeps the ID without a row (orchestrator review).
  - `installation_repositories.removed` and `repository.deleted` also route to tenants that only list a removed repository as a candidate, and remove that candidate. docs/specs says "for each connected repository"; a stale candidate would fail at its clone.
  - `installation.created` ignores an enterprise `target_type` (M33 rule) and a sender without a user. It records no candidates: docs/specs names only the installation and the publish, and the install flow lists them again at sign-in (orchestrator decision).
  - `installation_repositories.added`: the job reads each repository with `GET /repos/{full_name}` and a token from `InstallationTokenProvider::forRepository()`, checks that GitHub answered the same ID, and takes the name, `private`, `default_branch`, and `html_url` from the answer. All reads happen before the write, so a failed read adds nothing and the retry adds all. An existing candidate stays. A new candidate gets the tenant's newest `listedAt`, read under the lock, so R2 `githubListedAt` stays the time of the last sign-in; without candidates it gets the current time (orchestrator review). A missing installation row is not created.
  - `suspend` stores the worker's clock time, not GitHub's `suspended_at`: only null or not null is read, and no response shows the value. `unsuspend` clears it.
  - `repository.renamed` and `transferred` set the name under the tenant lock; a case-insensitive collision with another repository of the tenant waits, as at sign-in. `private` is updated in the same step. Other actions update `private` only and publish nothing, as docs/specs lists no update for them. A removed repository is renamed too. Candidate rows are not renamed.
  - `candidates_changed` is published after every created, deleted, added, or removed job, also when no row changed; a redelivery is filtered before.
  - The access removal first deletes the candidates and installation rows in one transaction under `ConnectGitHubRepository::lockKey()`, then runs `removeAccess()` outside the transaction on a fresh `findBy()`, so a connect that commits in between cannot leave an active repository (orchestrator review).
  - Push: the job checks `access = active`, then calls `FetchRepository::request()`, which restarts a failed clone as R5 does. `NotFound` and `RepositoryUnavailable` since the lookup are ignored.
  - No symbol index exists before M26, so the clone is the code data that the access removal deletes now.
  - `github_app_authorization.revoked` is logged at `info` with the sender ID.
  - Test seams: `GitHubResponses` answers `GET /repos/octocat/Hello-World` only for the installation token. `GitHubWebhooks` resets the tenant context before each delivery, as at the start of a worker request, because the first request of a `KernelBrowser` does not reset services. The webhook fixtures are request bodies in the documented shapes on docs.github.com, with values chosen for the tests, not recordings.
  - The GitHub API base URL is the public constant `InstallationTokenProvider::API`, next to `API_HEADERS`, used by the token request, the sign-in listing, and the repository read (orchestrator review).
  - Tests beyond the acceptance list, one per rule: the content type and method of the matcher, the rename onto a taken name, and the candidates of `installation_repositories.added`.
  - Skills: `make-webhook` scaffolded the classes; the matcher and the signature check replace the generated ones. `make-entity` scaffolded `WebhookDelivery`, then the string ID, the constructor, no setters, no repository. `make-migration` generated the migration, reviewed, with a description. `configuration`: the secret is an environment variable or a vault secret, the retention a class constant. `services`, `components` (Webhook, RemoteEvent, Messenger, Lock, HttpClient, Serializer, Clock), `discover` (vendor sources of `AbstractRequestParser`, `WebhookController`, `ConsumeRemoteEventHandler`, `EnvVarProcessor`, `IsJsonRequestMatcher`, `KernelBrowser`), `make-test`, and `cli-conventions` were followed. context7: Symfony 8.0 webhook documentation.

- **Risks discovered:**
  - The worker crash of M11, M16, and M24 happened again during the manual check: the dev worker died on a container file that a rebuild removed, and kept its message delivered. Setting `delivered_at` to null released it.
  - Each added repository costs two GitHub requests: a token and the read.
  - A delivery ID longer than 255 characters fails the insert. GitHub sends GUIDs.
